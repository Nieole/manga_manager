# 藏书事实与读者阅读视图区分建模

实施状态：阅读查询通过明确 `reading.Subject` 返回 `BookView`、`BookSeriesView` 及主体绑定的列表结果，HTTP、OPDS、Mihon 与编排消费者已迁移。旧公共可变投影和未绑定主体的阅读视图入口已退出；持久化行与匿名兼容能力继续保留，读态解释和继续阅读规则由 reading 维护。

书的藏书事实与某位读者的阅读视图具有不同含义，后者的读取入口必须明确主体，不能依赖调用者记住先覆盖同一个数据库记录的阅读字段。采用职责明确的查询结果模型，逐步隔离有业务含义的持久化类型；简单查询不强制构造领域实体，对外 JSON 与匿名兼容读态继续保持兼容，主体筛选仍须先于 SQL 分页。

继续共用 database.Book 并加强调用约定可减少转换，但无法使调用者区分原始藏书记录和已绑定主体的视图；全面映射所有数据库结果又会增加无规则收益的转换。选择按实际语义分离，接受必要转换，以减少漏投影和跨主体误用的风险。
