# 重启函数在装配期注册，不由任务启动时携带

任务快照会落库，因此重试的目标可能是**上一个进程**留下的历史任务——`retryTask` 是先从库里读出任务快照，再按其类型查找重启函数。所以重启函数的注册表必须在装配期一次性填满，不能改成「启动一个任务时顺便登记它自己的重启方式」：那样一来，本进程从未启动过的任务类型就查不到重启函数，重试会从「409 同类任务已在运行」静默退化成「400 不支持的重试类型」，而且只在服务重启后才复现。

## 为什么记下来

把重启函数搬到 launcher 旁边、让任务声明自带它，是一个看起来明显正确的重构——它能消掉一张十余条的注册表，也能让「加一个任务类型要改三个地方」变成改一个地方。2026-08 的架构评审就走到了这一步才被上述事实拦下。没有这条记录，下一次评审会再提一次。

## 附带结论

该注册表同时是「哪些任务类型可重试」的唯一事实来源（任务快照里的 `Retryable` 由它推导）。它此前取代了两份需要手工同步的硬编码清单，不要再把这个判定复制出第二份。
