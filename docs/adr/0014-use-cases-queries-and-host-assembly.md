# 按完整功能组织用例与查询，宿主独立装配

实施状态：生产装配由 `bootstrap.Open` 持有唯一 `runtime.New` 调用，创建内容、缓存与应用资源，绑定 HTTP leaf effects 后才执行恢复并开放输入。`Host` 只保存已绑定的 HTTP 适配器，在同一鉴权 chi 子树组合阅读、编排、资料库/运行与管理家庭；不构造应用、不持有 Runtime 或全量 Store。旧 `Controller`、core/runtime HTTP 装配、家庭重建与兼容转发已删除。工单 47 的未提交实现与门禁证据待独立评审，不代表已集成或关闭。

阅读、目录、评价及 OPDS/Mihon 由 `ReaderHTTP` 消费阅读命令、查询与只读目录投影；元数据、提案裁决、合集、智能书架、关系、阅读清单与 AI 分组审核由编排家庭持有。阅读协议经窄回调共享同一编排查询、认证和内容访问适配器，不按需回退重建家庭。

资料库/扫描、维护、磁盘、迁移及运行家庭消费各自能力与窄查询。封面写入归封面适配器，标签、自定义字段、批量收藏及打开目录归目录维护适配器；页清单、页图、整书传输、封面/缩略图与页缓存诊断归内容适配器；供应商查询与刮削提案入队归供应商适配器。运行历史、控制和推送共享一个运行投影，内容传输仍持有同一 Engine 的访问租约直至句柄关闭。

管理家庭持有配置发布、账户用例、窄会话/诊断查询及 KOReader，包括设备协议入口。Cookie/CSRF、可信代理、失败限流和 Basic 凭据缓存共享一个认证状态。Transport 的技术 leaves 独立构造，只保留认证、事件 broker、运行投影、外部供应商客户端工厂和缓存/内容效果绑定，不镜像应用服务。统计、推荐、图像和内容缓存各只有同一份实例；SSE 在普通请求排空前结束，运行取消和资源退休在排空后发生。

API 白盒回归通过 `_test.go` 的显式能力绑定持有多个窄适配器，以及 SQLite、时钟、调度与应用资源供断言；不再调用任何生产兼容构造或转发桥。故障注入指向实际消费的查询、用例、来源解析或调度端口，不依赖替换旧宿主字段。生产恢复、共享能力与实况关闭另经 `bootstrap.Open` 和真实 HTTP 消费者验证。

写入通过表达完整意图的用例维护业务不变量，并依赖范围明确的事务能力；查询按搜索、列表、详情与统计等场景返回所需视图，保留批量 SQL、分页与缓存，不要求查询装载完整领域实体。两者继续使用现有 SQLite，无需独立读库或消息设施。

装配根负责创建应用、技术资源和 HTTP 宿主，功能处理器只接收所需用例及查询能力。Controller 不再作为应用构造、恢复与启动入口，也不将运行时服务引用完整复制到传输层；注册、恢复、后台开放、请求开放及停机排空次序保持有效。

前端按离线、配置编辑会话、资料库管理、任务等完整功能拥有状态与接口，页面和导航壳保留局部视图状态。组件消费功能投影类型，读取结果与编辑草稿分别表达含义；查询不隐含宣告已发生写入，AI 审核裁决由后端返回权威结果。

全面实体化读写会增加无规则收益的装载与转换，继续由宿主和页面拼配方又会分散一致性知识。接受针对场景的接口与必要转换，以集中业务知识并收窄依赖，而不统一模板化所有包或建立全站万能对象。
