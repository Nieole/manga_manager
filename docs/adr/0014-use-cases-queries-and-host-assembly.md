# 按完整功能组织用例与查询，宿主独立装配

实施状态：分批实施。生产入口由 `bootstrap.Open` 构造唯一应用及 HTTP `Host`，先登记、恢复再开放。`Host` 暂以已绑定能力驱动兼容 `Controller`；阅读、编排、资料库和管理 HTTP 家庭迁移后，收缩票删除旧构造与全量依赖面。兼容面不得另建 Engine、Manager、鉴权、SSE 或查询缓存，也不得再次启动应用。完整用例、查询及前端功能归属仍按架构整理工单逐项验收。

管理家庭由 `Host` 注入配置发布、窄账户/会话与诊断存储、KOReader 能力；生产管理路由直接调用家庭适配，不经过 Controller 转发。账户写入消费初始化、管理与改密用例，KOReader 分区校验与版本保存由 configuration 持有。Cookie/CSRF、代理信任、限流与 Basic 凭据缓存仍归 HTTP，同进程各家庭共享唯一认证状态。尚存的 Controller 转发只服务迁移中的家庭和嵌入测试，收缩票负责退出。

写入通过表达完整意图的用例维护业务不变量，并依赖范围明确的事务能力；查询按搜索、列表、详情与统计等场景返回所需视图，保留批量 SQL、分页与缓存，不要求查询装载完整领域实体。两者继续使用现有 SQLite，无需独立读库或消息设施。

装配根负责创建应用、技术资源和 HTTP 宿主，功能处理器只接收所需用例及查询能力。Controller 不再作为应用构造、恢复与启动入口，也不将运行时服务引用完整复制到传输层；注册、恢复、后台开放、请求开放及停机排空次序保持有效。

前端按离线、配置编辑会话、资料库管理、任务等完整功能拥有状态与接口，页面和导航壳保留局部视图状态。组件消费功能投影类型，读取结果与编辑草稿分别表达含义；查询不隐含宣告已发生写入，AI 审核裁决由后端返回权威结果。

全面实体化读写会增加无规则收益的装载与转换，继续由宿主和页面拼配方又会分散一致性知识。接受针对场景的接口与必要转换，以集中业务知识并收窄依赖，而不统一模板化所有包或建立全站万能对象。
