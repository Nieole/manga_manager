# 声明分家：重启入参与声明标签，合并据此判有损

状态：已实施。`task.RunSpec.Args` 只承载行为输入，环境归 `Labels` 或已有的 `Limits`，IO 累计量归指标。装配期注册的重启能力保持有效。

一次运行的声明今天装在 `RunSpec.Metadata` 一个格子里，而它的 doc 自称「重启入参」。
这句话不为真：资料库扫描往里放六个键，只有**强制**会被**重启函数**读回去，另外五个
（存储档位、卷键、归档打开并发、封面并发、扫描等级）没有任何重启函数读它们；封面运行更极端，
三个键全是描述性的，而真正改变它跑法的「自己去找活」压根不在声明里，只是个 Go 形参。

分不开的直接后果是**合并判不出自己丢了什么**。引擎在合并时只加一次计数，事件也只在
第一次被合并时落一条——那条规则有它自己的充分理由（守护与监听扫描会在一次长扫里反复撞上同一条
排队运行，每次落一条能在一条还没起跑的运行上堆出几千行）。但它恰好吞掉了唯一有损的那种：
守护 tick 先并进来落了事件，用户随后点的强制重扫并进来时一条都不落——**丢掉东西的那一次，
正是没留下痕迹的那一次**。

**决定：声明分成两格。** **重启入参**是会改变这次运行怎么跑的那几项，判据是「把它从声明里去掉，
重启出来的那次会不会跑成另一个样子」；**声明标签**是描述它在什么条件下跑的那几项，重启函数一项不读。
「自己去找活」这类由发起点决定取值的行为参数进声明，归入参——**发起方**只答「谁叫来的」，
不夹带「怎么跑」（见 `CONTEXT.md` 该词条）。

**合并据此判有损：** 两次发起的**重启入参**不同即为有损，有损**每次都落事件**，不论第几次；
无损维持「只落第一次」。噪音防护因此原封不动——守护与监听那一路什么都不丢。

## 考虑过并否掉的

**不动声明，把规则缩成「只认 `force` 这一个键」。** 那是一张按键的例外表：新任务类型带了新参数时，
没有任何东西提醒作者去登记它，表会静默漏项。分家之后规则是一行比较，对新类型自动成立——
这正是同一批次里另一处已经论证过的取舍（挂账 `address-by-object` D11：普适判据优于按类型的例外表）。

**把判断留在启动点，让它自己在发现「被合并了且我带了参数」时落一条告警。** 引擎不用改，
代价是三处各写一遍，且**启动点只有自己那一份声明**——「这次合并丢没丢东西」是需要同时看两份
声明才答得出的事实，只有引擎手里有。

**承认发起方会改变跑法，改词汇表那句话。** 否掉是因为界面上那枚徽章就是照着「谁叫来的」画的；
让**发起方**开始夹带行为，等于把一个干净的概念换成一个说不清的。

## 后果

**判据今天有一个机械检查。** 重启函数读回哪些键是 grep 得出来的：`taskParam(run, …)` 命中的
就是重启入参，其余都是标签。这个检查会随着重启函数增多而变松（有人可能直接读 `run.Params`），
因此它是落地时的对账工具，不是长期护栏——长期护栏是那两个格子本身。

**三处已知的「同一件事报了两遍」由同一条判据一次裁掉：** 扫描等级同时在声明与**上限**表里；
koreader 与维护任务把三个 IO 数同时报进**指标**与参数；四个跨库任务把一块盘报成自己的存储档位——
第三处按判据连标签都不该有，跨库的运行没有单一的盘可标。

**每个启动点的声明都要重新归位一次。** 这是一次一次性的人工判断，判错的后果是安静的：
把入参判成标签，重启函数就读不回它、静默回落到默认值（`RunSpec.StartParams` 的 doc 已经
记着这样一处：AI 分组的语种）。


## 落地契约

合并比较落盘的排队运行 `Args` 与本次提交 `Args`（空 map 与 nil 等价）。每次差异均写
`control/coalesced` 事件，无损仍仅首次写；不替换先排声明、发起方、任务体或上限。
事件 `detail` 为 JSON，包含本次 `trigger`、`args`、`labels`、`limits` 与 `lossy`；
HTTP 原样交回，任务详情显示明细。此字段沿用字符串契约，不增加传输字段。

封面输入 `backfill` 显式控制是否发现缺封面，不依赖发起方。旧记录没有此键时沿用回填默认值；
新记录显式 false 时只认领当前进程已有批，跨进程没有批则不自行找活。
KOReader 对账和匹配刷新消费 `match_mode` 与 `path_ignore_extension`，单独重建指纹只消费
`match_mode`。低优先级回填只消费 `reason`，模式与跑法由变体规定。

扫描的环境已经在 `Limits` 中，不重复塞标签。跨库维护没有单一盘的标签；计数、IO 等待与暂停
只报指标。不可重启的外部会话与迁移计划标识是标签；ComicInfo 系列身份不再重复写入参。
旧运行不回写迁移，展示消费者保留旧 `params` 回落；重启函数继续忽略旧环境与指标键。
