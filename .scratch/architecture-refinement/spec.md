# Spec: 全项目领域边界、完整用例与资源生命周期整理

Status: ready-for-agent

阶段：根据 2026-10-26 已确认设计与 Q1–Q19 整理的待实施规格。测试边界沿用已确认的完整用例、真实临时 SQLite、资源与生命周期及前端消费者验证方案。本状态只表示规格就绪，不表示已经拆票、实施或完成运行验收。

## Problem Statement

作为长期维护与使用 Manga Manager 的人，用户希望继续深化整个项目的结构，使一次功能修改不再要求同时理解数据库生成结构、HTTP 辅助方法、后台任务、资源池和多个页面的隐含约定。上一轮已建立阅读、藏书编排、应用生命周期和前端会话的主要归属，但完整能力仍存在模型混用、事务能力过宽、宿主承担装配和功能接口依赖页面等问题。

用户要求审查扩散到大多数代码文件与主要功能，而不是只拆 Controller。Controller 中的结构体与辅助方法只是线索：传输契约、领域概念、查询结果、持久化记录、运行时状态和技术辅助需要按含义归位。单纯移文件、缩短文件或统一目录层次不能证明修改知识集中，也不能说明调用方更容易正确使用功能。

当前一些边界还有可观察的产品后果：提案部分应用可能在并发拒绝后继续写入；作品群重建失败缺少跨重启修复依据；删库先发生取消和停监听却没有完整的占用协调及失败恢复；外部库只检查与当前资料库的重叠；整本复制结束前不能响应取消；归档替换与活跃读取缺少明确的发布资格；查询失败可能被展示成零或空集合。配置保存、生效时间和运行中资源的关系也需要明确表达。

## Solution

在现有模块化单体与单一领域语境内，按实际问题采用 DDD 的语言、模型、不变量和一致性边界。让完整写入用例拥有规则与原子保证，查询按用途返回明确视图，应用编排拥有跨功能协作，装配根拥有进程构造，技术能力拥有资源和访问资格，前端功能拥有跨页面状态与操作结果。

覆盖藏书与读者视图、元数据与提案、藏书编排及派生恢复、资料库管理、书内容与文件发布、扫描与身份、配置及集成资源、运行声明与契约、账户与前端功能归属。已具备明确职责的能力保留；存在重复知识或隐含配方的能力完成迁移，不要求每个文件都发生变化。

按完整功能逐批交付，保留身份、权限、协议、来源差异和已批准的历史取舍，同时实施本轮明确确认的行为修正。通过实际调用者、真实事务、文件操作、重启恢复与前端消费者验证成果；迁移完成后移除被替代的生产规则副本。

## User Stories

### 全项目职责与维护体验

1. 作为维护者，我希望主要后端与前端功能都纳入审查，以便本轮改善覆盖整个项目而不只围绕 Controller。
2. 作为维护者，我希望审查区分文件索引、关键路径阅读和实际运行验证，以便能够判断结论的证据范围。
3. 作为维护者，我希望每个主要区域都有保留、调整或需验证的明确处置，以便未修改文件不被误认为遗漏。
4. 作为维护者，我希望业务规则、状态、事务和生命周期各有明确所有者，以便修改知识集中在所属能力。
5. 作为调用者，我希望通过完整用例表达意图，以便不必自己组合校验、写入、聚合与后续动作。
6. 作为维护者，我希望领域概念、查询视图、编辑输入、传输契约和持久化记录按含义区分，以便结构体归属可以从职责判断。
7. 作为维护者，我希望合理的技术辅助保留清晰职责，以便不会为采用 DDD 而增加无收益的领域包装。
8. 作为维护者，我希望模块通过所需能力建立依赖，以便不会把全站应用对象或全量 Store 变成默认入口。
9. 作为维护者，我希望业务模块不反向依赖 HTTP 或页面，以便同一功能可以由不同输入和测试调用。
10. 作为维护者，我希望读写各有合适的接口，以便写入一致性与查询效率都能得到保证。
11. 作为维护者，我希望使用现有单一领域语境和部署方式，以便模块整理不演变成无依据的上下文或服务拆分。
12. 作为维护者，我希望有依据的业务差异继续保留，以便统一结构不会抹平不同来源和功能的意图。
13. 作为维护者，我希望每条迁移都有实际消费者且删除旧规则副本，以便不会同时维护两份权威实现。
14. 作为维护者，我希望按规则集中和验证成本评估成果，以便文件数量、行数和层数不代替真实收益。

### 藏书事实与读者阅读视图

15. 作为阅读者，我希望书的藏书身份与个人阅读状态分开表达，以便另一位读者的进度不改变这本书的身份。
16. 作为调用者，我希望阅读查询明确接收主体，以便结果属于谁不依赖隐含全局用户。
17. 作为维护者，我希望类型能区分藏书事实与已绑定读者的阅读视图，以便调用者不会忘记先做主体投影。
18. 作为阅读者，我希望详情、导航和继续阅读使用同一主体的事实，以便不同入口不会展示他人或全局兼容进度。
19. 作为兼容客户端使用者，我希望无站点用户的路径继续保留已确认语义，以便升级不会丢失兼容阅读能力。
20. 作为维护者，我希望非法主体不能被静默当作匿名，以便输入错误不会变成另一种身份的读取。
21. 作为阅读者，我希望主体读态进入筛选、排序与计数后再分页，以便分页结果和总量真实反映自己的状态。
22. 作为维护者，我希望列表查询继续使用批量 SQL 和必要聚合，以便模型分离不会退化为逐书查询。
23. 作为阅读者，我希望书、系列和跨页面读态解释一致，以便已读、未读和阅读中不会因页面而变化。
24. 作为阅读者，我希望未知页数的完成态与真实页数分开，以便不会把内部哨兵显示为已读页数。
25. 作为阅读者，我希望有效新位置继续允许前进和回退，以便结构调整不恢复旧的最远页策略。
26. 作为离线阅读者，我希望原时间、事实身份及清除后的拒旧规则继续有效，以便视图整理不破坏上一轮已交付的写入语义。
27. 作为阅读者，我希望普通继续阅读与有序清单的重读回退各保留用途，以便全部已读后仍可从清单首书重读。
28. 作为客户端使用者，我希望既有 JSON 和 TypeScript 字段保持兼容，以便内部模型变化不迫使客户端同步改版。
29. 作为维护者，我希望缓存区分主体及所依赖事实，以便不能把一个人的视图复用给另一个人。
30. 作为维护者，我希望基本阅读规则可经完整查询和用例验证，以便无需构造整个 HTTP Controller。

### 写入用例与事务能力

31. 作为维护者，我希望事务能力只提供完整一致性操作所需内容，以便窄接口不能通过回调穿透为全部 SQL。
32. 作为维护者，我希望事务归属按业务不变量确定，以便不会按一张表或一个 handler 机械划界。
33. 作为调用者，我希望人工保存元数据是完整动作，以便不必补上事务、系列统计和响应重读配方。
34. 作为管理员，我希望人工编辑的未提供字段与显式清空继续区分，以便既有编辑意图不被改变。
35. 作为管理员，我希望批量编辑继续保留标量、标签添加与移除的既有次序和语义，以便抽取不会改变结果。
36. 作为管理员，我希望扫描写入继续遵守标题和元数据锁定，以便摄入不会覆盖人工保护。
37. 作为管理员，我希望提案应用继续遵守来源规则、锁定与字段选择，以便不会被统一成无差别覆盖。
38. 作为维护者，我希望元数据来源规则仍有单一归属，以便完整应用用例不会复制另一份规则。
39. 作为维护者，我希望存储适配避免形成包依赖循环，以便业务类型分离后仍可编译和独立验证。
40. 作为维护者，我希望只隔离有业务含义的存储形状，以便纯查询不产生大量无规则收益的转换。
41. 作为操作发起者，我希望结果区分未提交、部分提交和已提交但后续未完成，以便可以安全判断是否重试。
42. 作为操作发起者，我希望前批已提交结果在后批失败后继续有效，以便错误报告不会掩盖已发生事实。
43. 作为维护者，我希望进度已保存而统计失败仍独立告警，以便不通过强事务回滚改变已批准的软统计语义。
44. 作为维护者，我希望退出无人使用且可绕过新规则的旧写入口，以便未来修改不会重新长出第二条写路径。

### 提案的并发裁决

45. 作为审核者，我希望完整应用和部分应用都在写入事务中确认提案仍待裁决，以便终态之后不再写入字段。
46. 作为审核者，我希望并发拒绝先完成时后来的部分应用返回冲突，以便抢先完成的裁决得到尊重。
47. 作为审核者，我希望冲突时本次元数据、提案字段和来源沿革都不提交，以便审计与实际结果一致。
48. 作为审核者，我希望拒绝不撤销此前成功应用的字段，以便已确认事实不会被后续拒绝反向抹去。
49. 作为审核者，我希望部分应用成功后保留剩余待裁决字段，以便可以继续处理未应用部分。
50. 作为审核者，我希望应用依据事务内最新字段、锁定和系列事实选择，以便不使用加载后已过期的选择结果。
51. 作为审核者，我希望两个部分应用交错时不会重复使用已移除字段，以便来源和剩余建议保持一致。
52. 作为审核者，我希望完整应用仍能正确进入终态且不可重复裁决，以便原有状态语义保持有效。
53. 作为审核者，我希望全部锁定或没有可写变化仍得到准确结果，以便不会把未写入误报为应用完成。
54. 作为客户端使用者，我希望裁决冲突与系统故障可区分，以便页面可以重读当前状态而不是误报保存失败。
55. 作为维护者，我希望真实并发事务覆盖裁决竞争，以便事务外预检不能被当作唯一正确性保证。

### 藏书编排与作品群恢复

56. 作为管理员，我希望人工合集、智能书架、快照、作品群和阅读清单保持不同成员语义，以便结构统一不改变编辑权限。
57. 作为管理员，我希望一次性快照和 AI 落地合集继续归人工所有，以便来源不会被误认为持续推导。
58. 作为管理员，我希望合集名称、归属和成员修改通过完整用例维护，以便输入不需要了解跨表约束。
59. 作为阅读者，我希望作品群身份和成员差集更新保持稳定，以便重建不使收藏入口或链接无故变化。
60. 作为管理员，我希望关系保存可以先成功而作品群随后更新，以便每次编辑不等待整个关系图重建事务。
61. 作为维护者，我希望关系变化与待更新依据同事务提交，以便关系已变但修复责任不会丢失。
62. 作为维护者，我希望派生更新依据覆盖全局关系图，以便跨资料库关系不会被错误分割。
63. 作为维护者，我希望系列和资料库删除导致的级联变化也标记派生结果待更新，以便修复不会只覆盖显式关系编辑。
64. 作为维护者，我希望影响派生结果的系列事实变化也进入更新依据，以便成员名称等展示不会永久陈旧。
65. 作为阅读者，我希望重建失败后系统退避重试，以便一次暂时错误不会永久留下旧结果。
66. 作为阅读者，我希望服务重启后仍继续未完成重建，以便内存通知丢失不影响最终修复。
67. 作为维护者，我希望重建期间的新变化不会被旧成功清除，以便系统不会误以为已追上最新关系。
68. 作为维护者，我希望旧尝试的失败不能覆盖较新的成功状态，以便修复状态反映实际版本。
69. 作为阅读者，我希望已有成功作品群结果在失败期间仍可读且标明陈旧，以便保持可用性而不误信其已更新。
70. 作为阅读者，我希望首次没有成功结果时显示不可用而不是空结果，以便不会误判没有作品群。
71. 作为管理员，我希望可以立即重试派生更新且后台责任持续保留，以便可以主动恢复而不依赖下一次关系修改。

### 资料库管理与删除协调

72. 作为管理员，我希望创建、修改和删除资料库各有完整用例，以便 HTTP 与导航壳不再持有操作配方。
73. 作为管理员，我希望资料库路径、格式、间隔和已有路径占用有一致校验，以便不同输入不会绕开约束。
74. 作为管理员，我希望新建后的监听、首扫和刷新得到完整交接，以便资料库创建成功不被等同为扫描完成。
75. 作为管理员，我希望有记录的资料库改路径继续使用保留身份的迁移流程，以便普通设置修改不会破坏记录。
76. 作为管理员，我希望保护恢复约束继续限制自动处理和危险清理，以便迁移后异常记录不会被误删。
77. 作为管理员，我希望删库先关闭该库新工作和读取准入，以便等待期间不会不断增加占用。
78. 作为管理员，我希望已排队工作在删库保留期间也不能开跑，以便关闭准入不是只拦住新发起。
79. 作为管理员，我希望可取消的本库运行被请求取消并有界等待，以便删除不会无限挂起。
80. 作为管理员，我希望仍有阅读、不可取消或跨库工作占用时明确阻止删除，以便不会靠外键失败收拾晚到写入。
81. 作为管理员，我希望删一个库不自动取消覆盖其他库的系统运行，以便其他资料库工作不受牵连。
82. 作为维护者，我希望取消资格结合实际覆盖和任务身份判断，以便任务键前缀或单个库标识不造成误判。
83. 作为维护者，我希望等待的是访问者真实退出而不只是展示终态，以便资源仍在使用时不会删记录。
84. 作为维护者，我希望占用排空与升级独占之间没有重新准入窗口，以便并发访问不能穿过删除边界。
85. 作为管理员，我希望请求取消、超时或删除失败后准入被释放，以便仍存在的资料库可继续使用。
86. 作为管理员，我希望删除失败后按当前设置恢复应有监听，以便资料库不会悄悄失去自动发现能力。
87. 作为管理员，我希望失败结果说明已取消的运行不会自动复活，以便可以有意识地重新发起工作。
88. 作为维护者，我希望删除释放后适用队列恢复放行且其他库不被阻塞，以便协调能力不会造成永久停滞。
89. 作为管理员，我希望删除成功后统计、阅读路径、推荐和派生结果得到必要失效或修复，以便不继续看到已删资料库的旧内容。

### 书内容访问与归档发布

90. 作为阅读者，我希望页清单、页读取和整书打开使用一致内容来源，以便缓存和访问资格不因入口不同而分叉。
91. 作为调用者，我希望内容能力隐藏来源定位、归档借还、加工和缓存资格，以便不必重新拼接读取配方。
92. 作为维护者，我希望内容事实与 HTTP 响应映射职责分开，以便技术读取能力不依赖请求对象或响应状态码。
93. 作为阅读者，我希望整书下载在句柄关闭前保留所需访问资格，以便删除、迁移或回写不会强行截断已开始的读取。
94. 作为维护者，我希望已物化页字节及时释放归档借用，以便资源占用符合实际使用范围。
95. 作为阅读者，我希望图像透传、真实加工结果和缓存资格继续区分，以便没有实际加工的结果不会被错误缓存。
96. 作为阅读者，我希望图像尺寸、解压与内存保护继续有效，以便内容抽取不会扩大危险输入的资源影响。
97. 作为阅读者，我希望缓存包含影响字节的参数与来源依据，以便变更图像选项或替换归档后不会读取旧内容。
98. 作为管理员，我希望 ComicInfo 临时归档构建尽量不阻塞阅读，以便耗时处理不占据整段写入窗口。
99. 作为管理员，我希望最终替换前取得该书短期写入资格并阻止新借用，以便在稳定发布窗口处理原归档。
100. 作为管理员，我希望发布有界等待已有读取结束，以便工作不会无限等待且不强制切断读者。

## Implementation Decisions

### 组织与依赖

- 按已确认业务语义建立完整能力，不预设所有模块采用统一三层模板。模块包括藏书事实与读者查询、领域写入用例、资料库管理、书内容及身份、扫描摄入、进程与技术能力、运行与投影、账户用例和前端功能。已有清晰能力可以保留。
- 延续单一领域语境、模块化单体和现有部署。表不等同聚合，目录不等同 bounded context。以不变量、改变知识和调用者必须掌握的约束划分 interface。
- 输入适配负责解析、身份、授权入口及外部响应；完整功能拥有内部规则、原子边界和应有后续结果。应用编排组合不同功能，装配根组合进程能力；两者均不成为吸收所有规则的总对象。
- 完整用例接收明确操作主体并维护本功能的所有权与业务授权约束，不能用入口已经解析身份代替实际所有权校验；HTTP 与设备协议仍维护各自的认证及访问入口。
- 事务回调仅提供所需能力，不暴露全量生成查询对象或任意数据库连接。适合位置变更的原子存储操作加业务决策模式保留，不统一套用全站 UnitOfWork 或通用 CRUD Repository。
- 具体存储适配承担必要转换，避免数据库包反向依赖已使用它的领域包。全量存储能力可保留在合理装配位置，但不作为功能默认依赖。
- 页缓存归内容能力，统计缓存归对应查询能力；已提交动作负责交接必要失效。收窄旧写入口前核对迁移、测试及真实消费者，结束后只保留单一权威路径。

### 模型、查询与元数据

- 藏书事实不带隐式当前用户读态；读者阅读视图明确主体。主体明确区分站点用户、匿名兼容及非法输入。读取方无需执行先取记录再覆盖字段的配方。
- 查询按列表、搜索、详情、统计和继续阅读用途提供结果。主体进入过滤、聚合、排序、计数与 SQL 分页之前，保留批量与缓存，不以逐项装载实体替代高效查询。
- 内部查询模型与传输形状可以不同，由 adapter 保持既有外部 JSON 和生成 TypeScript 名称与含义。未知页数完成态、普通下一本未读及清单首书重读分别保留已确认语义。
- 阅读写入保持原时间、稳定事实身份、拒旧、清除跨重启和批内聚合语义；位置提交与软统计的失败边界不重定义。真实结果区分未提交、部分提交和已提交但后续未完成。
- 人工元数据编辑的完整应用 owner 组合事务、来源特定规则及必要统计。seriesmeta 保持人工、批量、扫描、提案的来源区别，不加入通用策略开关，也不吸收任务和跨功能生命周期。

### 提案与藏书编排

- 提案完整应用与部分应用均在写事务内取得待裁决守卫，再重载字段、锁定和系列事实。事务外预检可以快速拒绝，但不得成为最终依据。部分应用删除本次已应用字段而保留其余待裁决内容；完整应用推进终态。
- 并发终态先完成时返回明确冲突，本次元数据、字段及来源沿革一起不提交；不回滚此前已经成功的部分应用。无需为此新增提案版本协议，但具体守卫必须保证真实 SQLite 并发正确。
- 人工合集、智能书架、快照、作品群和有序清单保持独立含义与所有权。AI 分组不是系列元数据提案，应用与建合集仍按既有完整动作保持一致。
- 作品群按全局关系图范围保留持久更新依据，采用期望版本与已应用版本或等价的防丢变更机制。关系变化和待更新依据同事务提交；直接编辑、级联删除及影响派生结果的事实更新都须进入覆盖。
- 重建以一致图事务提交稳定身份、成员差集与完成依据。新变化不能被旧成功清除，旧失败不能覆盖新成功。失败保留责任并退避重试，启动恢复未完成修复，提供立即重试。
- 查询区分已有旧结果、首次无成功结果、更新中和更新失败。已有成功结果可读且显式陈旧；无成功结果不可用，真实完成后的空结果仍是正常空。仅保存恢复和展示所需依据及最近结果，不建立关系事件账本或第二套任务系统。
- 持久化变更保持现有作品群及成员身份，并建立最小更新版本、最近尝试及修复状态。升级时已有结果可以作为陈旧结果保留，首次成功核对前不以默认版本值误判为已追上；迁移失败不得损坏原关系与合集事实。

### 资料库访问与删除

- 资料库管理接管创建、修改、删除的校验、落盘、监听、运行交接及必要失效。非空资料库路径变更、持久保护、迁移补偿和恢复独占继续遵守既有决定。
- 迁移内部明确持久操作过程、路径与保护决策、SQLite 适配和配置协调的归属；保留路径已提交状态、效果失败时的独占、配置补偿与恢复先于开放等承重约束，不能把文件和数据库操作伪装成一个普通 Save 事务。
- 在同一任务引擎访问协调中增加关闭准入后排空的能力，不能直接复用仅在无占用时才关闭的即时独占操作，也不能新增删除专用准入锁。
- 删除保留关闭目标新读取、新运行及已有覆盖队列的放行；在引擎锁外请求取消允许取消的本库运行并有界等待。判断取消资格要使用任务身份及实际覆盖，不按任务键猜测，不取消覆盖其他库的系统工作。
- 等待使用者真正退出。最终排空检查与独占升级须防竞态，失败、放弃及请求结束都幂等释放资格；解除保留唤醒适用队列，其他库工作继续正常推进。
- 占用未释放时返回结构化冲突，不删记录。删除失败按当前设置恢复监听，如实说明已取消结果，不自动重做写盘、清理或付费操作。数据库成功后交接缓存及派生修复；外部副作用不承诺随数据库回滚。
- 等待预算服从请求取消且有上限；具体常量、通知方式和内部锁形状是工程决定，必须通过无丢通知、无死锁和公平放行相关回归。

### 书内容与文件操作

- 页读取、页清单和整书打开共享明确内容能力，隐藏来源定位、归档池、加工、缓存资格与访问租约。书身份和设备匹配保留不同 seam，不建立万能 BookService。
- 整书读取句柄关闭时归还访问资格；已物化独立页字节可结束归档借用。HTTP 保留请求和响应映射；内容能力提供实际加工、字节、签名或来源等事实，不要求调用方推断缓存资格。
- ComicInfo 暂存构建尽量与读取并行；最终发布前取得书级短期写入资格，阻止新借用并有界等待已有读取，结合原文件变化检查。冲突时不发布、不截断读取，清理本次暂存并保留原归档。
- 发布与资料库删除、迁移访问协调配合，不另建任务准入。池淘汰不等于最后使用者退出；真实文件替换性质、缓存失效及发布后部分失败须分别验证和表达。
- 外部路径与任何已登记资料库的相等、祖先或后代重叠均被拒绝；路径比较延续平台正确的路径语义并防止显而易见的别名绕过，具体解析与不可解析路径失败归类由工程设计明确，不借此提供跨库传输。
- 外部复制拥有明确复制会话、暂存文件、偏移、提交与资源归还。取消在块边界检查，保留已成功文件与已有目标，清理未提交暂存；暂停保留当前复制状态并释放可重新取得的 IO 配额。
- 恢复前重新核对源事实与目标资格，不能确认安全时失败并清理本次暂存，不拼接变化来源。不新增进程重启后的自动续传；不承诺强行中断系统内阻塞的单次读写。
- 最终发布不得覆盖复制期间已经出现的原有目标。未提交文件不计成功，部分成功保留范围并更新会话投影；发布后失败不能被表达成从未写入并诱导盲目重试。

### 扫描、身份、配置及集成

- 扫描保留完整摄入与清理用例，内部围绕发现、解释、身份认领、落盘和安全清理组织。技术 watcher 交付变化，摄入协调掌握去抖后的真实扫描完成、失败重排及清理资格。
- 保留唯一运行准入、独立封面运行、迁移保护、安全清理和 size+mtime 改名重连取舍。扫描、维护通过中立身份能力获取证据，KOReader 继续拥有账号、认证、设备键匹配和协议记录；不改变现有算法。
- 配置 Manager 继续作为事实源，保存、重载及跨持久参与者协调保留各自补偿含义。进程资源有明确创建、替换与关闭者，可先维持进程单实例。
- 配置按字段提供即时、后续作业或重启后生效含义。一次操作目标、来源和写入意图固定在适当发起边界；资源预算安全更新，不强行销毁旧使用者的资源，设置不得只展示保存成功而掩盖生效范围。
- 元数据搜索、推荐、分组和连接测试按实际消费能力收窄输入与依赖。同一供应商可实现多个接口；上游格式、分页、重试、取消、预算和脱敏仍归适配实现，不抹平来源差异。

### 装配、运行与账户

- 装配根创建资源与必要传输 leaf effects，连接应用能力、登记重启能力、执行恢复，然后开放后台和请求。HTTP 处理器只依赖需要的用例与查询，不承担整个进程创建与启动，不镜像全部运行时服务。
- 停机保持停止输入、排空请求与推送、停止监听、取消并等待运行及后台、最后释放资源的承重顺序。登记或恢复失败不得开放后台输入。
- ADR 0008 完整落地：影响重放行为的输入与仅描述环境的标签分开；有损合并每次记录事件，无损合并维持首次事件降噪；不改变被合并运行的既有执行选择，不把发起方当行为参数。
- 逐启动点核对参数、声明标签、上限、指标和文案参数的含义，避免重复事实。任务领域与落盘、HTTP/SSE 投影、日志、事件和采样分工保留，生成契约按源更新。
- 账户初始化、角色变更、删除和改密成为完整用例，核对现有不变量在真实事务与并发下成立；传输保留 Cookie、CSRF、限流及协议挑战等安全职责。保持字节精确用户名、禁止删自身、最后管理员保护及既有旧数据归属政策，不扩展为新的权限系统。

### 前端功能与界面状态

- 离线功能拥有归属、书目、字节、下载与补传契约，鉴权和离线书架消费功能能力。断网、会话过期、显式登出、换人和首次认领的差异保留，既有进度事实与队列语义保留。
- 配置编辑会话集中维护分区字段、草稿、基线和版本冲突；账户诊断及维护能力独立生命周期。读模型与编辑输入区分，不要求列表与详情强行同构，也不把所有后端 DTO 全量转换成统一实体。
- AI 分组动作返回权威候选及整单结果，前端只合并投影。查询只取数，功能动作基于真实提交结果声明必要失效；部分提交也触发对应刷新。
- 功能模型与接口由功能拥有，组件、页面、Layout 消费它们；页面保留筛选、选中、滚动、弹窗和草稿等局部状态，不建立包揽全部功能的全站 store。
- 真实空值、未加载、失败与陈旧分别表达。已有成功数据失败后可以保留并标记陈旧，首次失败不可用且可重试；必要主干失败不伪装成功，附属降级由功能定义。异步作用域同时核对主体、目标和请求代次。

## Testing Decisions

### 测试面与质量标准

- 已确认的主要 seam 是完整用例和查询 interface，而不是仓储步骤、辅助方法或整个 Controller。现有 seam 优先；新能力只在完整资料库管理、内容访问/发布、复制会话、派生修复和配置编辑会话等必要的最高功能入口建立 seam。不同功能不硬塞进单一测试总对象。
- 测试断言外部可观察结果、持久事实、可用性、提交范围、冲突和恢复；不以内部函数调用次数、文件布局或 mock SQL 顺序证明业务正确。
- 结构与归属由生产调用者、依赖审查和旧副本核对支持，行为由运行测试支持；不编写只镜像实现的结构测试，也不声称一个行为断言证明全仓所有权。
- 事务规则使用真实临时 SQLite，文件规则使用真实临时目录、归档与句柄。时钟、外部供应商、必要故障点和阻塞控制用最少 seam 提供确定性，不以不受控 sleep 抽签判断并发正确。

- 时间和并发用可控屏障构造先后顺序；取消/暂停用复制会话或 IO 检查点控制，真实外部磁盘卡顿仅作为明确平台限制，不能将系统拦截或环境失败记为通过。
- 生命周期与持久修复必须包含关闭再开启、失败后恢复和后续更新竞争。归档活跃借用与替换在适用平台验证，不能只 mock 文件系统成功。

### 门禁与证据

- 实施时执行适用后端测试、gofmt、golangci-lint，前端测试、lint 和构建；SQL 与 TS 生成按项目规则验证无漂移，SQL 查询源保持 ASCII，sqlc 本机使用 PowerShell。
- Go 工具链及 lint 与 CI 对齐，使用合法缓存和临时目录。承重资源与并发更改执行相应竞态回归，远端多平台 CI、漏洞扫描及生成契约门禁按项目流程实际验证。
- 维护规格故事到实现、消费者及执行结果的映射。新测试源码存在、历史运行通过、本轮实际通过和未执行限制分别记录；真实设备或供应商未运行时明确标记。
- 本规格阶段只核对文档、来源和既有 seam，不宣称新规则已经通过运行测试。

## Out of Scope

- 微服务拆分、无词义或自治依据的多 bounded context、改变部署方式、替换 SQLite/sqlc，以及全仓统一领域/应用/基础设施目录模板。
- 全站万能应用对象、统一客户端数据库、全局 store、通用事件总线、独立读库、通用 outbox、通用 saga 或完整关系/阅读事件账本。
- 全量映射所有数据库结果、为所有实体建立通用 CRUD Repository、为每个技术辅助新建领域服务，以及仅凭文件大小的大规模改名。
- 更改书哈希、设备路径匹配、size+mtime 改名重连算法、自动合并冲突记录或猜测重建历史阅读活动。
- 抹平元数据不同来源规则、把软统计改为强事务或无依据重试时长、改变人工/动态/推导成员所有权。
- 跨资料库传输产品功能、外部传输跨进程自动续传、强行截断活跃下载或系统阻塞 IO、跨标签合并连接或升级离线下载为全站任务。
- 更换认证机制或扩建新权限系统、真实外部供应商能力改版、图像及归档格式算法重写、主题/CSS/纯呈现的无关重做。
- 本阶段创建实施工单、修改生产行为或宣称交付完成；后续 to-tickets 和 implement-spec 分别承接。

## Further Notes

- 需求来源为已确认的 [设计](design.md)，事实范围与尚未深读处见 [审查线索](audit.md)。本规格是后续拆票与验收的需求依据，审查候选描述不构成另一套产品规则。
- ADR 0001、0003、0005、0006、0007、0009 的有效决定继续保持；ADR 0008 的未完成部分纳入本轮。ADR 0010–0015 记录本轮模型、提案、派生恢复、删除、整体组织与内容发布决定，接受状态不等于实施完成。
- 测试边界复用已由用户确认的完整用例、真实临时 SQLite、资源与生命周期和前端消费者方案；没有重新开启需求访谈。工程可自行选择包名、文件布局、适配实现、等待与退避常量，但须满足有界、可取消、不会丢失修复责任等已确认约束。
- 推荐先稳定事实/视图和写入 seam，再完成裁决与派生修复、访问与文件协作、扫描/资源/装配、任务声明及剩余前端与账户整理。依赖稳定后可交错推进，每批须有真实消费者及完整回归，不以孤立新模块作为交付。
- 后续每个实施工单单独承载验收条件及依赖，本规格不以故事分组代替拆票。ready-for-agent 表示可供后续代理制定实施任务，不表示已存在任务队列。
- 结构改善须通过归属、依赖与调用知识减少核对；功能修正通过运行行为验证。仅移动类型的导航收益应如实描述，不夸大为领域深化或性能提升。
