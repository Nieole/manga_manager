## Comments


### 实施与验证

- 同一 task.Engine 的 `ReserveLibrary` 关闭目标读取、新运行及既有覆盖队列；`LibraryReservation.Upgrade` 在同一互斥边界检查占用并升级独占，`Release` 幂等释放并恢复适用队列，其他资料库继续放行。迁移独占和保留互斥，没有删除专用锁。
- 冲突依据引擎实际 LibraryIDs、任务身份和真实访问 claim；快照进入终态不意味着 body 已退出。删除提交后退休稳定库 ID，避免旧请求在释放后重新准入该已删库；AllLibraries 新工作仍可处理剩余资料库。
- `application/libraries.Service.Delete` 拥有完整资格、监听、删除及提交后交接。占用返回时不取消任何运行或停止监听；数据库失败/请求取消释放资格，并按当前设置恢复适用监听，恢复失败单独告警。原 HTTP 删除配方与无人消费的取消/丢批适配退出。
- HTTP 保留空闲删除成功形状，结构化 409 返回真实占用；删除界面实际消费读者、排队、收尾、跨库占用，冲突时保留库与确认弹窗，重试提交后才交接导航/刷新。恢复监听失败独立提示。本票不提前执行 23 的主动取消或有界等待。
