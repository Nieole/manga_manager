# 共享弹窗背景模糊的 GPU 回归

## 当前实现

`ModalShell` 将原生 4px 背景模糊分成 8×4 个区域，颜色遮罩独立绘制。迁移、恢复与其他共享弹窗均保留模糊；不暂停动画、不降低动画帧率、不停止数据更新。分块数量固定，不随资料库记录数增长。

迁移与恢复弹窗与其他弹窗共用同一模糊实现。正式修复版本为 v1.7.1，更新说明见 CHANGELOG.md。

## 复现环境与反馈循环

- 用户现场在另一台电脑：约 50 万条目的检查期间，开窗 GPU 约 70–80%，关闭约 20–30%；本次不访问该电脑或真实数据库。
- 本机 Windows / AMD Radeon 780M，独立有界面 Chrome，视口 2560×1215。使用实际迁移弹窗、共享外壳、任务气泡、主题与语言组件。
- 模拟数据是 5000 系列、500000 本书的接口摘要，不构造或渲染 50 万条数据库记录。后台气泡按任务引擎 200ms 投递间隔更新；迁移弹窗保留实际约 1s 轮询。
- 另一场景直接使用默认共享弹窗，并让弹窗内、背景各有一个持续动画。新回归同时验证实际 4px 滤镜覆盖整个视口、前后景动画仍为 running，以及 GPU 增量。
- 每个状态稳定 1.5s 后按 1s 间隔采样 8 次。指标为独立测试 Chrome GPU 进程的 Windows 3D / high-priority 3D 引擎占用之和，不是整机总占用。

修复前 `node .scratch/relocation-gpu/profile.mjs shared` 退出 1，开窗 30.06%、重复开窗 28.27%，关窗约 1.9%。未通过修改生产源码制造 RED。

最终回归在同一窗口中切换分块模糊与单块全屏模糊作为正向对照：只有单块模糊能重新产生足够高的 GPU 占用，低占用结果才有效。一轮窗口未有效绘制时出现的近零数值已弃用；测试窗口明确激活并禁用测试实例的遮挡降频，未更改用户浏览器或系统设置。

## 实测结果

| 场景 | 关窗 | 分块模糊 | 同窗口单块模糊对照 | 切回分块 |
| --- | ---: | ---: | ---: | ---: |
| 迁移检查 | 2.07% | 4.25% | 28.65% | 4.20% |
| 共享弹窗，含前后景动画与叠层入口 | 2.08% | 10.36% | 28.87% | 10.18% |

这些是本机模拟场景的数值，不能替代另一台电脑升级后的现场复测。保留模糊仍有绘制成本，不宣称与无模糊遮罩相同。

定位过程中：只停背景动画、只调整图层合成、将背景改为普通 filter、缩放滤镜均未充分解决问题；分块方式保留动画与模糊效果，并明显降低占用。16、32、50、64、128 块的实际对照及原始样本见 `evidence/blur-preserved/`。

## 画面与交互

对实际共享外壳修复前后截图做像素比较，排除前景弹窗、诊断工具栏和动态任务气泡，仅比较静态背景：平均 RGB 绝对差 0.031/255，分块边界 p99 差 1.667/255；同时人工查看确认模糊保留、没有明显接缝。比较脚本为 `compare-blur.py`。

真实浏览器检查 390×844、1280×720、2560×1215：滤镜区域覆盖率均为 100%，弹窗不越界；两层弹窗叠加时 Esc 只关闭顶层，最后一层关闭后滚动锁解除。该检查使用真实布局、CSS 和键盘事件。

`evidence/blur-preserved/` 保存本次单块模糊、分块模糊、正向对照及布局结果。父级 evidence 中的无模糊对照仅用于诊断，不代表当前交付效果。

## 运行回归

在仓库根目录准备隔离的测试依赖并启动开发服务器：

```powershell
npm install --prefix .tmp/relocation-gpu/runtime --no-audit --no-fund --package-lock=false playwright-core@1.64.1
npm --prefix web run dev -- --host 127.0.0.1 --port 18084 --strictPort
```

保持服务器运行，另一终端执行：

```powershell
node .scratch/relocation-gpu/profile.mjs shared
node .scratch/relocation-gpu/profile.mjs regression
node .scratch/relocation-gpu/profile.mjs layout
```

GPU 差值超阈值、实际模糊丢失、动画停止、正向对照无效或布局/叠层行为不符，都会退出失败。阈值用于捕捉本机此次约 26–30 个百分点的回归，不是跨硬件的通用性能标准。

脚本仅临时复制两个 web 入口，遇到同名不同内容文件会拒绝覆盖；退出时移除自己创建的入口并关闭独立浏览器。模拟 adapter 不连接后端，不触发迁移或取消请求。其余模式为明确标记的诊断对照；不会进入产品构建。

完整日志、隔离依赖与浏览器缓存位于忽略的 `.tmp/relocation-gpu/`，产品未加入调试日志或临时样式，真实资料库和系统安全设置不变。

## 最终本地门禁

- GPU：`shared` 与 `regression` 均退出 0，含单块模糊正向对照；`layout` 三种尺寸及叠层键盘行为通过。
- 画面：`compare-blur.py` 对已归档同场景截图比较退出 0，4px 模糊保留。
- 前端：81 文件、866 项 Vitest 通过；ESLint 与 TypeScript/Vite 生产构建退出 0。
- 后端、SQL、生成契约未修改；正式发布仍执行完整跨平台 CI。
- 临时 web 入口已移除，未加入产品调试日志或全局动画降帧。测试窗口的调度参数只用于测试实例。
