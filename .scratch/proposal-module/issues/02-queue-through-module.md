# 02 — 入队走模块

**What to build:** 刮削产出一条**提案**时，入队经新模块完成，三种良性结局（无差异 / 差异字段全被锁 / 此前已拒绝）与「复用了既有提案」成为结果值而不是哨兵错误。用户在这三种情况下看到的仍是可行动的提示，而不可能退化成「服务器错误」——今天那一点全靠一个「必须把每个哨兵都识别到」的纪律撑着。

模块本体、事务接缝与适配器随本票诞生：这是第一条打通的通路，也是后面几票的地基。

**Blocked by:** None — can start immediately.

**Status:** done

- [x] 新建 `internal/proposal`，含 package doc；模块只依赖数据库一样东西
- [x] 模块声明两个接口：事务内可用的查询集合，以及「开一次事务」的能力。查询集合里只放批量版字段行查询，逐条版不进接口
- [x] 适配器写在 api 侧；模块的任何签名都不出现 `database.Store`
- [x] 入队入口收一个已加载的**系列**（三个调用点都已握着它），返回已分类结果，`error` 只表示故障
- [x] 三个刮削入队调用点全部改走模块；`queueOutcomeForError` 不再出现 `errors.Is`
- [x] 入队的裁决用例搬进模块测试：真 SQLite、三步装配（migrate + store + 适配器），不构造 Controller、Scanner、config 管理器与归档解析器全局池
- [x] 覆盖：空提案不入队、与当前值相同不入队、**锁定字段**不入队且只统计「不锁就会入队」的那些、与 pending 签名相同则复用、与最近拒绝记录相同则报「此前已拒绝」、显式忽略拒绝记录时可重新入队、不同系列之间互不干扰
- [x] 旧的 Controller 入队方法暂留（票 06 删除），本票不留任何兼容垫片或过渡别名
- [x] `GOCACHE="$(pwd)/.gocache" GOTMPDIR="$(pwd)/.tmp" go test ./...` 全绿
