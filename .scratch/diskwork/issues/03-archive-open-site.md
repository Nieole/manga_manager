# 03 — 归档打开改走磁盘作业模块

**What to build:** 扫描 worker 打开归档读元数据的那一处改走新入口。票 01 已经把令牌的持有区间收拢到真正的归档 IO 上，这一票只需把那段区间包进闭包，让页目录与 ComicInfo 解析结果经闭包捕获带出来。

这是这套形状的**证伪点**。它是全仓唯一一处令牌跨越多次归档 IO 的取用点；若闭包形状装不下它，要在这里暴露，而不是在转完其余六处之后。它同时门控票 04 与票 05——这是刻意牺牲并行度换来的。

## Comments

闭包形状装得下这一处，**证伪点未被证伪**：两个出参（页目录、ComicInfo）经捕获带出，中止与否由闭包返回的 error 决定，手写的幂等 `closeArchive` 整个消失。票 04 与票 05 解锁。

本票新增了票面未要求的两条用例（`archive_open_test.go`）。归档打开失败与页目录读取失败这两条出口此前**零覆盖**，而它们正是本票唯一可能漏掉令牌的地方——用外置硬盘档把归档打开并发压到 1，漏掉的令牌会让坏档后面的好档永远扫不到，于是「令牌归还」这条验收有了会失败的守卫，而不只是一次目测。

三处偏离，前两处此前无票认领：

1. **存储策略的解析源从 `rootPath` 改成 `job.path`**。旧代码恒取资料库根命中的那条策略；新入口按 `Work.Path` 解析，而 `ResolveStoragePolicy` 走最长前缀匹配，因此配了「比库根更深」的策略条目时，本处生效档位会变。卷键在 unix 上不变。这不是本票引入的新口径——票 02 迁走两处哈希时已产生同样副作用，且封面构建那处本就按归档路径解析；本票只是让第三处对齐。**票 06 的 CHANGELOG 应把这条一并记上**，它与「每工种上限单独决定」是同一次口径统一的两面。
2. **申领失败时的等待与暂停耗时现在也汇入指标**（旧代码在 acquire 出错时丢弃）。方向与票 02 comment 3 一致：慢盘上等了很久最终被取消的申领，正是最该留下数字的一种。
3. **`progress.publish("reading_metadata", …)` 现在跑在闸门之前**，同票 02 comment 2 之因。此处影响近乎为零：`workerProcess` 开头另有一道闸门，暂停中的作业到不了这句 publish。

并发上限由 `min⁺(ScanConcurrency, ArchiveOpenConcurrency)` 收窄为 `ArchiveOpenConcurrency`，以及本处新得的 250ms 慢等待日志，均已由票 02 与票 06 认领，不另记。
