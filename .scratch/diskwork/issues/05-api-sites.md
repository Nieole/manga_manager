## Comments

八处**磁盘作业**至此全部走完新入口。`acquireTaskStorageToken` 随之无调用点，`golangci-lint` 报
一条 `unused`——它是票 06 第一条要删的东西，本票按票面顺序未提前动手，因此从本提交到票 06 之间
有一个 commit 的窗口 lint 是红的。

本票新增了票面未要求的一条用例（`hash_backfill_skip_test.go`）。两处回填在「指纹算不出来」那条
出口上的**分页游标推进**此前零覆盖，而它正是本票唯一可能失手的地方：游标推进与 `continue` 原先
挂在 koreader 直接返回的 `err` 上，改走闭包之后它变成闭包自己捕获的 `hashErr`。守卫有效性已实测：
摘掉两处的 `afterID = book.ID` 再跑，两条子用例都挂到 5 秒超时后失败——批次按 `id > afterID` 切，
坏书排在批次末尾时同一本被永远切回来。坏书必须排**末尾**才测得出：排中间的话后面那本好书会替它
把游标推过去，缺陷被顺手掩盖。

三处偏离，第一处此前无票认领：

1. **ComicInfo 回写在令牌申领失败时从「本本记失败、继续下一本」改成中止。** 申领只在上下文取消时
   出错，而中止路径返回 `TaskResult{}`、三个计数一并丢弃，因此这条改变对外不可观察；旧码那一次
   `failed++` 也只是把一次取消记成一次写失败。方向与两处哈希对齐：`Do` 返回的错误是闸门与令牌的
   错误，一律中止；闭包自己捕获的才是这一本书的结局。
2. **存储策略的解析源从 `book.LibraryPath` 改成 `book.Path`**（两处哈希）。同票 03 comment 1 之因，
   是同一次口径统一的第四、第五处：`Work.Path` 是「字节落在哪」，而 `identity_hash` 读的正是那本
   书。若改用 `PolicyFrom` 把策略源钉回库根，api 的 `identity_hash` 就会与扫描器的同工种解析出
   不同档位——那正是本次要消掉的「取决于调用它的是哪个包」。**票 06 的 CHANGELOG 应把这条一并
   记上**（票 03 comment 1 已提出同一要求）。
3. **ComicInfo 回写的聚合与序列化移出令牌持有区间**，同票 01 之因：那是纯 CPU 工作，夹在持有区间
   里只会虚占归档打开的并发额度。序列化失败仍计入失败计数，三类计数不变。

两条实现说明：

- **`absorbDiskWork` 只认有值的档位与卷键。** 闸门拦下的作业根本没解析策略，`Do` 交回零值 `Stats`；
  无条件照抄会把「没有实况」写成「实况为空」。等待与暂停仍无条件累加，含申领失败的那一次——
  与票 02 comment 3、03 comment 2、04 comment 2 同因。
- **两处手工拼装的测试装置补上了 `diskWork`**，调度器按 spec 的 Testing Decisions **新建**而非取包级
  实例。`seedIdentityCandidates` 那条「LibraryPath 留空 → 卷键为空 → 取令牌短路」的注释随之失真
  （卷键现由书的路径决定），已改写。
