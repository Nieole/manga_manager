# Spec: 资料库路径迁移

Status: ready-for-agent

## Problem Statement

用户在 A 电脑扫描外接硬盘上的漫画资料库，再把程序及原数据库迁往 B 电脑。硬盘内容与内部目录结构不变，但盘符改变。用户修改资料库根路径后，已入库系列与书仍指向原来的绝对路径，无法正常读取。重新扫描会按新路径创建系列，已有元数据、阅读进度与收藏等信息不能完整继承。

当前资料库编辑只更新资料库自身的路径，系列与书独立保存路径；扫描器的书文件改名重连也不能完整处理系列身份。对于已经只改了资料库根路径的用户，当前根路径还不能代表子记录的原根，不能简单再次替换当前根。

用户需要把现有资料库重新关联到新位置，保留原有身份与关联数据，并能在部分文件暂时缺失时继续迁移。只关闭自动扫描不足以保护这些记录：手动清理仍可能删除缺失书，连同关联的阅读进度一起删除。

## Solution

为每个资料库提供管理员专用的“迁移路径”操作：选择目标根目录，核对原根，后台检查并预览，确认后整体提交，最后在任务中心查看结果。已有系列或书的资料库通过普通编辑修改根路径时，也进入同一流程；没有系列或书的空资料库保留普通编辑能力。

迁移仅重新关联路径，文件由用户预先放在目标位置。保留库内相对路径以及资料库、系列、书的身份，连带保留阅读进度、元数据及其他关联。支持原根已经不可达，以及资料库根已改、系列与书尚未改的补迁移。每次操作一个资料库，多块硬盘分别处理。

检查区分阻断项与可接受的书文件异常。路径映射、已有记录、目录 IO 策略或相关工作冲突必须先解决。缺失、不可读和大小不同的书则列出明细，允许管理员明确接受后继续；这些书的原记录仍全部迁移，并建立持久化保护，关闭该资料库的自动扫描、监听和失踪清理，直到管理员主动恢复。

迁移期间短暂独占受影响资料库，其他不冲突资料库保持可用。相关目录 IO 策略随迁移更新，旧路径缓存与外部库比较会话失效。数据库路径、配置策略和保护状态在失败或重启后必须恢复一致，迁移完成不主动发起扫描。

## User Stories

1. 作为管理员，我希望在换机后把资料库关联到新的盘符，以便继续使用原有阅读记录与元数据。
2. 作为管理员，我希望为每个资料库单独迁移路径，以便分别处理挂载在不同位置的外接硬盘。
3. 作为管理员，我希望从资料库入口找到“迁移路径”，以便无需直接修改数据库。
4. 作为管理员，我希望在编辑已入库资料库的根路径时进入迁移流程，以便一次修改就覆盖系列与书。
5. 作为管理员，我希望空资料库仍能直接编辑路径，以便无需为尚无藏书的资料库执行无意义的迁移。
6. 作为管理员，我希望选择新目录时复用已有目录选择能力，以便准确选择服务端可访问的位置。
7. 作为管理员，我希望迁移原根已不可达的资料库，以便原盘符消失也不影响迁移。
8. 作为管理员，我希望修复已经只改了资料库根路径的状态，以便无需把资料库删掉重建。
9. 作为管理员，我希望核对系统提供的原根候选并能手动指定，以便候选有歧义时仍能使用准确的映射。
10. 作为管理员，我希望预览原根、目标根和路径示例，以便提交前确认选择的是同一套漫画资源。
11. 作为管理员，我希望看到受影响的系列、书和目录策略数量，以便评估操作范围。
12. 作为管理员，我希望内部相对路径保持不变，以便根路径改变不会重新组织漫画文件。
13. 作为管理员，我希望迁移不修改漫画文件内容，以便不产生搬运、覆盖或重新编码的副作用。
14. 作为阅读者，我希望书和系列的身份保持不变，以便已有详情入口、阅读进度和阅读活动继续对应原记录。
15. 作为阅读者，我希望书签、阅读时长与各用户独立进度保留，以便迁移不重置阅读历史。
16. 作为管理员，我希望标题、作者、标签、简介、字段锁与来源信息保留，以便无需重新整理元数据。
17. 作为阅读者，我希望收藏、合集和阅读列表中的归属保留，以便继续使用已有组织方式。
18. 作为管理员，我希望待处理提案与已应用字段的来源保留，以便迁移不影响审核工作。
19. 作为阅读者，我希望既有封面和自定义封面保留，以便资料库外观不会因换盘符丢失。
20. 作为 KOReader 用户，我希望原有内容指纹和库内相对路径指纹保留，以便设备进度继续匹配同一本书。
21. 作为管理员，我希望目标根不可访问或不是目录时被明确阻止，以便不会把整库关联到无效位置。
22. 作为管理员，我希望无法用一个原根解释的记录被列为阻断项，以便程序不会猜测内部改名或混杂记录的对应关系。
23. 作为管理员，我希望目标路径已有系列或书记录时看到冲突，以便先处理重复入库而非覆盖双方数据。
24. 作为管理员，我希望冲突检查包含其他资料库，以便迁移不会抢占其他资料库的记录。
25. 作为管理员，我希望检查目标书的存在性与大小，以便知道当前硬盘是否缺少文件或包含不同版本。
26. 作为管理员，我希望查看缺失、不可读和大小不同的书的明细，以便逐项处理异常。
27. 作为管理员，我希望明确接受书文件异常后仍可迁移，以便不完整的硬盘副本也能先恢复资料库关联。
28. 作为阅读者，我希望异常书的原记录也保留，以便暂时无法读取文件时不会丢失阅读进度与元数据。
29. 作为管理员，我希望带异常迁移后自动处理保持关闭，以便后台工作不会立即清除异常记录。
30. 作为管理员，我希望异常保护在服务重启后仍生效，以便重启不会悄悄解除保护。
31. 作为管理员，我希望手动扫描和清理入口提示迁移异常，以便操作前了解可能的后果。
32. 作为管理员，我希望失踪清理无法绕过保护删除书或系列，以便通过其他 API 或后台入口也不会丢失受保护数据。
33. 作为管理员，我希望主动恢复自动处理时看到尚存异常及清理后果，以便由我决定何时解除保护。
34. 作为管理员，我希望相关目录 IO 策略随路径迁移，以便移动硬盘的扫描、解压等限速继续生效。
35. 作为管理员，我希望看到目标位置的策略冲突，以便迁移不会静默覆盖已经配置的行为。
36. 作为管理员，我希望迁移不改变其他资料库的配置效果，以便其他硬盘的处理策略不受影响。
37. 作为管理员，我希望检查发现相关运行中或排队中的工作时列出它们，以便先完成或取消再迁移。
38. 作为管理员，我希望不可取消的清理被识别为需要等待的工作，以便不会误以为请求取消后就能安全迁移。
39. 作为阅读者，我希望迁移期间受影响资料库的读取暂停时有清晰提示，以便知道这是短暂操作而非文件永久损坏。
40. 作为其他资料库的用户，我希望不冲突的阅读和后台工作继续，以便单库迁移不会要求整个服务停用。
41. 作为管理员，我希望从任务中心查看检查和迁移的进度，以便大资料库耗时较长时仍能了解进展。
42. 作为管理员，我希望检查期间可以取消，以便选错目标后无需等整个检查结束。
43. 作为管理员，我希望关闭弹窗后仍可查看检查与迁移结果，以便不必一直停留在操作页面。
44. 作为管理员，我希望预览过期时系统要求重新检查，以便不会提交忽略新数据或新配置的旧计划。
45. 作为管理员，我希望重复点击确认不会执行两次迁移，以便网络重试或界面重复提交不破坏结果。
46. 作为管理员，我希望写入失败或进程中断后恢复一致状态，以便数据库与目录策略不会永久停在不同位置。
47. 作为管理员，我希望迁移后旧外部库比较与传输计划失效，以便后续传输不会写到原位置。
48. 作为阅读者，我希望迁移后重新取页使用新路径，以便缓存不会继续访问旧盘符。
49. 作为管理员，我希望迁移结果列出数量、异常、保护状态及后续操作，以便明确本次操作是否完成。
50. 作为管理员，我希望迁移完成后自行决定何时扫描，以便迁移不会自动启动额外磁盘工作。

## Implementation Decisions

1. **功能边界。** 本功能是资料库路径迁移，只改变根目录关联。以原根与目标根进行确定性映射，保持库内相对路径；不以文件名、大小或内容相似性推测身份，不复制、移动、删除或改写漫画文件。

2. **职责划分。** HTTP 层负责权限、载荷和响应转换；独立的迁移领域服务负责检查计划、重验、提交与恢复，避免把事务和路径规则堆进 handler。数据库层承担持久化与条件更新，配置层承担目录策略生效；现有任务领域、运行落盘和磁盘作业能力继续复用，不另建扫描器专属准入锁。

3. **身份与关联。** 原位更新资料库、系列和书的路径，保留全部 ID。不得删除旧记录再创建新记录。进度、书签、活动、阅读时长、用户系列状态、收藏、合集、阅读列表、关系、提案、字段锁与来源信息维持原关联。模型中的无关字段不因迁移被重置。

4. **原根选择与补迁移。** 正常迁移优先使用现有资料库根。若子记录不在该根下，可从已存路径提出候选，但必须展示并允许管理员明确指定。共同前缀不是历史证明，单系列和根目录散装书尤其不能静默推断。所有待迁移系列和书必须能由同一原根解释；混合新旧路径且无法完整映射的状态阻止，不做局部迁移。

5. **路径与阻断规则。** 输入以服务端原生绝对路径解释，按目录边界计算相对路径并验证不越出根。规范化处理符合运行平台的大小写与分隔符语义，拒绝映射歧义，不能用裸字符串前缀替换。目标根须存在、可访问且为目录。映射前后同一条原记录不算占用冲突；与其他记录、资料库根或策略产生的真实冲突须展示并阻止。已有嵌套资料库不能一律视为非法，必须判断具体映射与策略影响。

6. **系列目录与书文件检查。** 逐本检查书目标路径的文件信息与已记录大小，不解压、不全量计算内容指纹。缺失、不可读、目标不是普通书文件和大小不同以对应原因展示，不能声称大小一致就证明内容相同。系列可能是根目录散装书派生的虚拟系列，不要求每个系列路径都是实际目录。目标根无效与书文件异常的处理不可混为一谈。

7. **计划契约。** 检查返回可寻址的计划及对应运行，包含资料库、原根、目标根、系列与书数量、映射示例、策略变更、阻断项、异常汇总及可继续读取的明细。大资料库结果必须有界读取，不能把完整异常列表塞进每帧 SSE 或要求一次性渲染。确认请求只引用服务端计划，并表达是否接受该计划中的文件异常；客户端不能自行提交任意路径更新清单。

8. **计划重验与重复提交。** 确认后、正式修改前重新检查路径与配置版本、相关记录和目标占用、目标文件状态及冲突工作。影响用户确认结论的变化使计划过期，要求重新检查；不依赖固定时间窗口代替事实重验。并发提交同一计划只产生一个有效迁移结果，已消费计划不能覆盖后续迁移。检查和提交各自的运行能关联回同一计划，查看结果不会重新执行迁移。

9. **可接受异常与保护。** 有书文件异常时，管理员必须明确接受才可提交；确认后仍映射所有原记录。持久化资料库的保护状态、异常事实与恢复所需信息，关闭该库自动扫描、监听及失踪清理。保护同时覆盖逐本缺失删除和整系列缺失删除，不能只在 UI 或清理 HTTP 入口判断。普通编辑不能通过恢复扫描模式绕过保护。手动扫描与清理显示异常，受保护期间不得经任何失踪清理路径删除原记录。

10. **主动恢复。** 提供管理员可见的保护状态、异常详情与主动恢复操作。恢复时重新检查并展示尚存异常，明确说明解除保护后失踪清理可能删除对应记录及关联数据，由管理员明确确认。重新检查、重启、扫描完成或文件重新出现均不自动解除保护。原自动处理设置需要保留，以便管理员决定恢复；没有异常时保留原设置，但迁移成功本身不触发一次扫描。

11. **现有资料库编辑契约。** 有系列或书的资料库改变根路径须走迁移流程；前端引导与后端校验都要覆盖，直接调用普通编辑接口也不能绕过。路径未变的普通编辑维持现有行为，真正空资料库可以直接修改。更名、其他设置修改与路径迁移不应发生未确认的捆绑保存。

12. **统一访问协调。** 检查与提交明确识别本库、所属系列和覆盖本库的系统级工作，包括活动态和排队中运行、清理、封面、传输及尚可能使用旧路径的计划。发现冲突则列出并拒绝开始迁移，不自动取消用户任务。不可取消的清理必须等待结束，取消请求不是退出证明。

13. **提交独占与队列。** 获得独占访问和识别既有工作必须构成不可竞态的边界。独占期间约束新任务准入、排队放行、文件读取、目录监听派发、定时扫描、外部库会话与传输计划；在途访问须先安全退出，不能只更新数据库或移除监听。已排队闭包保有旧路径，不能在迁移后直接放行。协调遵守现有任务准入的单一归属，不把全库互斥误认为同任务身份去重。其他不冲突资料库继续运行。

14. **目录 IO 策略。** 原根及其子目录的显式策略按相同相对路径映射并纳入预览。目标已有不同策略时阻止，不静默覆盖；相同策略不能制造重复项。原根之外的祖先策略和无关配置保持原样。若迁入或迁出会改变其他资料库的策略语义，阻止并报告。配置更改经 config.Manager 与统一的持久化、生效边界完成。

15. **跨介质一致性。** 数据库事务之外还涉及配置文件和运行中配置，不能宣称两个独立原子写构成整体事务。实现必须保存足够的持久化操作状态以决定提交或补偿，并在启动阶段先恢复受影响操作，再开放对应资料库访问及后台调度。恢复无法完成时保持该库受阻并报告原因，不让半迁移状态继续工作；其他不冲突资料库不因此被不必要地停用。

16. **并发设置与故障处理。** 设置页保存、配置热重载、路径迁移及恢复需共享足以防止丢失更新的一致性边界，不能用旧配置快照覆盖并发修改。取消或提交前失败不改变原路径与策略；提交中的失败必须补偿或进入受阻的恢复流程。持久化状态应区分尚未提交、已提交待完成附属更新及可报告的最终结果，不能在路径已提交后假报“未修改”。

17. **持久化归属。** 计划、操作结果、异常保护和恢复信息由迁移领域的持久化边界管理，不以短期运行历史或纯内存缓存作为唯一依据。运行仍归现有 taskstore 管理，清理任务历史不能解除保护或丢失未完成恢复的依据。新增存储需支持现有数据库升级和幂等初始化，不重新定义已有任务与运行表的归属。

18. **任务与运行。** 检查和迁移展示在现有任务中心，具有清晰的资料库作用域、阶段、计数、发起方和结果引用。后台文件信息检查走运行句柄和磁盘作业，日志使用带 ctx 的接口。运行控制按运行标识寻址，不能新增按任务键控制的旁路；队列、终态、事件和推送沿用现有机制。

19. **取消、重试和恢复。** 检查可取消，确认提交前也不应修改原状态；正式提交不承诺即时取消，UI 必须显示实际控制能力。迁移提交不作为可无人确认自动续跑的普通任务；崩溃后的确定性恢复与“重新迁移一次”是不同操作。检查可重新发起，迁移重试必须重新满足计划与确认约束，不能凭旧根、新根或运行参数盲目重放。

20. **成功后的派生更新。** 成功提交后刷新资料库显示和读取路径缓存，重新配置监听；有异常保护则监听保持关闭。使依赖原路径的外部库比较会话与待用传输计划失效，要求重新比较；在途传输本来就应阻断迁移。已有内容指纹、库内相对路径指纹、封面缓存路径、自定义封面及锁定状态保持，不把漫画根替换进缓存路径。附属更新失败时保持必要的访问限制，恢复后再报告完整完成。

21. **权限和响应语义。** 发起检查、查询含主机路径的计划与结果、确认迁移和恢复保护均只允许管理员，并沿用会话与 CSRF 约束。响应能区分输入无效、计划过期、资源冲突、文件异常需确认、保护中、恢复中和持久化失败；任务中心与弹窗显示可操作原因。非管理员不能通过结果详情或任务载荷新增获取主机绝对路径的渠道。对外契约变化沿用项目既有类型生成方式。

22. **界面与文案。** 复用资料库入口、目录选择、模态交互与任务中心，提供原根候选说明、目标位置、映射示例、冲突工作、异常确认和恢复保护入口。关闭弹窗不取消已发起的后台运行，重新打开可查询结果。中英文文案遵循现有 i18n；不把文件大小检查描述为内容校验，不把“运行已发起”描述为“迁移已完成”。

23. **架构约束。** 遵守 ADR 0004 的任务与运行身份、ADR 0005 的后台磁盘工作和单一准入、ADR 0006 的任务领域与落盘分离，以及 ADR 0007、0008 的寻址和重启入参语义。ADR 0009 记录本次按根映射保留身份、异常保护与跨介质一致性的取舍。暂不进行全库相对路径存储重构。

## Testing Decisions

1. **已确认的主要测试入口。** 用户已确认以现有 Controller 的 HTTP 接口、真实 SQLite、临时资料库目录与配置文件作为主入口，覆盖检查、确认迁移、结果查询、重新读取和重启恢复。观察真实可见结果，不断言内部调用次数、锁结构、SQL 拼接或私有状态机实现。

2. **最少的补充边界。** 前端用用户交互测试覆盖入口、预览、确认、错误、进度与保护恢复；Scanner 使用已有清理测试入口证明底层失踪清理不能绕过保护。这两组补充分别覆盖 HTTP 后端集成不能证明的交互与旁路，不为每个内部 helper 增设测试接口。需要故障注入时放在主装配的外部依赖边界，不能用伪实现替换整个迁移流程。

3. **已有测试先例。** 复用 newTestController 的真实数据库与临时配置装配、现有 Controller 请求与落库断言方式；参照 TestRenamedBookKeepsIdentityAndProgress 的 ID 与多用户进度保持断言、TestCleanupAbortsWhenLibraryRootIsUnreachable 的清理无损断言。任务生命周期参照 newBackgroundTestEngine 的可控后台执行与对外快照，重启参照 restartController 以同一持久化存储构造新实例。配置行为参考 TestPersistConfigRebuildsDerivedResources；前端参考现有资料库表单和请求竞态的 Vitest、Testing Library 测试。

4. **正常迁移矩阵。** 使用原位置已消失而目标位置已就绪的目录夹具，覆盖嵌套书、同库多个系列、根目录散装书、中文和空格路径、原根尾分隔符及路径边界近似名称。断言所有 ID 和代表性关联完整保留，旧路径不再被读取；另一资料库和漫画文件字节不变。路径规则在支持的 Windows 与 Linux 环境均有覆盖，不能让 UNIX 专用夹具成为主要回归证据。

5. **补迁移与冲突。** 覆盖资料库根已更新但子记录仍持旧根、旧根不可达、候选有歧义需明确指定、混杂路径无法映射、目标系列或书已有记录、其他资料库记录占用、目标根非法、目标策略冲突。阻断后数据库、配置文件、运行中策略和双方原数据均保持原状态。

6. **异常接受与清理保护。** 分别构造缺失、不可读、非书文件和大小不同的目标；未接受不能提交，接受后所有原记录都映射且保护持久化。通过手动、自动、监听派生清理及直接 Scanner 清理入口，验证书删除与系列级联删除均被保护。重启、普通编辑和后续扫描不得自动解除保护；主动恢复显示现有异常并仅在明确确认后解除。无需依赖真实外接盘或管理员权限变化来制造不可读的偶发故障。

7. **并发与陈旧计划。** 用可控屏障而非固定 sleep 覆盖本库活动态和排队中任务、所属系列任务、覆盖本库的系统维护、不可取消清理、在途读取、外部库比较与传输计划。在检查后增加记录或修改配置、目标文件变化、两个确认同时到达、迁移与新任务同时发起时，断言拒绝陈旧计划或只提交一次；另一个不冲突资料库仍可正常使用。

8. **失败与崩溃恢复。** 在写数据库前、配置落盘与数据库提交之间、已提交但监听或缓存尚未完成等边界制造确定性失败，再用相同存储重新启动。只接受完整旧状态、完整新状态或明确受阻的恢复状态，不能对外开放混合状态。覆盖恢复重复执行、恢复失败后再次启动、设置页并发保存和配置热重载，验证无丢失更新和无旧闭包放行。此组必须运行真实持久化与生产恢复入口，不能只测 journal 序列化。

9. **结果、权限与用户交互。** 覆盖管理员发起、普通用户拒绝、CSRF、结果路径不泄露；检查取消和提交阶段的真实能力、关闭弹窗后查回结果、大异常列表的分批读取、计划过期重新检查、编辑引导和空库普通编辑。任务中心看到的阶段与终态必须与读取到的提交结果一致；迁移完成不能主动发起扫描。

10. **指纹、封面与失效。** 断言内容指纹、库内相对路径指纹、自动封面引用、自定义封面与锁保留；已有阅读路径缓存不继续命中旧源。迁移后旧比较会话和已经取得但未启动的传输计划都不能继续使用，重新比较才产生有效计划。

11. **实现阶段门禁。** 运行项目要求的 Go 测试、gofmt、golangci-lint、前端 lint、Vitest 和构建；并发测试在支持环境运行 race 检查。新增 schema 或生成契约时执行相应生成与漂移核对，更新用户可见变更说明并为 UI 留下截图证据。规格阶段仅核对文档结构、范围和仓库状态，不把未运行的实现验证记为通过。

## Out of Scope

- 复制、搬运、删除、重新编码漫画文件，或自动调整操作系统盘符。
- 内部目录重排、系列改名、书文件改名、按内容猜测跨目录身份及局部迁移。
- 对新旧重复系列或书进行合并、选择元数据优先级或合并两边阅读进度。
- 全量哈希或逐本解压校验、证明大小相同的文件内容一致。
- Windows 与 Linux 间的历史路径格式转换、网络挂载配置和任意符号链接别名的自动修复；目标使用当前服务端可访问的原生目录。
- 改造全库为相对路径存储、通用任务引擎重写，以及与迁移无关的扫描算法调整。
- 批量同时迁移多个资料库、无人确认自动迁移、提交操作自动续跑、另建一键历史回滚系统。
- 迁移后自动重扫、自动刮削或自动清理；管理员另行发起既有操作。
- 将服务的数据库、缓存和日志搬到另一位置，或替用户迁移整套部署环境。
- 在本次 to-spec 调用中生成实施工单或修改功能代码；后续由用户调用 to-tickets 拆分。

## Further Notes

- 领域术语以项目 CONTEXT 为准：资料库、系列、书、任务与运行各自有明确含义。这里的迁移恢复是维持一次操作的一致性，不等于同一个任务的自动重试。
- 用户已完成设计问答并确认整体设计，也已明确确认本规格采用的测试边界。书文件异常允许继续是刻意选择，不能在实现中改成一律阻止；目标根和记录冲突等阻断项仍不可绕过。
- 迁移保护按管理员明确恢复解除，不随运行历史裁剪。允许解除时仍有异常，界面必须说明之后可能发生的失踪清理后果，不将恢复按钮变成无提示的配置开关。
- 尚无生产迁移执行或现有用户数据库修复发生。本规格为后续拆票和实现提供验收依据，ready-for-agent 只表示规格完备，不表示功能完成。
- 前置设计问答保存在同目录 design-notes.md；本文件是后续拆票和验收的正式规格，发生差异以本文件及后续明确决策为准。实现不得将任何运行配置密钥或完整敏感配置写入公开的计划、结果、日志和测试输出。
