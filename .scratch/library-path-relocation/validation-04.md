# 04 验证记录

## 提交与恢复边界

`internal/relocation` 统一承载计划确认、重验、提交与恢复。`relocation_operations` 以唯一计划引用保存结果；消费计划、原位更新资料库/系列/书路径及进入 `paths_committed` 同属 SQLite 事务，不依赖运行历史。

配置事实由 `config.Manager.WithSnapshot` 在更新边界内读取，本票不写配置文件。确认时先取得相关资料库独占，重验原根、记录、目标文件、占用和目录策略；正式事务内再次核对同一组事实。检查逻辑与预览共用，不覆盖管理员确认过的原计划。

独占覆盖映射两端所涉及的其他资料库作用域；预览列出对应活动与排队运行。资料库根拓扑变更和作用域计算共享边界，迁移持有期间拒绝新建或普通编辑进入相关路径。互不冲突的资料库读取与运行继续使用现有准入。

提交前可取消；运行句柄在同一任务引擎控制边界内关闭取消能力后才开始正式写入。任务中心和弹窗读取实际运行标识、阶段与控制能力。失败文案要求查看持久化结果，不将附属更新失败描述成路径未修改。

路径提交后，缓存、外部比较会话/传输计划及监听更新完成才释放访问。启动装配先准备真实监听资源，再恢复未完成操作，随后才开启监听派发、自动续跑和后台服务；配置热重载也在恢复入口之后启动。监听注册失败仍保留 `paths_committed` 和资料库访问阻断，后续启动可幂等完成。提交运行没有普通重启函数。

## HTTP 与真实存储回归

`internal/api/relocation_commit_test.go` 经 Controller HTTP 入口、真实 SQLite 和临时 CBZ 覆盖：

- 原目录已消失、中文及空格路径、预热阅读缓存后的正常确认，原书 ID 从新位置返回相同页字节；真实旧外部比较会话和已准备传输计划失效。
- 检查后改变文件、记录、根、配置或目标占用，使确认结果过期且不修改原路径。
- 同一计划并发确认及重复请求返回同一持久操作；SQLite 拒绝更新时全部路径回滚。
- 提交前取消、排队取消后立即清理运行历史并重启，保留取消事实；正式提交后不能再取消。
- 附属更新失败保持访问受阻，经生产同源装配重启完成恢复；再次重启结果不重复迁移。
- 监听模式的目标离线使真实监听注册失败，恢复不误报完成；目标恢复后再次启动可完成。
- 跨库工作覆盖映射文件时，预览列出冲突；检查后才发起的相关工作阻止提交。效果阶段的可控屏障验证新建及空库编辑不能改变冲突根拓扑。
- 有记录的普通根编辑返回 `relocation_required` 且不捆绑更名或设置；真正空库仍可普通编辑。

`internal/api/relocation_preservation_test.go` 使用两个用户的独立进度与时长及非空关联夹具，对资料库、系列、书的非路径字段和代表关联表逐项前后比对。涵盖书签、活动、用户系列状态、作者/标签、关系、自定义字段、元数据来源、提案、收藏、合集、阅读列表、内容与相对路径指纹、自定义封面及锁。真实归档和封面字节不变，嵌套系列及不存在实体目录的虚拟系列保留身份。

权限、CSRF 与主机路径可见性复用既有鉴权链路；新增结果路由已纳入全部 GET 路由的非管理员主机路径回归。提交仅引用服务端计划，书文件异常、阻断或显式目录策略迁移在本票不允许确认，后续票继续扩展同一服务。
