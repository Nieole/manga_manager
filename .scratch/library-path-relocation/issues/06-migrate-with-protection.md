# 06: 允许带文件异常迁移并保护原记录

**What to build:** 检查发现书文件缺失、不可读、非普通书文件或大小不同后，管理员可明确接受异常并迁移全部原记录；自动处理关闭，持久化保护阻止任何失踪清理删除原记录。结果和资料库界面展示保护状态，重启后仍生效。

**Blocked by:** 04 — 完成正常资料库路径迁移。

**Status:** done

规格覆盖：用户故事 25—32、41、43、46、49、50；实施决策 6—10、15—19、21、22。

- [x] 在已有计划预览中按异常类别显示数量和可分批读取的书、目标路径、原因；大小一致不声称内容一致，目标根无效及记录冲突仍为不可绕过的阻断项。
- [x] 未明确接受该计划异常时拒绝提交；确认与重验绑定同一计划，目标状态变化不能用旧接受结果静默放行。
- [x] 接受后所有原系列与书均按根映射，包括异常书，保持 ID、进度和元数据。不能只迁移检查通过的书，也不能删除异常记录来完成操作。
- [x] 与路径提交一致地持久化资料库保护、异常事实和原自动处理设置；关闭自动扫描、监听和失踪清理。不能只靠 scan_mode、内存标记或运行历史维持保护。
- [x] 清理保护覆盖存活系列内的缺失书删除和缺失系列级联删除，手动 API、系统维护、自动或监听派生入口和直接 Scanner 清理均不能绕过；保护期间扫描也不得间接清理原记录。
- [x] 普通资料库编辑、设置变更、重启、文件重新出现、一次扫描结束和运行历史裁剪不会解除保护或恢复自动处理。受保护状态在调度与监听装配时先于工作生效。
- [x] 手动扫描和清理入口显示异常及保护原因；普通用户不能以直接请求解除限制。管理员能从资料库和任务结果查看状态，主动解除入口由 07 提供，不能用普通扫描模式编辑代替。
- [x] 路径、保护和结果在失败、进程中断或附属更新失败时保持父规格的一致性约束，恢复前维持访问限制，不报告虚假的迁移完成。
- [x] 主测试从 Controller HTTP 接受异常并读取真实记录与配置，再重启验证保护；补充现有 Scanner 清理入口测试，断言所有受保护书及系列关联仍在。
- [x] 各类异常用确定性临时目录或外部依赖边界制造，不依赖真实外接盘、网络故障或权限碰巧生效；覆盖明确接受、未接受、异常变化、直接清理、普通编辑绕过和重启。
- [x] 复用 04 的提交与协调流程，不另开不具备独占或恢复能力的“强制迁移”入口；迁移完成不主动扫描，正常无异常迁移回归保持。
- [x] 前端异常确认、关闭重开、保护提示及中英文文案齐全，完成适用的生成、前后端门禁与 UI 证据。

本票刻意允许异常迁移，不能改回“一律阻止”。解除保护归 07；目录策略尚未支持时继续阻断该分支，08 落地后沿用共同提交及恢复能力。

## Implementation evidence

明确接受绑定当前计划和完整事实重验，全部书与系列保持身份并映射；路径、持久保护、异常依据及原自动设置同事务写入。直接 Scanner 清理通过条件 SQL 删除守住并发边界，普通编辑、自动调度、监听和续跑无法恢复自动处理；后续干净迁移仍保留保护和首次原设置。

Controller HTTP、真实 SQLite、全新配置 Manager 与启动恢复回归覆盖异常类别、陈旧事实、关联保留、历史裁剪、清理入口、失败和重启。审查补齐系列自动扫描准入重验，并用确定性屏障修复预览轮询覆盖完成事实的竞态。与 08 集成后，保护写入与策略日志、prepared 恢复及界面确认共存；相关完整迁移 API race 通过。全部门禁及失败重试边界见 `../validation-06.md`，真实 UI 来源见 `../screenshots/README.md`。
