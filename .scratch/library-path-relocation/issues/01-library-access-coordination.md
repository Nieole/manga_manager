# 01: 统一资料库访问协调

**What to build:** 对现有资料库访问做行为保持的预重构，为迁移提供统一的独占与冲突观察入口。管理员以后检查或迁移时能够知道哪些工作仍持有资料库；进入独占后，旧路径工作不能混入，其他不冲突资料库继续使用。本票不开放迁移写入，也不新增独立任务引擎。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

规格覆盖：用户故事 37、38、39、40；实施决策 12、13、18、23。

- [ ] 既有扫描、清理、封面、系列级工作、覆盖资料库的系统级工作、定时与监听派发统一声明受影响资料库；保持任务领域对准入、排队和运行终态的唯一归属，不在 Scanner 再建一套同类准入。
- [ ] 独占申请与冲突检查没有先检查后插入工作的竞态；活动态和排队中的相关运行均可识别，并返回运行标识、资料库关联及可操作原因，不以任务键寻址。
- [ ] 已排队扫描持有旧资料库路径这一事实被覆盖：受阻期间不能放行旧闭包；本库取消中的运行、未退出的任务体仍视为冲突。
- [ ] 不自动取消用户工作；不可取消清理必须结束后才能取得独占，取消请求不能作为退出证明。
- [ ] 约束在途及新文件读取、监听排期、外部库比较、传输计划生成和传输启动；仅移除 watcher 或清除会话不算已独占。
- [ ] 外部库已经生成但尚未启动的计划能被迁移失效约束覆盖，不能在取得独占后绕过启动检查；不会提前取消或破坏现有有效会话。
- [ ] 暴露稳定的资料库访问占用与受阻语义供后续接口使用；未启用迁移独占时，现有 HTTP、阅读、协议和后台工作行为保持一致，不借机重写调度体系。
- [ ] 独占可在成功、失败和提交前取消时可靠释放；受阻请求得到可识别的暂时不可用结果，不假报文件丢失。其他资料库和不冲突的工作可继续。
- [ ] 使用已有 Controller、真实 SQLite 和可控后台执行，覆盖本库、系列、系统及跨库工作；用屏障验证独占与新任务、排队放行、读取、监听派发、传输启动之间的竞态，不依赖固定 sleep。
- [ ] 通过既有接口验证行为保持；不为每个内部锁或 helper 设置测试接口。保持 ADR 0004—0008 的身份、运行、准入和控制语义。

本票是明确的前置接缝整理，验收是现有调用已接入且可验证独占规则，不是创建一把尚无调用方的锁。遵循父规格的实现门禁；本票不搬运漫画文件、不修改资料库路径。
