# 04: 完成正常资料库路径迁移

**What to build:** 对原根明确、书文件检查正常且不需要迁移目录策略的资料库，管理员可从检查预览确认，完成一次保留身份的迁移并在任务中心查到结果，阅读使用新位置。已有记录的普通根路径编辑进入相同流程，不能再只修改资料库行。

**Blocked by:** 03 — 检查并预览资料库路径迁移。

**Status:** done

规格覆盖：用户故事 1、2、4、5、7、12—20、23、24、37—41、43—46、47、48、49、50；实施决策 1—3、5、7、8、11—13、15—23 中适用于不变更配置文件的部分。

- [x] 从 03 的服务端计划确认并发起迁移运行，前端显示实际阶段、可用控制和终态；检查与提交关联同一计划，关闭弹窗后可查回结果。
- [x] 正式写入前取得 01 的资料库独占并重新验证相关记录、根路径、目标文件状态、配置事实、目标占用及冲突工作。影响确认结论的变化要求重新检查，不能只依据固定有效期放行。
- [x] 迁移保持库内相对路径，原位更新资料库、系列、书，保留全部 ID、字段及关联；支持原目录已不可达、嵌套系列和根目录散装书，不移动、复制、删除或改写漫画文件。
- [x] 用真实数据库断言多用户进度、书签、阅读活动与时长、元数据、字段锁、来源、提案、收藏、合集、阅读列表及关系的代表性数据保留；封面引用、自定义封面锁、内容及相对路径指纹不变。
- [x] 只有没有书文件异常且无需迁移显式目录策略的计划可在本票提交。其余分支明确阻断，不能忽略异常或丢掉策略；后续票通过同一计划与提交服务扩展，不建立旁路。
- [x] 同一计划并发确认只产生一个有效提交，网络重试可识别既有结果；计划消费、路径更新和操作状态具有一致的持久化边界，旧计划不能覆盖后续迁移。
- [x] 提交前取消或失败保持原状态，正式提交不承诺即时取消。路径已提交但附属更新未完成时记录真实阶段并保持访问受阻，不能假报未修改或提前开放旧路径工作。
- [x] 启动时通过真实恢复入口处理未完成操作，再开放该资料库读取和调度；恢复幂等，无法完成则明确受阻。迁移提交不能作为普通任务凭旧入参自动续跑。
- [x] 更新资料库显示、阅读路径缓存和监听，旧外部库比较会话及已生成但未启动的传输计划失效；重新比较才能传输。其他资料库继续使用，不放行旧路径闭包。
- [x] 无异常时保留原自动处理配置；迁移完成本身不发起重扫、刮削或清理。
- [x] 普通编辑中已有系列或书的根路径变化引导迁移，后端直接调用也不能绕过；真正空资料库可普通编辑，路径未变的其他编辑保持。未确认的更名和设置不得捆绑提交。
- [x] 通过 HTTP 主入口验证正常迁移、真实新路径取页、冲突、陈旧计划、重复提交、取消、失败及重启；用可控屏障验证任务和读取竞态。覆盖 Windows 与 Linux 路径语义，不以 UNIX 专用夹具作为唯一证据。
- [x] 管理员权限、CSRF、任务结果路径可见性及中英文文案完整；运行标识用于控制，不新增按任务键寻址；结果包含数量、实际处理状态和后续操作。

本票是无配置文件变更的完整可用子集，不代表父规格其余分支已完成。目录策略跨介质一致性归 08，补迁移归 05，异常接受与保护归 06。遵循父规格全部适用门禁，包含 UI 截图、生成契约与用户可见变更说明。

## Implementation evidence

正常确认共用只读检查服务端事实；计划消费、三层路径原位更新及操作 `paths_committed` 在真实 SQLite 事务中一致落地。提交独占覆盖相关目录拓扑和跨库工作，前置取消与正式写入的控制边界明确；失败与恢复保留实际持久化阶段，监听未就绪时不开放资料库。普通有记录根编辑不能绕过迁移。

Controller HTTP、真实 CBZ/SQLite 与屏障回归覆盖正常确认、页图、陈旧事实、重复并发确认、取消、SQL 回滚、监听失败、多次启动恢复以及相关工作和新根的竞争。关联保护夹具逐项核对两用户进度/时长、25 张非空关联表、全部非路径字段和真实归档/封面字节。前端验证确认、关闭重开、目标编辑及普通编辑引导；三张真实联调截图证明确认后同一书 ID 可阅读目标文件。

完整结果见 `../validation-04.md` 与 `../screenshots/README.md`。最终普通 Go 全量、迁移与根编辑 race、gofmt、golangci-lint、tsgen 无漂移、前端 lint / 838 项测试 / build、文档风格均通过。宿主系统偶发阻止和既有文件替换波动均单独保留执行记录，未关闭智能应用控制。
