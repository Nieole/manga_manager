# 08: 随迁目录 IO 策略并保证失败恢复

**What to build:** 当资料库原根及子目录存在显式 IO 策略时，管理员能预览并确认策略随路径一起迁移；冲突时原状态不变。写入失败或服务中断后，数据库路径、配置文件、运行中策略与访问状态恢复一致，其他不冲突资料库仍可使用。

**Blocked by:** 02 — 统一配置保存与热重载的一致性边界；04 — 完成正常资料库路径迁移。

**Status:** done

规格覆盖：用户故事 11、34、35、36、40、44、45、46、49、50；实施决策 7、8、12—23 中涉及配置、提交和恢复的部分。

- [x] 复用现有检查与确认，展示原根及其子目录显式策略的新旧路径和实际变化；目录边界映射，祖先策略及无关设置保持不变。
- [x] 目标已有不同策略时阻止；相同策略不产生重复项；迁出或迁入会改变其他资料库策略语义时说明影响并拒绝，不能为方便而禁止所有嵌套资料库。
- [x] 确认计划覆盖原根、目标根、相关数据及配置事实，任何影响确认结论的变化要求重新检查；通过 02 的共同更新边界经 config.Manager 持久化和生效，不用陈旧配置覆盖并发设置或热重载。
- [x] 使用 04 的独占、路径提交、操作结果与恢复流程扩展策略迁移，不另建绕过冲突检查、异常保护或客户端计划约束的路径。无策略正常迁移仍工作。
- [x] 持久化足够的操作依据以判断完整旧状态、完整新状态或需恢复的受阻状态；数据库事务与配置文件原子替换不能被当成联合原子提交。
- [x] 覆盖配置落盘、数据库提交、Manager 生效及监听、缓存更新之间的失败顺序，实施可重入的补偿或完成恢复；失败和取消不能对外暴露混合路径与策略。
- [x] 启动时先恢复未完成操作，再开放受影响资料库读取、任务准入、排队放行和自动调度；恢复不能完成时明确受阻，其他不冲突资料库保持可用。
- [x] 区分路径尚未提交、已提交待附属更新及最终完成，任务中心和结果显示真实状态；不能在已提交后假报“原状态未变”，不能凭旧运行入参盲目再迁移一次。
- [x] 恢复信息不依赖短期运行历史或内存，历史裁剪不丢失恢复依据；恢复不把完整敏感配置写入公开计划、结果、日志或测试输出，保持配置权限。
- [x] 主测试通过 Controller HTTP、真实数据库、真实临时配置及生产启动恢复入口，覆盖每个持久化边界失败、进程中断后的新实例恢复、重复恢复、恢复失败后再启动与重复确认。不能仅测试操作记录的编解码。
- [x] 用可控屏障验证迁移与设置保存、文件热重载交错，无丢失更新、无旧路径闭包放行；验证另一资料库的策略效果、数据与可用性不变。
- [x] UI 完整呈现策略预览、阻断、进行中、待恢复和最终结果；与已落地的补迁移及异常保护分支共用操作状态与契约，不改变它们的身份保留和保护规则。
- [x] 完成父规格的适用生成、测试、lint、构建和 UI 证据；策略迁移本身不主动重扫，不变更不相关的部署目录或漫画文件。

本票不依赖 05、06、07，其核心是共同正常提交的跨介质扩展；已落地分支必须组合回归。尚未落地分支后续接入同一服务，不以新增旁路换取表面可用。

## Implementation evidence

显式策略通过共同确认入口随根映射；策略冲突与影响其他资料库行为的变化阻断。配置更新会话串行化 Save、Reload、持久化和运行中发布，私有策略日志依据 SQLite 决策补偿或前滚；启动先预约全部受影响资料库，再恢复和开放访问。零策略计划也校验实际磁盘策略事实，并保留恢复依据。

真实 Controller HTTP、SQLite 与配置回归覆盖配置替换、SQL、运行中应用和附属更新失败；子进程在实际持久化边界退出后由全新 Manager 和生产 Controller 入口重复恢复。屏障测试覆盖并发保存、热重载与外部编辑，界面联调核验策略预览、完成状态及实际配置路径。完整门禁、逐包重试限制和最终修复结果见 `../validation-08.md`；截图来源见 `../screenshots/README.md`。
