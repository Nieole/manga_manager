# 05: 补迁移已经修改过根路径的资料库

**What to build:** 管理员可修复“资料库已改为新根、系列与书仍在旧根”的状态，核对或明确指定原根后复用检查、确认和迁移流程，保留原记录与关联。原硬盘位置无需可访问。

**Blocked by:** 04 — 完成正常资料库路径迁移。

**Status:** done

规格覆盖：用户故事 7、8、9、10、12、14、21、22、44、49；实施决策 3—8、20、22。

- [x] 当系列与书不能用资料库当前根解释时，UI 展示补迁移提示，允许核对原根候选或明确输入原根；确认预览同时显示资料库当前根、用于映射的原根和目标根。
- [x] 候选仅作提示，不把共同前缀当可靠历史；单系列、深层系列、系列等于根、虚拟系列和根目录散装书不会被无提示地套用错误原根。
- [x] 无需访问原根即可从数据库验证完整映射，原盘符消失不阻止；所有原系列与书必须可由同一原根解释，目录越界和混杂新旧路径无法完整解释时展示具体阻断项。
- [x] 资料库当前根与目标根已相同，但子记录仍需迁移时，不能当作“无需操作”；映射到本记录自身的路径不被误判成与其他记录冲突。
- [x] 正式确认与 04 共用计划重验、独占、事务、恢复、权限、结果和缓存失效，不额外提供直接替换数据库路径的接口。
- [x] 无法确定原根、目标已有记录或相关工作冲突时保留所有原数据，不做局部迁移、不自动合并、不靠扫描猜测身份。
- [x] 提交后 ID、多用户进度、系列元数据及其他关联保留，正常读取改用目标路径；不主动重新扫描。
- [x] 通过 Controller HTTP 与真实数据库覆盖先只改根再补迁移、原根不存在、单系列歧义、明确原根、根目录散装书、混合记录和重复确认。断言阻断时路径与配置不变、成功时关联完整。
- [x] 前端交互验证候选说明、原根输入、预览和错误重查；保持 04 的正常迁移回归，通过父规格的适用门禁并更新 UI 证据。

本票扩展的是原根确定方式，不降低文件检查、策略变更或异常保护约束。06、08 尚未落地的分支继续按 04 的能力边界阻断；落地后共用服务自然组合，不增加对应依赖。

## Implementation evidence

管理员明确指定用于映射的原根，候选只作提示；当前根已等于目标时仍迁移旧子记录，复用正常迁移的检查、独占、提交与恢复流程。混合根、越界和冲突保留全部数据，原位置不可访问不妨碍数据库映射验证。

Controller HTTP 与真实数据库回归覆盖补迁移、不可访问原根、歧义候选、散装书、虚拟系列、混合路径、重复确认及全部已填充关联夹具；实际联调核验明确选择、三根预览、完成结果及原书 ID 读取目标页图。完整验证、宿主系统拦截后的逐包重试边界与 UI 来源见 `../validation-05.md` 和 `../screenshots/README.md`。
