# 07: 查看异常并主动恢复自动处理

**What to build:** 受迁移保护的资料库具有完整的管理员恢复流程：查看当前异常、重新检查、了解解除后的清理后果、明确确认，再解除保护并选择恢复自动处理。恢复本身不重新执行迁移，也不把普通编辑作为解除旁路。

**Blocked by:** 06 — 允许带文件异常迁移并保护原记录。

**Status:** ready-for-agent

规格覆盖：用户故事 26、29、30、31、32、33、41、43、44、46、49、50；实施决策 8—11、17—19、21、22。

- [ ] 管理员从资料库保护状态进入恢复流程，查看保留的原自动处理设置及当前异常；明细采用与检查一致的有界读取方式，关闭重开仍可继续查询。
- [ ] 恢复前发起只读重新检查，通过现有任务中心展示进度、结果与取消能力；检查完成或文件全部恢复均不会自动解除保护。
- [ ] 如果仍有异常，展示失踪清理可能删除相应记录和关联数据的后果，允许管理员明确确认后解除；不能将用户已经选择的主动裁决改成必须无异常才能恢复。
- [ ] 确认基于当前检查，异常或相关资料库状态变化使确认失效；未确认、普通编辑、直接清理请求均不能解除保护。
- [ ] 解除保护和自动处理设置更新具有一致的持久化边界，管理员能依据原设置选择恢复；恢复前先满足相关工作与访问协调，失败时不暴露半解除状态。
- [ ] 恢复动作不修改已迁移路径、不重新创建系列或书、不直接删除异常记录，也不主动发起一次扫描或清理。后续原定自动处理按管理员恢复的设置运行。
- [ ] 重复确认、取消检查、恢复写入失败与重启均可识别真实结果；运行历史裁剪不影响保护，未完成恢复不得被当作已解除。
- [ ] 主测试通过 Controller HTTP、真实 SQLite、临时配置和重启覆盖无异常恢复、有剩余异常明确接受、拒绝确认、陈旧结果、重复提交及失败；恢复前直接 Scanner 清理仍受保护。
- [ ] 前端覆盖保护状态、重查、风险确认、设置选择、取消和错误反馈；普通用户无恢复能力且不新增主机路径泄露，中英文文案和任务控制语义完整。
- [ ] 通过父规格适用门禁，保持正常迁移与带异常迁移的回归，并提供 UI 证据及用户可见变更说明。

恢复由管理员承担明确决策，系统只保证正确呈现事实和执行确认。此票不新增自动异常修复、记录合并或一键历史回滚。
