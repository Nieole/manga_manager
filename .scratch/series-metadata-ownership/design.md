# 系列元数据规则归属：设计结论

状态：grill 已收敛，用户已确认 Q1–Q8。

本文件记录 grill 的设计结论，不是工单或实现完成记录。正式规格见 [spec.md](spec.md)，状态为 ready-for-agent；后续业务契约与验收要求以规格为准，当前没有实现代码变更。

## 总体方向与首期目标

按业务能力形成有完整规则拥有权的 module，逐步收缩 `internal/api.Controller` 的职责。首期选择系列元数据，覆盖人工编辑、批量编辑、扫描和提案四条路径；前端工作流复用留到后续。

共同拥有权指系列元数据规则的归属，不意味着所有相关表只能有一个物理写入者，也不意味着所有流程共享一个事务入口。目标是增加 depth：调用方通过表达来源意图的 interface 使用规则，不再逐字段重建相同知识。

## 包含与排除

包含上述字段并集，不要求四条路径支持相同字段集。来源记录只保留已有写入行为，不为人工、批量或扫描新增沿革。

范围外：系列与书的身份、路径迁移、封面、阅读进度与活动、系列关系、合集、自定义字段、全局标签改名/合并/删除、前端业务状态。搜索索引与关联计数的既有数据库触发器继续归持久化实现。

全局标签维护会改变多个系列的标签集合与元数据内容指纹，是明确保留的另一类动作；不能宣称所有标签变化都只能经过新 module。

## 规则与流程的职责

- 新 module：各来源的标量空值处理、字段锁判据、集合替换或追加、作者与链接写入、标题与首字母联动、既有来源记录、首建元数据默认值。
- 人工编辑流程：请求与响应翻译，以及版本校验、元数据提交和统计刷新的原有事务关系。版本规则可内聚，但不能移出该事务。
- 批量编辑流程：全选区的事务编排、原有提交后刷新与失败记录。
- 扫描流程：归档发现、系列身份建立、书入库、批次事务、扫描缓存、派生数据节流刷新。
- 提案流程：入队与去重、字段选择、fill_empty 裁决、部分应用、拒绝与关单 CAS；内容、来源记录与提案状态的原有原子关系保留。
- metadata：继续负责外部来源与 AI；不因本次变更引入数据库写入职责。

## 四路径兼容清单

下表是源码走读得到的现状约束，后续 spec 应以现有实现和行为测试核实。描述现状不代表认可所有行为合理。

| 路径 | 字段与集合语义 | 锁与来源记录 | 事务与派生刷新 |
| --- | --- | --- | --- |
| 人工编辑 | 标量按现有空值语义保存；tags/authors/links 为 nil 时不改，为非 nil 时替换，空集合清空。 | 人工可编辑被锁字段与锁本身；不新增 provenance。 | 版本校验、字段与关联写入、RefreshSeriesStats 同事务。 |
| 批量编辑 | 只支持已有 status、publisher 与标签增删；指针 nil 不改；先加标签后删标签。保留缺失 ID 容忍、重复 ID 与空值行为。 | 保留当前不检查字段锁、不记录 provenance 的差异。 | 全选区一事务；SQL 分块不拆事务；提交后逐系列尽力刷新，刷新失败记录告警而非撤销成功。 |
| 扫描 | 首建标题来自目录名、默认锁定 title；已有标题按原规则保留或兜底。ComicInfo 标量及 tags/authors 的追加行为保持。 | 保留原缓存锁集与集合字段处理；不增加来源记录，不顺手修正集合锁差异。 | 元数据与身份/书记录参与原有批次事务；派生数据按现有节流与收尾刷新，不改成逐书全量刷新。 |
| 提案 | 标量非空覆盖；参与本次写入的 tags/authors 整体替换；保留状态归一、去重和部分应用。语言与锁按当前行为保留。 | 保留裁决与写入处的锁规则、已有 provenance 和 Bangumi 来源链接追加。 | 元数据、来源、字段删除或关单 CAS 与 stats 保持原有事务关系。 |

补充约束：

- 保留人工编辑的内容指纹，不改成自增版本；缺席、空版本的不同请求语义保留。
- 保留现有快照加载与扫描缓存更新时机，不能借内聚规则重新读取最新行而改变覆盖行为。
- 扫描首建失败跳过、已有系列部分更新及关联错误的当前容错方式，不能统一改成整批失败。
- 不扩大字段锁效力，不把提案整体替换改成追加，不把扫描追加改成整体替换。
- 保留 name_initial 与实际标题的联动；FTS/gram 及标签计数继续由既有触发器维护。
- 不新增统一 dashboard cache 失效、用户进度重算或持久化事件机制；各路径原有刷新效果和失败处理保持。

## interface 方向与被放弃的形状

采用来源明确的 interface，让人工编辑、批量编辑、扫描与已裁决提案表达真实意图；不公开可任意组合的“忽略锁、集合模式、记录来源、刷新模式”等策略开关。

没有选择“少数通用入口”：方法数虽少，调用方仍要掌握多种请求和扫描 continuation，不能据方法数量宣称 interface 更小。

没有选择公开的“变更集生成后再提交”：目前没有延期提交或公开执行计划需求，额外生命周期会增加调用方知识。implementation 内部是否使用受控变更集属于实现选择。

扫描保留一个必要的 seam：新 module 准备范围内元数据，扫描在原有 upsert 与事务中结合身份、路径和计数。不能先建空系列再单独补元数据，也不能把身份管理交给元数据 module。

不在 grill 中冻结 Go 方法名、参数定义或包名；后续 `to-spec` 应把这些转成可检查的契约，不能改动已确认的规则和事务归属。

## 依赖方向与批量编辑迁移

预期依赖方向：调用流程（api、scanner、proposal）→ 系列元数据 module → 持久化能力。database 不反向依赖新 module。

现有 database.SqlStore.BulkEditSeries 同时包含业务规则与事务编排，不能让它反向调用依赖 database 类型的新 module。将高层编排迁到调用流程，database 保留具体批量存储原语；整批事务、SQL 分块、集合操作顺序和提交后刷新语义保持。

禁止将批量更新退化为逐系列读取和整行写回。不得用运行时类型断言把 proposal.Queries 强转为具体数据库对象；后续 spec 需明确事务写入能力如何通过现有 adapter 交入。

SQLite 属于 local-substitutable 依赖。优先通过真实临时 SQLite 与事务验证 interface，不为结构整齐增加假想 adapter 或复制整套存储模型。

## 验证与完成判据

1. 四条来源的字段规则集中于同一 module，调用方不再持有被替代的规则副本。
2. interface 测试覆盖各来源的 nil/空值、锁、集合、链接、来源记录、初值与错误结果；通过提交后的可观察事实断言。
3. 保留人工版本冲突与回滚、提案 CAS 与回滚、扫描批事务与节流、批量全选区原子性与大选区行为的跨流程测试。
4. 新的 interface 测试替代重复规则测试；仍有跨流程约束价值的测试继续保留，不机械叠加或删除。
5. module 不依赖 Controller；业务编排不反向进入 database；没有永久双实现。
6. HTTP 响应、数据库内容、失败分类及既有事务/刷新语义保持；未获得独立授权不修复旁支缺陷。

验证入口包括 TestUpdateSeriesInfoConcurrentEditConflict、提案集合替换与锁定测试、扫描人工字段保留测试，以及 TestBulkOperationsExceedVariableLimit。实施门禁遵循 AGENTS.md；本次只有设计与词汇文档，没有执行代码测试。

## 待独立核实的行为线索

扫描集合字段锁、扫描空标量处理及忽略部分写入错误、提案部分应用的并发窗口、不同入口缓存失效差异，均作为独立线索保留。它们不是本次已授权修复项，也不是静态走读已经复现的缺陷。
