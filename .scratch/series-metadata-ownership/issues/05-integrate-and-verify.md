# 05: 完成跨来源兼容验收与旧通路退出

**What to build:** 四种来源均接入后，维护者能够从一个 module 审查系列元数据规则，并确认管理员通过不同入口连续修改同一系列时，内容、版本、事务、派生结果及范围外动作仍兼容。完成旧规则退出与完整门禁，给出规格覆盖和验证结果，不把工单完成数量当作实现完成证明。

**Blocked by:** 02 — 提案应用接入共同规则；03 — 批量编辑接入共同规则；04 — 扫描初值与更新接入共同规则。

**Status:** ready-for-agent

**规格覆盖：** US 1–8、14、28、50–68；整体验收同时核对 US 1–68，无遗漏。

- [ ] 在已经集成的四条真实来源上核对整个规格，不以单个 module 测试通过代替调用流程验证，不以几张票完成推导规格全部完成。
- [ ] 验证人工、批量、扫描和提案按既有语义连续修改同一系列后的最终字段、集合与沿革；场景至少区分人工替换、批量增量、扫描追加和提案整体替换。
- [ ] 验证各来源的实际内容变化仍影响人工编辑内容指纹，单纯集合存储顺序变化不产生错误冲突；不把现有快照和并发语义改成新的统一策略。
- [ ] 验证范围外的全局标签改名、合并和删除仍有效，能按原行为改变相关系列及其内容指纹；不得因新 module 宣称独占表写入而阻断这些动作。
- [ ] 验证现有搜索触发器、标签计数、首字母、各路径统计与缓存刷新保持原有行为；不引入新的全局失效或用户聚合重算策略。
- [ ] 验证资料库/系列/书身份、路径、封面、阅读记录、关系和自定义字段未被重构意外改变；保留资料库迁移保护、运行准入及既有 ADR 约束。
- [ ] 检查四来源调用方均已退出被替代的字段规则，旧批量高层入口已删除，没有永久双 writer、兼容开关或未接入的平行 implementation；遗漏清理必须在本票完成。
- [ ] 新 module 不依赖 Controller、全局 Store、配置或任务生命周期；数据库不反向依赖业务 module；提案生命周期和扫描身份管理仍归原流程。
- [ ] 事务能力在编译期交接，不存在运行时强转、为了测试复制存储模型或任意原始 SQL 入口；检查来源明确的 interface 没有退化为任意策略标志组合。
- [ ] 审查测试替换：删除仅复述已迁入规则且失去独立价值的测试，保留人工并发/回滚、提案 CAS、扫描批次/节流/取消和批量规模/刷新容错的高层保护。
- [ ] 不建设通用架构检查框架；只有编译器无法表达且存在实际绕过风险时，才采用小范围结构守卫。现有提案查询归属守卫仍有效。
- [ ] 运行完整后端测试、gofmt 检查和 golangci-lint；必要生成物完成漂移检查。门禁失败必须解决或明确报告真实阻塞，不以设计/工单状态代替验证证据。
- [ ] 仅更新与最终实现有关的当前职责文档，遵守仓库文档归属规则；不重写前端工作流、不修改外部请求响应或数据库格式。
- [ ] 核对规格全部 68 条用户故事并给出可追踪的覆盖和验证记录；记录规则 locality、调用方 interface 与旧通路退出的实际结果，代码行数仅作为描述，不承诺比例。
- [ ] 将本期发现的疑似既有缺陷与已验证实现结果分开记录；未得到独立授权不修复扫描锁、空值、容错或提案部分应用并发等旁支问题。
- [ ] 交付说明明确列出实际通过的检查、未验证的限制及未完成事项；只有验收实际完成才报告本期实现完成，不声称整个项目架构重构已完成。

01 已由三个直接前置传递保证，因此不重复列阻塞边。本票不是推迟各来源必要测试与旧规则删除的理由；02、03、04 必须先各自完整交付。
