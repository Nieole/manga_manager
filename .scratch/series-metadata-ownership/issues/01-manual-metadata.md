# 01: 人工编辑接入系列元数据 module

**What to build:** 管理员通过现有人工编辑入口保存系列时，由独立的系列元数据 module 处理本期字段规则；请求、响应、内容版本保护和回滚结果保持原样。以这条完整流程建立后续来源可扩展的 interface 和事务能力交接，删除对应旧规则，不先建设没有真实调用方的通用框架。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**规格覆盖：** US 1–7、9–18、50、54–55、57–59、61–62、64–65、67–68。

- [ ] 建立独立的系列元数据 module，采用人工来源明确的入口；metadata 继续负责外部获取与 AI，proposal 继续负责提案，module 不持有 Controller、不管理后台运行或配置。
- [ ] 人工保存从现有 HTTP 入口实际接入 module，不是仅增加尚未使用的写入实现；HTTP 仍只解析、调用与翻译结果。
- [ ] module 接受本流程所需的事务绑定窄查询能力，不自行开始、提交或回滚事务，不接收全局 Store，不提供任意原始 SQL 执行能力。
- [ ] 只建立这条流程实际需要的事务能力；契约允许后续来源按真实需要扩展，不提前实现万能 patch、来源注册或公开变更集。
- [ ] 标题、简介、出版社、状态、评分、语言、字段锁，以及标签、作者和链接的现有人工编辑语义保持；不扩大到封面、路径、身份、阅读记录、关系或自定义字段。
- [ ] 集合 nil 不改、非 nil 替换、空集合清空；标量空值及非正评分保持现有 NULL 行为；保留当前空白过滤和实际落库值，不套用提案或扫描的规范化策略。
- [ ] 人工仍可修改被锁字段及锁本身，不新增来源记录，标题与首字母联动保持。
- [ ] 统一元数据内容指纹的既有算法与加载能力，避免调用方复制版本规则；保留指纹字段范围、集合归一、原始响应值及原有快照读取时机。
- [ ] 省略版本继续兼容既有客户端，空版本仍拒绝，版本过期仍返回原有冲突分类与当前版本；版本读取比较和写入处于同一事务。
- [ ] 字段、标签、作者或链接写入失败仍使人工保存整体回滚；系列统计刷新与内容写入保持原有同事务关系。
- [ ] 通过 module 的正式 interface、真实临时 SQLite 与事务断言字段、关联、版本和回滚结果，不依赖私有 helper 或内部布局。
- [ ] 保留人工入口的请求兼容、并发版本竞争、关联写入失败回滚和响应测试；可沿用 TestUpdateSeriesInfoConcurrentEditConflict 及系列元数据原子性测试。
- [ ] 删除人工入口中被替代的逐字段规则、重复版本实现及失去价值的规则测试；保留仍验证 HTTP 与事务接线的高层测试。
- [ ] 其余三条来源可暂时保留原实现，既有流程仍可验证通过；不要求提前迁移，不修改现有外部契约或数据库格式。
- [ ] 相关测试及仓库后端门禁通过；如调整生成查询，按仓库要求生成并验证产物。交付说明区分实际通过的检查与尚未执行的检查，不声称首期必须净减代码行数。

本票是首个真实来源的贯通，不是整个规格完成。保持所有既有行为；旁支疑点单独记录，不借迁移修复。
