# 18: 手动、定时与监听扫描清理

**What to build:** 三个输入接入完整扫描用例，等待真实运行再清理，保持改名重连、统一准入和扫描后统计预热与推送。

**Blocked by:** 17: 应用运行入口与历史保留清理

**Status:** ready-for-agent

**验收基准：** [父规格](../spec.md)。本票遵守其中的跨功能约束和范围，不将历史实现偏差重新定义成业务规则。

**规格覆盖：** US 90、US 91、US 93、US 94、US 95、US 99、US 100、US 104、US 106。

- [ ] 手动资料库或系列扫描、定时扫描、监听派生扫描与清理实际调用应用编排的完整用例，输入不再复制发起规则。
- [ ] 继续通过 17 的同一任务引擎准入，保留强制属性、作用域、发起方、重启入参、声明标签和合并语义。
- [ ] 监听必须等待真实运行完成后再允许清理；排队、合并或停发的结果不能当作扫描成功，失败和取消不触发危险清理。
- [ ] 改名重连先于失踪清理，保留书身份及阅读、书签与合集关联；受保护资料库的自动处理和所有清理限制仍有效。
- [ ] 扫描观察者和运行句柄继续归属正确运行，任务体日志带上下文，不从全局任务键反查运行。
- [ ] 扫描批事件保留统计失效、完成时必要预热与原语义推送；迁移回调不能覆盖其中一部分。
- [ ] 迁移所需监听协作归属时保留监听资源装配的兼容方式，不提前改变进程启动恢复和关闭顺序。
- [ ] 用应用 seam、真实 SQLite 和既有监听集成先例覆盖排队、合并、停发、失败、改名后清理与保护；完成相关门禁并移除本票旧发起配方。
