# 17: 应用运行入口与历史保留清理

**What to build:** 以历史保留清理跑通应用侧运行发起、上下文及观测；原发起方式兼容接入同一个任务引擎，为后续逐批迁移提供入口。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**验收基准：** [父规格](../spec.md)。本票遵守其中的跨功能约束和范围，不将历史实现偏差重新定义成业务规则。

**规格覆盖：** US 1、US 4、US 5、US 7、US 9、US 90、US 91、US 93、US 94、US 95、US 106、US 107、US 109。

- [ ] 以运行历史保留清理这条完整用例建立应用侧运行发起与装配入口，实际从定时发起到保留裁剪、运行观测和收尾验证。
- [ ] 沿用同一任务领域引擎、存储、槽位和资料库访问协调；旧发起入口通过兼容方式接入，不产生第二个准入守卫或状态事实源。
- [ ] 保持任务与运行身份、任务键仅供日志、运行句柄、上下文日志、暂停取消和排队合并等既有领域分工。
- [ ] 重启能力与可重试、可续跑判定仍来自装配期完整注册的单一事实源；本票不为实现兼容而改成首次发起时懒登记。
- [ ] 应用入口不反向依赖请求处理或 HTTP 快照类型；传输转换留给 adapter，旧调用方可逐批迁移且保持可编译。
- [ ] 只迁历史清理所需完整行为和共同运行接入，给遗留功能保留明确可移除的兼容方式，不先造任意流程框架。
- [ ] 测试实际历史清理发起、存活运行不被裁剪、上下文观测、重试能力与共享准入，规则测试可通过应用 seam 验证。
- [ ] 保持 CI 可通过，完成相关后端与生成物检查，记录过渡职责及需由后续票移除的兼容入口。
