## Comments

### 2026-10-25 实施与验证

- `application/relocating.Service` 以完整预检、确认、显式恢复与启动恢复入口组合迁移领域、同一 `application.Runs`/任务引擎、拓扑排他、资料库覆盖与派生状态。API 只保留输入解析、授权既有入口、状态码和隐私文案转换。
- 请求侧 `relocation_access.go` 的拓扑状态、目录相交覆盖与排他获取已移除；建库/改库经应用 `GuardRoot` 参与同一拓扑边界。`relocation` 仍持有确定映射、持久计划/事实、数据库路径事务、配置政策日志、补偿和恢复规则，仅新增流式覆盖读取以避免在输入 adapter 知道持久表结构，也不物化整库路径清单。
- 应用完成效果统一执行阅读路径缓存清除、统计失效、外部会话失效与监听切换；监听失败时领域持久状态保持未完成并保留访问排他。显式恢复也完成缓存和外部会话失效后才清保护；管理员确认与接受丢失风险仍交原领域规则验证，没有自动代替确认。
- 生命周期装配保留原顺序：创建监听资源后装配应用能力，先中断旧预检并恢复迁移一致性，再开放后台与请求。监听资源获取是叶子依赖，测试/启动恢复可替换既有资源，不把效果配方放回 API callback。
- TDD 从应用预检入口尚未实现的失败开始。真实 SQLite/配置文件应用用例通过：路径及书/系列身份和进度保留、相交库排他且无关库仍可读取、源目标根禁止更改、监听失败后新引擎/新服务启动恢复、配置文件写失败补偿、运行配置发布失败持续保护、显式恢复确认。
- 已有 API 迁移/恢复/保护/配置崩溃边界/相交目录/缓存及隐私回归整体通过（41.81 秒）。预检读取故障夹具在换入新 reader 后显式重装应用能力，保持不等待引擎 writer 锁的既有断言。
- 当前全量 lint 为 `0 issues.`；格式与 diff 检查通过。首次生成契约检查因系统 Application Control 拦截 `tsgen.exe`，未改路径或绕过；未改 SQL 来源或对外响应结构。最终门禁与集成合并后的结果随后记录。
