# 02: 统一离线批量与逐本补传

**What to build:** 两种传输走同一规则，保留发生时间和原活动日期，前端队列重试保持事实身份与用户归属。

**Blocked by:** 01: 在线阅读位置的完整用例

**Status:** ready-for-agent

**验收基准：** [父规格](../spec.md)。本票遵守其中的跨功能约束和范围，不将历史实现偏差重新定义成业务规则。

**规格覆盖：** US 16、US 17、US 20、US 21、US 35、US 37、US 38、US 39、US 40、US 86。

- [ ] 离线批量同步与逐本回退均实际调用已建立的位置规则；前端可继续使用现有批量优先、必要时逐本回退的传输方式。
- [ ] 两种传输保留相同发生时间、新旧胜负和同页语义；验证较旧 A 先回退补传后，真实较新 B 不会被 A 的接收时间错误挡住。
- [ ] 队列保留可识别事实身份或等价发生时间；请求在途时新的队列项不会被旧响应删除或改写，身份切换仍遵守离线 owner 规则。
- [ ] 保留逐项处理、输入顺序、逐项结果及缺失书和非法项的既有容错；单项失败不会让其他独立项失去结果。
- [ ] 有效补传活动按可证明的原阅读日期归属；重复传输不改为联网日期，被拒旧的位置不更新最近阅读，也不据此补造额外历史活动。
- [ ] 本地日历和时间归一化一致；没有完整轨迹的队列不能凭最后位置补出多日活动，已有历史统计不猜测重算。
- [ ] 用同一真实 SQLite 行为矩阵对比批量和回退的页码、最近阅读时间、活动日期与重复结果；前端覆盖批量不可用、回退失败、晚响应及账户切换。
- [ ] 移除两条输入中被替代的规则副本，保留协议和队列兼容；完成对应后端、前端及生成物门禁。
