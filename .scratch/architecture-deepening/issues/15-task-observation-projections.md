# 15: 任务实况、历史与气泡投影

**What to build:** 消费者接入统一会话，保留投递链补拉、轮询、终态气泡及后端实况权威，移除对应旧全局事件依赖。

**Blocked by:** 14: 应用会话连接与普通刷新

**Status:** done

**验收基准：** [父规格](../spec.md)。本票遵守其中的跨功能约束和范围，不将历史实现偏差重新定义成业务规则。

**规格覆盖：** US 73、US 74、US 79、US 80、US 81、US 82、US 85、US 89。

- [x] 任务实况、任务历史和气泡从 14 的应用会话消费运行消息，各自持有自己的功能投影，不把全部页面数据塞进会话对象。
- [x] 按投递链前序关系判断缺口，保留重连与漏帧后的补拉；正常节流的序号空档不能误判为丢帧。
- [x] 全局槽位等实况汇总仍采用后端事实，不从局部运行快照列表重算；历史筛选和展开行为保持。
- [x] 保留必要轮询、任务与运行身份区分、控制动作、终态气泡延时移除及管理员权限。
- [x] 挂载、离开页面、切换身份与多消费者订阅不造成重复控制、重复请求或旧角色数据残留。
- [x] 移除本票消费者对旧 DOM 自定义事件的直接依赖；兼容桥只服务尚未迁移消费者，不能复制两套投递链规则。
- [x] 通过会话和消费者行为测试验证完整缺口恢复、重连、历史与气泡结果，保留任务页面及普通用户拒绝回归。
- [x] 删除被替代投影与恢复副本，完成前端测试、构建和适用 lint，保持传输契约兼容。

## 实施与验证

- `web/src/features/task-observation/useTaskObservation.ts` 接管实况、任务清单、展开历史与详情查询、控制操作及恢复投影；页面保留筛选草稿与提交条件。`useTaskBubbles` 自行订阅会话、管理终态定时器并补拉漏掉的终态。
- 应用会话唯一持有投递链水位。`useSessionRecovery` 在前序不相接或连接恢复时通知功能补拉；重连重置旧水位，正常节流跳号不触发误补拉。任务中心同时补拉实况、带原筛选的清单及当前展开历史；气泡只补拉已显示任务。
- 删除 `run-push` DOM 桥、气泡 override 事件依赖和导航对气泡的手动喂帧。`run-snapshot` 单向桥仅留给后续外部传输消费者。会话不持有任务结果，实况汇总继续使用后端事实。
- 作用域退出使在途查询失效；旧控制请求结束后不会继续请求、发出成功提示或更新新身份的投影。原有 60 秒轮询、任务重试与运行控制身份、终态气泡延时及页面筛选保持。
- TDD：通过会话投递的缺口恢复测试、气泡订阅和丢失终态恢复测试，以及卸载后控制请求收尾隔离测试，均先观察失败后实现通过。新增消费者测试通过真实 apiClient adapter 驱动网络输入，检查完整投影结果。
- 同步集成 `c0c9322` 后，`npm run test`：85 文件、876 用例通过，含任务页面按需搜索/过期查询、管理员路由和普通用户拒绝、会话身份切换、重连、漏帧与气泡回归；`npm run build`、`npm run lint`、提交差异检查通过。
- 本票未更改后端传输契约；票 14 的后端 CGO 门禁仍被系统 Application Control 策略阻断，本票完成不表示该门禁通过。
