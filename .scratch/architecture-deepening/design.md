# 全项目架构深化设计

阶段：已进入实施验收。需求与测试决定以 [规格](spec.md) 为准，实际交付及验证见 [集成记录](implementation.md) 与 [联合验收](acceptance.md)。
本文保留批准的架构取舍依据，不作为另一份独立验收标准。

## 目标与范围

四个方向共同推进：后台应用编排、阅读状态、前端应用会话与数据一致性、藏书编排。
以重复规则减少、修改知识集中、调用方需要了解的细节减少、完整功能可测试为主要目标，净删行数仅是辅助信号。

保留现有部署方式与 SQLite、sqlc，按功能形成 deep module。现有 `task`、`taskstore`、`seriesmeta`、`proposal`、`relocation` 等 module 延续自身职责。
新 module 只依赖本功能需要的数据能力，随功能迁移渐进收窄 `database.Store` 的使用面；不要求先重写存储模型。

兼容原则是保留有业务依据的能力、身份、权限与数据。历史实现差异须分类：明确的业务取舍保留，证据充分的遗漏统一纠正，产品意图不清再询问用户。
发现错误不再以“保持行为”为由机械复制；设计中明确记录有意纠正的部分。

## 整体归属

| 归属 | 持有的知识 | 调用方无需知道的细节 |
| --- | --- | --- |
| 输入 adapter | HTTP/协议解析、身份提取、权限入口、响应转换；定时或监听输入 | 功能内部规则与事务步骤 |
| 阅读状态 module | 阅读位置、读态、阅读活动、时长、书签、每用户投影与继续阅读判定 | 拒旧、去重、批量展开、活动写入、系列聚合 |
| 藏书编排 module | 人工合集、智能书架、作品群与其成员/身份规则，AI 分组落地 | 所有权检查、名称冲突、裁决与建合集的事务、稳定身份 |
| 应用编排 module | 跨功能完整协作链、后台发起、装配与进程生命周期 | 启动恢复顺序、停止等待、多个能力间的交接 |
| 前端应用会话 module | 实时连接、协议解码、推送连续性信号、共享刷新协调 | 重连、帧投递和路由作用域的连接管理 |
| 前端功能 module | 本功能查询、操作结果与状态投影 | 输入传输与全站连接机制 |
| 页面 | 筛选、选中项、弹窗、布局等局部视图状态 | 全站一致性与后端功能规则 |

推荐工程落点为 `internal/reading`、`internal/organize` 与 `internal/application`；前端会话使用独立于导航视图的目录。
目录名称是实现期可调整的机械选择，职责与依赖方向才是设计约束。已有页面拆分不作无收益的批量改名。

依赖从输入 adapter 指向功能 module；应用编排组合功能 module 和基础能力。
功能 module 不反向依赖 `internal/api` 或应用总对象；需要的协作能力由装配注入。
应用编排不为每个单纯功能调用新增转发方法，也不吸收阅读或藏书编排的内部规则。

请求身份和授权继续由现有入口校验；module 接收明确的用户或操作主体，不依赖隐含的全局“当前用户”。

## interface 比较与推荐

围绕进度变更核心比较了三种形状：

| 形状 | depth / locality | 取舍 |
| --- | --- | --- |
| 少量入口配封闭输入变体 | 可隐藏共同 implementation，但同一方法仍有多种结果与语义 | 方法少不等于调用方学习少；避免为追求入口数量把概念塞在一起 |
| 通用变更计划与 profile | 可复用内部执行过程 | 公开策略组合会产生无意义组合与运行时校验，将正确性责任泄回 adapter |
| 按完整用例命名 | 调用方直接表达已有意图，规则与后续动作有 locality | 入口略多，但无需学习策略开关，leverage 更明确 |

推荐第三种。`RecordPosition`、`SyncPositions`、`MarkBooks`、`MarkSeries` 是说明意图的示例，不是生成契约。
在线、离线批量与逐本回退共享位置变更的核心规则，不因传输形态形成独立业务 policy。
KOReader 继续负责设备账号、认证、指纹匹配和协议记录；匹配后的当前位置变更进入同一阅读状态规则。
分页位置与百分比的转换使用已有书事实，不将设备协议细节塞进共同的规则。

存储 seam 留在 implementation 内，按已经证明需要的一致性操作组织；不公开 `GetBook → WriteProgress → RefreshStats` 之类步骤配方。
调用结果表达应用、跳过、提交范围与告警等事实，不要求 adapter 根据 `NeedLogActivity` 或 `InvalidateStats` 等指令自行收尾。
功能内部需要的缓存失效能力通过明确依赖注入，跨功能后续动作由唯一的编排所有者接管。
不引入通用流程引擎、任意 policy 开关或万能事件总线。

## 阅读状态的已确认行为

### 当前位置、时间与重放

- 阅读位置是用户当前的位置，允许有效的新阅读前进或回退。KOReader 书投影不再永远取最远页。
- 有阅读发生时间的报告，用该时间判断新旧并记录；没有该时间的在线/设备新报告使用服务端接收时间。
- 同一离线队列通过批量或逐本回退传输，冲突胜负与落库时间相同。
- 同页发生新的有效阅读，刷新最近阅读时间；同一报告重试不制造新的阅读事实。
- 补传和对账重放携带原事实时间，不把执行时刻当作新的阅读时刻。
- 标记未读清除读态。旧记录重放不能复活清除前的进度，更新的有效阅读仍可建立位置。
- 清除动作需要可跨重启保留的变更依据，与用于展示的最近阅读时间分开。现有直接删除进度行不足以独立满足这一要求；规格阶段需列出必要的最小存储变更。
- 保留每用户隔离、现有无用户兼容路径，以及协议账号与站点用户的归属规则。

### 批量标记与活动

- 按书、按系列的批量标记已读统一计入阅读活动，各条输入路径采用相同业务语义。
- 标记未读不新增阅读活动，也不删除过去的活动。
- 新的批量标记已读按标记发生日期记活动；重试与旧记录重放不制造新活动日期。
- 页数未知也可计入活动日和涉及书的统计；内部 `99999` 哨兵不得进入活动、聚合或展示中的真实页数统计。
- 离线阅读活动归属于可证明的原阅读日期，沿用服务端本地日历口径；不按联网日期虚构阅读。
- 现有活动页数按每日每书的绝对页码取最大值，并非实际翻读页数增量。本轮不将其包装成精确翻页统计，不猜测重建历史。
- 当前离线队列不保存完整阅读事件历史；只处理其中可证明的事实，不凭最后一条位置补造多日阅读。

### 提交与失败

- 保留分批提交，批内的进度与系列聚合一致；整体不承诺一个覆盖全部书的大事务。
- 前批已提交、后批失败，不能撤销已发生的提交；结果在功能内部准确表达，已提交部分触发必要缓存失效。
- 统计失败和进度写入失败分开处理。已提交进度不能被描述成未保存，统计告警仍须可观察。
- 全局及每用户活动写入的历史分工逐步收敛；兼容期间独立尝试，不能因其中一条失败就无理由跳过另一条。
- KOReader 设备协议记录与书位置不是一个跨功能大事务。真正的位置写入失败继续有诊断，设备协议保存顺序与返回约定保持兼容。
- 时长上报既有的活跃性判断、短时统计尽力而为与避免重复计数约束继续有效；不顺带增加全量时长事件存储。

### 阅读功能范围

除进度变更核心，还为时长、书签、按用户叠加状态与继续阅读判定建立阅读状态归属，可分后续批次迁移。
书的归档读取、图片解码转码、页图缓存和前端离线字节下载继续使用已有能力，不因“阅读”同名而全部并入一个对象。
统计展示查询可继续由已有查询实现承载；阅读状态拥有写入含义和派生一致性，展示不复制一套冲突规则。

## 藏书编排的归属

- 人工合集持有人工成员规则；智能书架按条件动态推导；固化是有明确时间的一次性动作。
- 作品群由系列关系推导，保留稳定身份、成员差集与人工只读规则。
- 智能书架快照与 AI 分组落地后的合集归用户所有，不因来源字段被误判成持续推导对象。
- AI 分组的合集建议不是系列元数据提案，不强塞进 `proposal`。
- 接受分组与生成合集作为完整动作接管，保持名称约束、消失成员处理与裁决状态一致性。
- 有序阅读清单保持独立子功能及其顺序语义，不复用一个抹平所有集合差异的“通用容器”模型。是否同目录不是领域判据。
- 图查询和 OPDS / Mihon 的合集访问继续共享已确认身份；传输 adapter 不持有重建规则。

## 前端会话与一致性

- 连接、解码、重连和连续性通知脱离导航视图的 implementation，订阅活跃范围由路由集成明确声明。
- 本轮保持主导航路线的既有订阅范围，阅读器与独立图谱不顺带新增常驻连接。
- 单连接指每个前端应用实例；不增加跨浏览器标签的连接合并机制。
- 普通用户保留藏书刷新；运行敏感数据仍由后端仅发送给管理员。
- 鉴权状态由现有 AuthProvider 持有。连接及角色相关投影随身份变化清理，临时断网不等于显式登出。
- 保留 `sequence / prev` 投递链语义、漏帧恢复和必要轮询；不按序号加一判缺口，也不从局部运行列表重算后端实况汇总。
- 任务实况、历史列表、气泡、外部传输各自拥有功能投影；应用会话不汇总成一个包含所有页面数据的大对象。
- 共享刷新协调覆盖功能写入后的必要失效与重拉，页面不再需要理解底层传输事件名。
- 当前书视图、跨书下载、本地离线归属与设备级偏好保持不同生命周期；不顺带将下载升级为全站任务或将偏好改成账户级。

## 应用编排与生命周期

跨功能协作需要完整交付，不能分别迁走后让输入 adapter 自行拼装：

| 协作链 | 必须共同保持的约束 |
| --- | --- |
| 资料库迁移与保护恢复 | 独占访问及相交目录保护、数据库和配置提交恢复、阅读路径缓存失效、外部会话失效、目录监听切换；全部成功才完成并开放访问 |
| 监听扫描后清理 | 等真实运行完成；合并、停发、排队发起不能冒充扫描成功，否则可能抢先删除改名重连的记录 |
| 扫描封面批交接 | 批在实际运行开跑时认领；合并不丢批；发起不阻塞扫描；扫描与封面仍各有运行 |
| 扫描批事件 | 统计失效、必要预热与原语义推送同时保留，不能用单纯刷新替换完整处理 |

启动顺序保持“登记能力与重启函数 → 一致性恢复 → 运行恢复和后台开放 → 请求开放”。
停止顺序保持配置监听停止、请求排空与推送关闭、目录监听停止、运行取消及后台等待等现有承重约束。
遵守 ADR 0001 / 0004 / 0005 / 0006 / 0007 / 0008 / 0009；不重新制造扫描准入锁，也不合并 task 与 taskstore。
ADR 的过期实施状态在后续文档整理时按代码核实，不把旧状态当作功能不存在的证据。

## 推荐推进顺序

1. 以本文统一职责图、行为矩阵和依赖方向，标明需保持的完整协作链。
2. 先迁阅读位置、读态、活动与派生一致性的完整链；同时覆盖已确认的历史遗漏纠正。
3. 为其余阅读状态建立归属，迁移时长、书签及共享读取判定；每次交付完整用例。
4. 迁移藏书编排，可按人工/动态/推导规则分批，但每批处理相关输入与事务，不留下两份权威规则。
5. 按稳定事件语义收拢前端应用会话和功能投影，保持连接作用域与权限。
6. 后台编排逐条接管完整协作链，最后收拢进程装配与生命周期。

过渡期允许 Controller 继续装配和转发；不要求先完成应用总装配迁移才能启动功能深化。
前端与后台工作可在依赖已经明确且不拆开一致性链时交错推进。
迁移使用短期兼容转发，阶段完成即移除被替代的规则实现和无行为价值的镜像测试。

## 验证与完成判据

interface 是测试面。复用现有行为回归，以真实临时 SQLite 验证事务、聚合与部分提交，时间与故障使用必要的 internal seam。
重点验证新旧时间胜负、同页新阅读与重试、KOReader 回退和旧记录重放、未读清除后的拒旧、批量活动、未知页数、统计告警及部分提交失效。
前端验证身份切换、路由作用域、重连、漏帧与跨功能投影；生命周期验证恢复先于开放访问和停止后后台退出。

依仓库要求执行相关门禁：Go 测试、gofmt 与 golangci-lint；前端变更执行测试、构建及适用 lint；生成契约和 SQL 变更按仓库规则再生成。
本轮未实现功能、未运行这些程序测试；当前文档校验不等同于实现验证。

每个方向完成时，输入 adapter 不再掌握被迁功能的规则与后续动作配方；相同规则只有一个权威归属；无需为了基本规则测试启动整个 Controller。
若删除新 module，复杂度应重新散回多个调用方；若只是去掉一层转发，说明没有获得足够 depth。
