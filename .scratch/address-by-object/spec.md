# Spec: 按对象寻址，任务键退回日志

Status: ready-for-agent

## Problem Statement

**用户点的重试，动到的可能不是他看着的那一条。** 队列一开，同一个**任务键**此刻可以有两条仍会
变化的**运行**——一条在跑、一条**排队中**。而重试按键取「最近那一条」，序号在入队与每次**合并**
时都会重取，所以只要有排队运行，它就永远是「最近那一条」。今天两条运行的**重启入参**恰好相同，
所以还没有人被咬到；但「最近那一次」这个说法已经不等于「用户正看着的那一次」，而这只是运气。

**搜索框里要打内部串才命中。** 任务清单与运行列表的关键词搜索按**任务键**匹配，用户得知道
`scan_library_1` 这种由身份四要素拼出来的串。他真正记得的是那个资料库叫什么——而资料库的名字
搜不到，尽管它就在运行行上（**作用域**显示名）。

**同一个东西在不同地方叫不同名字，读的人要认两次。** `internal/api` 里同时看得见两个
`RunStatus`：本包那个是交给前端的**运行**快照结构体，`task.RunStatus` 是运行状态那个字符串枚举，
同一个函数里两者会一起出现。任务子域里还留着一批按旧概念取的名字（一次运行的结果、它生效的
并发上限、任务体的形参），与刚改好的邻居自相矛盾。同一份载荷在 SSE 与浏览器自定义事件两跳里
也叫两个名字。八条状态文案的 i18n 键仍写作**任务状态**，而它描述的是一次**运行**的状态。

**吞吐曲线与运行卡片上有两个同名的数。** 卡片上的 `rate_per_minute` 是这次运行至今的平均速率
（分母扣掉**暂停**），**采样**点上的 `rate_per_minute` 是自上一个点以来那一段的吞吐（分母是墙上
时间）。一条正被暂停的运行因此同时显示「300/min」与一条贴着零的曲线，而两个数都是对的。

底下是同一件事：**「任务与运行分家」留下的最后一寸过渡期寻址与过渡期命名还立着。**

## Solution

六个控制端点全部按**对象**寻址：暂停 / 恢复 / 取消作用在**运行**上（已经如此），重试 / 禁用 /
启用作用在**任务**上（禁用与启用已经如此，重试改过来）。**任务键**从寻址里退出，退回它真正擅长
的地方——日志行上给人读（见 ADR 0007）。

搜索改按用户看得见的名字匹配：打资料库的名字就能筛出它的运行。

「任务→运行」的改名一次扫干净，包括那个同名不同物的快照类型与采样上那个同名不同物的速率字段。
这三件事都动前端生成契约，**并批做，契约只重生一次**。

## User Stories

1. As a 用户, I want 点某条运行卡片上的重试时动到的就是那一条对应的任务, so that 我不必担心它悄悄重放了另一次运行的参数。
2. As a 用户, I want 重试重放的是**上一次跑完那次**的入参, so that 我刚看到一次强制扫描失败、点重试，重跑的仍然是强制扫描。
3. As a 用户, I want 一个任务正有一条运行排着队时点重试不会读到那条排队的, so that 「重试」的对象与我屏幕上那张卡片一致。
4. As a 用户, I want 在任务中心的搜索框里打资料库的名字就能筛出它的运行, so that 我不必先知道 `scan_library_1` 这种内部串。
5. As a 用户, I want 搜类型名（如 `scan_library`）仍然命中, so that 换了匹配口径之后我原来的用法不失效。
6. As a 排障的人, I want 每一行日志上仍然带着**任务键**, so that 我能问「这个任务历次运行的日志」，而不只是「这一次的」。
7. As a 排障的人, I want 日志端点同时收**任务键**与**运行标识**两条谓词, so that 我能精确到「这个任务的这一次」。
8. As a 排障的人, I want 一条日志行上的任务键仍然读得懂, so that 我在日志文件里一眼看出它属于哪个库的哪类活，而不是只看到一个自增数字。
9. As a 用户, I want 升级之后我原有的任务与运行历史一条不少, so that 这次收口不以丢历史为代价。
10. As a 用户, I want 升级不触发一轮全量回填, so that 我的库不会在升级后首启白算一遍。
11. As a 开发者, I want `internal/api` 里不再有两个同名不同物的 `RunStatus`, so that 我读一个函数时不必靠包限定符分辨。
12. As a 开发者, I want 任务子域里描述「一次运行的结果」「它生效的并发上限」的类型叫 `Run*`, so that 名字与它描述的东西一致。
13. As a 开发者, I want **任务**与**变体**那两个类型保留 `Task*` 前缀, so that 名副其实的名字不被一次机械改名扫掉。
14. As a 开发者, I want 任务体形参在两个包里叫同一个名字, so that 我不必为同一个东西认两次。
15. As a 开发者, I want 一份推送载荷在 SSE 与浏览器事件两跳里叫同一个名字, so that 我读代码时不用跳一次才知道它们是一件事。
16. As a 译者, I want 八条运行状态文案的 i18n 键叫**运行状态**而不是**任务状态**, so that 键名与它描述的东西一致。
17. As a 用户, I want 吞吐曲线上那个数与运行卡片上那个数名字不同, so that 我看到「300/min」配一条贴零的曲线时知道它们量的不是一回事。
18. As a 开发者, I want 前端生成契约在这一批里只重生一次, so that 我不必为三次纯命名改动各审一遍前端 churn。
19. As a 用户, I want 重试端点与禁用 / 启用端点在同一段路径上用同一个参数名, so that 这两条路读起来不再像随时会看错。
20. As a 下一个动这块的人, I want 「键为什么留在日志里却从 API 与表里删掉」写在 ADR 里, so that 我不会把它当成一次漏删而「修好」它。

## Implementation Decisions

### 任务键退出寻址，不退出日志（ADR 0007）

这是本批的立论，已单独记为 ADR 0007。**删除**：`runs` 上的**任务键**列与它的索引、
对外契约上的 `RunStatus.Key`、`RunFilter` 的键谓词与按键取「最近那一条」的取数函数。
**保留**：`RunSpec.Key`，继续经 ctx 注入的 slog handler 写在每一行日志上；日志端点的
**任务键**与**运行标识**两条并列谓词照旧。

`CONTEXT.md` 的**任务键**词条要改写：它今天写着「给日志、URL 与人眼辨认用」，URL 那一项没了。
本批落地时改，不提前改——词条只写当前的实然。

### 重试改按任务寻址

端点改成按**任务**的自增标识寻址，与禁用 / 启用端点同形（它们已经如此）。这顺带消灭
「同一段路径上两个不同参数名」这个容易看错的形状。

**读哪一条运行的入参：最近一条进入终态的运行。** 重试的意思是「那次跑完的，再跑一次」，
而排队中与运行中的都没有可重放的东西。这是对既有行为的收紧，也把「排队那条永远是最近一条」
这个隐患一次答掉。找不到终态运行时按「任务不存在可重试的运行」处理。

### 搜索匹配串换成作用域显示名

任务清单与运行列表的关键词搜索表达式，把**任务键**那一格换成**作用域**显示名。类型名靠文案码
仍然命中（文案码里带着类型名），换来的是资料库名与系列名从此搜得到。

已知的小疤，本批**不修**：刮削全库那条的作用域显示名是写死的中文字面量，不走 i18n，英文界面
搜英文搜不到它。修它要先决定「系统作用域的显示名归谁」，那是另一件事。

### 改名一次扫干净

- 交给前端的运行快照结构体改名为 `RunSnapshot`，与 SSE 事件名对齐，也解掉与状态枚举的同名冲突。
  **这一条推翻 `task-run-model` 规格的关键决定 16**（那里逐字写的是 `RunStatus`）——那条决定
  当时没有预见到本包里会同时出现两个同名类型。
- 描述「一次运行的结果」与「它生效的并发上限」的类型改 `Run*` 前缀；相关函数名（取最近若干类型
  的运行、给进度补料、算至今暂停了多久）跟着改。
- **任务**与**变体**那两个类型**保留原名**：它们对应词汇表里的两个词条，名副其实。
- 任务体形参在 `internal/api` 侧由旧缩写改成与领域侧一致的名字。
- 浏览器内部那条自定义事件（含它的覆盖变体）改名与 SSE 事件名同形。
- 八条运行状态文案的 i18n 键由**任务状态**改为**运行状态**，两份 locale 与拼串处一起改。

### 采样那一格改名

**采样**载荷上的每分钟速率字段改名为 `throughput_per_minute`，与运行卡片上的平均速率区分开。
两个数都保留、都对，改的只是名字。这是一次对外 JSON 字段的变更（v1.6.2 已发布），
需要一条 `CHANGELOG.md`；唯一的消费方是本仓自己的前端，与后端同一个二进制一起发。

### 迁移

掉列与掉索引走幂等 DDL，**不推**全量回填的版本号——与「新表不推」「丢弃旧表不推」同一条口径：
那个版本号门控的是随库规模线性增长的全量重算，为一次结构变更推它会让每个存量库白算一遍。

### 两个控制端点生成器不合并

按运行寻址的那个生成器与按任务寻址的那个**不合并**。原先的判断是「重试改成按对象寻址之后
合并的收益比现在大」，实测不成立：重试要先取回快照、认出**重启函数**、再发起，并带自己的
404 分支，它加入不了任何一个生成器；可合并的仍只有原来那两个，而统一签名还要给三个控制方法
各补一个用不上的 ctx 形参。**写进代码注释，避免下一次 code-review 再提一遍。**

## Testing Decisions

好的测试只断言**外部行为**，不断言实现细节。本仓任务子域的观测面已经定死了：任务引擎只有
一个 seam（构造点 `newTaskEngine`），观测面是**投递出去的载荷**，与 SSE 订阅者看到的完全一致。
本批**不新增任何 seam**。

**在任务引擎 seam 上守（`internal/api`）：**
- 投递出去的运行快照上不再有键那一格。
- 重试按任务标识寻址：同一个任务有一条运行中与一条排队中的运行时，重试重放的是**最近那条终态
  运行**的入参，而不是排队那条。前例：既有的哈希重建重试装置。
- 重试端点与禁用 / 启用端点经**真路由**验证，两条路径都取到自己那个参数。前例：既有那条
  「禁用挡住自动发起但不挡手动」的用例，它已经走真路由。
- 搜索：打作用域显示名筛得到，打类型名仍筛得到。

**在 `internal/taskstore` 的真 SQLite 迁移 seam 上守：**
- 存量库掉列掉索引，任务与运行历史一条不少。两个起始版本各跑一遍。
- 前例：既有的「丢弃旧表」与「身份表改名」两条迁移用例。

**已经存在、必须保持绿的那一条：** 守「任务体沿途的日志带**任务键**、按它过滤拿得到非空结果」
的那条用例，正是 ADR 0007 决定的守卫。本批**不新写**它，只保证它不变红——破了的表现就是它
注释里写的：「那个按钮对绝大多数任务返回空列表」。

**前端（vitest）：** 重试按钮发的是任务标识；快照类型改名后组件与工具函数编译并通过既有用例。
前例：既有的任务中心组件用例。

**契约漂移**由 CI 既有的生成器检查兜住，本批不另写。

## Out of Scope

- **清除**（按筛选删运行记录）的寻址不动：它按筛选作用在运行上，本来就不按键寻址。
- 刮削全库那条写死的中文作用域显示名不修（见上）。
- **任务键**的拼法不动：它仍由启动点自己拼，与身份四项不互相推导。
- 不碰**合并**的语义、不碰**上报**走哪条通道——那是 `report-truthfully` 的事。
- 不做任务清单与历次运行的分页。
- 不动**退避**、**停发**、**可续跑**白名单与保留裁剪。

## Further Notes

- ADR 0004 只判定了「键不该当主键」，没有判定「键该不该用来寻址」。ADR 0007 补的正是后者，
  两者不冲突：反对的是**拿串当身份**，不反对**拿串给人看**。
- 本批三件事（删键、改名、采样字段改名）都动前端生成契约。**它们必须同批落地**，否则就是三次
  重生契约、三轮前端 churn；票的切分要保证契约重生只发生一次。
- 日志行上的任务键从此没有任何库表与它对应，唯一来源是启动点写下的 `RunSpec.Key`。改了某个
  启动点的 Key，历史日志与新日志就对不上，而没有哪张表能把两者接起来——这是让它留下来的代价，
  已写进 ADR 0007 的后果一节。
