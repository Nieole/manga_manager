# 02 — 一次运行的声明分成重启入参与声明标签

**What to build:** 用户打开任一条运行的参数面板时，看到的只剩**真正会影响这次怎么跑的那几项**——
扫描的强制、刮削的来源、AI 分组的语种、哈希回填的发起理由。今天那里还混着存储档位、卷键、并发数
这些**只描述它在什么条件下跑**的项，以及一份与**上限**表重复的扫描等级；用户分不出哪一格是
「我选的」、哪一格是「当时的环境」。

判据是一句话（ADR 0008 与 `CONTEXT.md` 的**重启入参** / **声明标签**两个词条）：
**把它从声明里去掉，重启出来的那次会不会跑成另一个样子？** 会 → 重启入参；不会 → 声明标签。
落地期间有一个机械对账：**重启函数**里按键取参数的那些调用点，读到的就是入参，其余是标签。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] `RunSpec` 上那个混装的格子拆成**重启入参**与**声明标签**两格

- [ ] 每个启动点的声明按判据归位；归位结果与**重启函数**实际读回的键对得上
- [ ] 扫描等级不再在声明里留第二份，归**上限**表——**同一件事只报一次**
- [ ] **重启函数**读回的每一个键仍读得回：既有的重试用例一条不改且全绿
- [ ] 投递出去的运行快照上两格分开；重生生成的前端契约，CI 漂移检查过
- [ ] 参数面板只显示**重启入参**；**声明标签**仍在它们今天显示的地方显示（如「存储 IO」那一行）
- [ ] 在**任务引擎 seam** 上断言：扫描、刮削、AI 分组、哈希回填四类运行的入参与标签各自落在对的一格
