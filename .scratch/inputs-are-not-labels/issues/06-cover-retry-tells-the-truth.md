# 06 — 重建封面的重试被合并时如实回话

**What to build:** 用户点了封面运行的重试，而这个库已经排着一条**串联发起**的封面运行时——今天界面
回「已发起」，实际这次重试被**合并**进那一条，而那一条**不会自己去找活**（它只处理扫描递过来的那一批，
而那一批早就没了）。于是用户点了重试，拿到的是一条什么都不做的运行，封面照样补不上。

票 03 把「自己去找活」变成了声明里的一条**重启入参**，票 04 让引擎判得出它被丢掉了——这张票把
判断结果说给用户。

**Blocked by:** 03, 04

**Status:** ready-for-agent

- [ ] 封面运行的手动与重试发起不再丢弃引擎交回的发起结果
- [ ] 本次发起被**有损合并**（「自己去找活」被丢掉）时，端点回一句说明：已并入正在排着的那次，那次不会自己找活
- [ ] 沿用票 05 那条判据函数的形状，**不新造第三套说法**
- [ ] 在**真路由**上守它：排着一条串联发起的封面运行，再来一次重试
- [ ] 守边界：队列里没有排队运行时，重试照常新建一条运行并保住「自己去找活」
- [ ] 守边界：**串联**发起被合并时不回这句话——它没有人在等答案，留痕由票 04 的事件负责
- [ ] `CHANGELOG.md` 记一条
- [ ] 后端与前端门禁全绿，**含 `gofmt -l ./cmd ./internal` 与 `golangci-lint run`**
