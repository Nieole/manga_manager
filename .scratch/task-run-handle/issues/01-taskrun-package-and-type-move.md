# 01 — 新包立起来，类型机械搬过去

**What to build:** 新增叶子包 `internal/taskrun`，一次性把**任务句柄**的完整接口做出来
（上报、过闸门、发起**磁盘作业**、取用 IO 实况），配齐契约用例；把 `api` 的 `TaskProgress` 与
`TaskFrame` 机械搬迁成 `taskrun.Handle` 与 `taskrun.Frame`；删掉三个上报方法；词汇表落地。

**本票零行为变化。** 句柄新长出来的过闸门与磁盘作业两个方法在本票**没有任何调用点**——
它们由票 02～04 接上。这样做是为了让后续三票都是纯调用点转换，而模块自身一次成型、
一次测完（`diskwork` 那次的票 1 就是这个形状）。

**Blocked by:** 无

**Status:** done

## 模块

包位于 `diskwork` 与 `taskcontrol` 之上、`api` 之下。它不认识**任务键**、**作用域**与**终态**。

构造期注入三个函数值与一个 `*diskwork.Runner`；**任务键**由引擎侧的闭包绑定，句柄上不出现它。
接口形状见 spec 的「深化后的模块与接口」，逐字照搬。

三条不变量由结构而非记性保证：

- 过闸门在未暂停时返回上下文错误，因此它同时是取消检查。
- 发起磁盘作业时，实况的吸收不依赖调用方记得做。
- `hashed_files` 只在工种是 `identity_hash` **且闭包真的执行了**时 +1 —— 实现上包一层闭包
  记录 `ran`，**不要**靠错误判断：入口把闸门错、令牌错与闭包自己的错从同一个值里返回，分不出来。

累加器加互斥锁。句柄的 package doc 与符号 doc 要写明：全部方法可从任意 goroutine 调用。
理由是上报那几个方法今天就会从任务体之外被调用（**扫描观察者**把封面队列的报文写进来，
见 ADR-0002），而累加器是新增的可变状态。

## 搬迁

`TaskProgress` → `taskrun.Handle`，`TaskFrame` → `taskrun.Frame`。引擎在启动入口里构造它，
把今天那三个按**任务键**写入的引擎方法包成闭包传进去。任务体的形参类型随之改名（17 处），
`taskScanObserver` 与 `rebuildThumbAggregator` 持有的字段类型也随之改名——**只改类型名，不重构**。

**删掉三个方法**（生产调用点全为 0）：

| 方法 | 处置 |
| --- | --- |
| `Item` | 删，0 个调用点 |
| `Labels` | 删，0 个调用点 |
| `Metrics` | 删，0 个调用点；三处用例调用点改写成整帧上报 |

`Frame` 的字段一个不动。零调用点的是**写入方法**，不是同名字段——`Item` 与 `Labels` 各有
5 处与 3 处生产写入点经整帧上报走这两个字段，删掉它们会让任务面板的**当前条目**与
`current_library` / `storage_profile` 等标签停止更新，与本票的「零行为变化」直接冲突。

保留**阶段**（6 个调用点）与**计数推进**（1 个）：它们分别编码词汇表里两个相互独立的概念，
不是凑数的转发。

**顺带修正一句与事实不符的 doc**：今天句柄的 doc 写着「日常上报请用 Advance / Phase / Item /
Metrics / Labels……是这个句柄的主用法」，而真实分布是整帧上报 24、**阶段** 6、合并参数 4、
**计数推进** 1、累加指标 1，其中两个被称作主用法的方法零调用点。

## 词汇表

`CONTEXT.md` 的「后台任务」节：

- **新增「任务句柄 (Task handle)」**：任务体干活所需的全部资格——写这个任务的进度、在可中断点
  询问**暂停闸门**、发起**磁盘作业**。任务体拿到它才能做这三件事，而不是谁拼对了**任务键**
  谁就能做。_Avoid_: 进度句柄、回调、reporter。
- **删除「进度句柄 (Progress handle)」**：外延已被上述词条覆盖。原词条那句核心论断
  （资格由「谁拿到它」决定）原样继承进新词条。
- 全仓约 12 处注释里的「**进度句柄**」随之改口。

**不要**复用「运行时句柄」这个名字：它已经指 `TaskRuntime`（引擎内部登记的 ctx + 闸门 + cancel），
且刻意从不交给任务体。

## 契约用例

新接缝 = 本包的构造点：三个记录用的桩函数 + 建在**新建**调度器上的 `diskwork.Runner`
（不得用包级实例，否则用例之间会经按卷计数的限流器互相污染）。无数据库、无引擎、无文件树。

- **计数规则**：工种 `identity_hash` 且闭包执行 → 为 1；闭包未执行（闸门暂停 / 上下文已取消）
  → 仍为 0；其余工种执行了也不计。**今天零覆盖且本次改行为，这是最该写的一条。**
- **吸收**：等待与暂停累加；存储档位与卷键取最后一次非空，闸门挡下的零值不覆盖已有值。
- **闸门先于令牌**：闸门处于暂停态时闭包不执行，且不占用令牌槽位。
- **过闸门**：暂停态阻塞、恢复后放行；上下文已取消时返回取消错误。
- **上报**：整帧、**计数推进**、**阶段**三条各自交给注入函数的 `Frame` 内容；合并参数与累加
  指标走各自那个函数。
- **并发**：`-race` 下一个 goroutine 反复发起磁盘作业、另一个反复上报并读 IO 实况，无竞态。

先例照 `internal/diskwork/runner_test.go`（新建调度器、断言闭包是否执行、契约压在构造点）与
`internal/taskcontrol/pause_gate_test.go`（驱动暂停态的写法）。
