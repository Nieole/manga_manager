# 挂账清单 · task-run-model

跑票过程中冒出的非阻塞选择。流程不为它们停；由用户挑时机逐条处理。

## D1 · 票 04 · **变体**落盘走任务参数还是给老表加一列

- **问：** 身份四要素里类型、作用域、作用域 id 三项都是 `tasks` 表的真列，**变体**没有。本票让它随
  任务参数（`params` TEXT）落盘再读回，理由是这张表随票 08 整表丢弃，而加一列要动 `schema.sql`、
  写一条迁移、重跑 `sqlc generate`，两票之后又全删掉。
- **选项：** A 维持随任务参数走（推荐，因为这张表两票之后就没了，而新表本来就有 variant 列）｜
  B 现在就加 `variant` 列并写迁移，让四要素在老表上也齐整
- **不处理会怎样：** 已按 A 落地。升级前落下的刮削与书哈希重建历史行读不回变体，
  `taskStatusFromRecordLive` 会按当前注册表把它们算成不可重试——界面上那个重试按钮消失（而不是
  点下去报错），重新发起一次即可，新起的任务不受影响。
- **状态：** pending

## D2 · 票 04 · `TaskStatus.variant` 要不要现在就进前端契约

- **问：** 身份四要素的另外三项都在 JSON 里，本票把变体也放了进去并重生了 `web/src/api/generated.ts`。
  但前端今天没有任何消费方，而票 16 还要把整份契约重生一遍。
- **选项：** A 维持进 JSON（推荐，因为四要素分两处走的话，任何按快照判身份的地方都要再从别处补
  一项；测试也才能像断言另外三项一样断言它——规格的测试口径正是「只断言投递出去的载荷」）｜
  B 标 `json:"-"`，等票 16 连同契约重生一起放出去，代价是身份四要素在快照上缺一项
- **不处理会怎样：** 契约里多一个可选字段先于用途存在；从库里读回的历史任务，参数面板里会多出
  一行 `variant`（`phase`、`can_pause`、`metric.*` 今天已经是这样）。
- **状态：** pending

## D3 · 票 04 · 播种脚手架的身份是必填还是留一个默认

- **问：** `taskSeed` 把 `Type` 换成了必填的 `Identity`，83 个播种点跟着改。另一条路是保留 `Type`、
  身份留一个「默认系统级」的兜底，只有关心作用域的用例才填。
- **选项：** A 必填（推荐，因为脚手架的 doc 本就写着「播种与生产同源」，而兜底会让按作用域筛选的
  用例静默换轨——它们不会变红，只会不再守着原来那条）｜ B 默认系统级，churn 小得多
- **不处理会怎样：** 已按 A 落地；代价是本票 diff 里测试改动占了大头。
- **状态：** pending
