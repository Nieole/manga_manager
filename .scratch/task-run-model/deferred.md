# 挂账清单 · task-run-model

跑票过程中冒出的非阻塞选择。流程不为它们停；由用户挑时机逐条处理。

## D1 · 票 05 · 作用域 id 用 `int64` 零值表示「没有」，还是 `*int64`

- **问：** 身份四要素里的作用域 id 今天在 `api.TaskStatus` 上是 `*int64`（JSON 侧要 omitempty）。
  领域包改成了 `int64`，0 表示系统级没有作用域对象。理由是身份的唯一约束要比较这一列，
  而 SQL 里 NULL 不等于 NULL——留 NULL 的话同一个系统级身份会被建出任意多条。
- **选项：** A `int64` + 0 表示没有（推荐，唯一约束天然成立，`Identity.Validate` 顺带把
  「系统级不得带 id」与「库级必须带 id」两条判掉）｜ B `*int64`，由 `taskstore` 在写入时 coalesce 成 0，
  代价是那条 coalesce 漏掉一处不会有编译错误
- **不处理会怎样：** 已按 A 落地。票 06 建表时 `scope_id` 应为 NOT NULL DEFAULT 0，
  接线时 api 的 DTO 要在边界上做一次 0 ↔ nil 的转换。
- **状态：** open

## D2 · 票 05 · 运行的展示标签落在哪张表

- **问：** 规格的表形状列了六张表（runs / run_events / run_samples / run_metrics / run_limits / run_args），
  没有标签的去处；而 `RunSpec.Labels` 与 `taskrun.Frame.Labels`（刮削源名等）今天确实存在，
  它们既不是重启入参也不是指标。领域包为此在端口上开了 `MergeRunLabels`。
- **选项：** A 单开一张 `run_labels`（推荐，与「五类语义各回各家」一致，读回时不必按前缀分拣）｜
  B 并进 `run_args`，靠键前缀区分，代价是那张表重新混进两类语义——这正是 `params` 堆的成因｜
  C 判定标签属于展示态、升为 `runs` 的定长真列，代价是加一个标签要改 schema
- **不处理会怎样：** 端口已按「标签自成一路」声明。票 06 若并进 `run_args`，改的是适配器一侧，
  领域端口不动；但两类语义会重新同居一个命名空间。
- **状态：** open

## D3 · 票 05 · 落盘是同步写端口，还是承接今天那条异步落盘 goroutine

- **问：** 今天的引擎有一条 500ms 节流的落盘 goroutine（待写集合按键合并、终态唤醒立即刷、
  停机前再刷一次），它防的是「在临界区里同步写 SQLite 阻塞任务 API」。领域包对着的是一个端口，
  纯内存下这套机械没有意义，因此本票写成了同步调用。票 07 的验收里点名要重新论证这条。
- **选项：** A 领域同步写，节流与批量交给 `taskstore` 适配器（推荐，领域层因此没有「待写集合」这类
  与规则无关的状态，票 07 只需在适配器一侧决定怎么攒批）｜ B 把异步落盘原样搬进领域包，
  代价是端口多一条「刷盘」语义，而纯内存用例要为它另写一套等待
- **不处理会怎样：** 已按 A 落地。票 07 接线时若发现同步写真的压着任务 API，
  要在适配器里加节流，而不是把它加回领域层。
- **状态：** open

## D4 · 票 05 · 控制能力（可暂停 / 可取消 / 可恢复）落不落列

- **问：** 今天这三个布尔值是 `tasks` 表的真列。规格的新表形状里没有它们，而它们的事实来源是
  「这条运行的**暂停闸门**此刻还在不在」——闸门活在进程里。领域包因此把它们做成了
  `Capabilities`，由引擎按运行的活性派生，随快照一起投递。
- **选项：** A 派生、不落列（推荐，落成列的话重启后那几个布尔值会集体说谎：库里写着可暂停，
  而闸门早已随进程消失）｜ B 落成 `runs` 的列，读回时再按活性覆盖一遍，代价是同一件事有两个来源
- **不处理会怎样：** 已按 A 落地。票 07 接线时 api 的 DTO 要从 `Snapshot.Capabilities` 取这三个值，
  而不是从运行行上读。
- **状态：** open

## D5 · 票 05 · **排队中**运行的开始时刻留零值

- **问：** 排队中的运行还没开跑，`started_at` 写什么。领域包留零值，等它真的进入运行中才写——
  写入队时刻的话，排了一小时队的运行会被算成跑了一小时，速率与 ETA 一路失真。
- **选项：** A 留零值，放行时补写（推荐，速率的分母因此只包含真的在跑的那段）｜
  B 写入队时刻，另加一列记真正的开跑时刻，代价是多一列且两列的语义要靠命名区分
- **不处理会怎样：** 已按 A 落地。票 06 建表时 `runs.started_at` 必须可空（或接受零值），
  不能加 NOT NULL 且无默认。
- **状态：** open

## D6 · 票 05 · `taskrun` 的包 doc 仍把句柄的归属写作 api 的任务引擎

- **问：** `internal/taskrun` 的 package doc 写着「句柄由 api 的任务引擎构造并交给任务体」，
  而票 07 接线之后构造它的是 `internal/task` 的引擎。本票隔离在 worktree 里、不改现有文件，
  因此没有动它。词汇上「任务句柄」也该随规格改名为**运行句柄**。
- **选项：** A 留给票 09 的符号对齐一并改（推荐，那一票本来就要改名与重生成契约）｜
  B 票 07 接线时顺手改，代价是改名散在两票里
- **不处理会怎样：** 过渡期内那段包 doc 指着一个即将不成立的归属。
- **状态：** open

## D7 · 票 05 · 落盘端口只有写入面，**运行事件**的读取与计数还没有去处

- **问：** 票 05 只要求端口容得下「将来的**写入**」，因此端口上只有 `AppendRunEvents` 与
  `AppendRunSamples`。票 16 的「条目失败每次运行最多留 500 条，超出只累加计数并落一条
  『还有 N 条未列出』」要先问一句「这条运行已经存了几条 item 事件」，那是读，端口今天答不出。
- **选项：** A 等票 16 落地时按它真正要的形状加读取方法（推荐，读取面的分页与筛选口径由详情页
  决定，现在猜出来的签名多半要改）｜ B 本票就加一个 `CountRunEvents(runID, kind)`，
  代价是端口多一个没有实现也没有调用方的方法
- **不处理会怎样：** 票 16 要往端口上加方法。票 05 的验收没有欠账——它只要求容得下写入。
- **状态：** open

## D8 · 票 05 · `AGENTS.md` 的 `internal/*` 包清单漏掉 `internal/task`

- **问：** `AGENTS.md` 的 Project Structure 一节逐个点名了 `internal/*` 下的包，新建的
  `internal/task` 不在其中；票 06 的 `internal/taskstore` 落地后同样会缺。这是共享文件，
  本票按隔离纪律没有动它。
- **选项：** A 等两个新包都落地后一次性补进去（推荐，一次改动补齐两个名字）｜
  B 每建一个包就改一次，代价是共享文件在批次里被反复碰
- **不处理会怎样：** 清单少两个包名，新来的 agent 得自己 `ls internal/` 才知道它们存在。
- **状态：** open
