# 12 — 自动发起的工作也建运行

**What to build:** 定时守护扫描、watcher 派生的扫描与清理、建库后的首扫全部出现在任务中心，
带**发起方**标记（定时 / 监听 / 串联），可暂停可取消。用户半夜听见硬盘响时，界面上终于有东西。
同一票删掉 `ErrScanAlreadyRunning`，**准入只剩一处**。

**Blocked by:** 11

**Status:** done

## 今天的样子（ADR 0005 的起因）

这三条路径一律交出 nil **扫描观察者**，不建任务行。用户看不见、停不掉、暂停不了。
而拒绝它们撞车的是 `scanner` 自己那把按扫描目标判的闸门，与引擎按**任务键**判的那把是两套，
判据不一样。

## 删闸门要先有队列

`ErrScanAlreadyRunning` 今天兜住的是「守护扫描撞上手动扫描」。票 11 的排队接手这件事之后，
它才可以删——**顺序不能反**，否则中间会出现一个谁都不拦的窗口。

删掉之后，`scanner` 不再自己判「这个目标是不是已经在扫」；那个判断归任务的准入，
由数据库的部分唯一索引兜底。

## 边界

- **毫秒级的内存活不建运行**：作品群重建、仪表板统计预热。它们不动磁盘，建运行只会刷屏。
- 封面异步队列**本票不动**，它归票 13。本票之后守护扫描的运行仍然不等封面。
- 建库首扫的**发起方**是「串联」还是单列一种，实现时按界面读起来自然的那个定；
  词汇表里五种发起方已经定好，不要新增第六种。
- 守护 tick 每分钟检查一次这个节奏不变，变的只是它撞车时的行为与可见性。
