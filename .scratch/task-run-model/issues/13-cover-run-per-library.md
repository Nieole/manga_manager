# 13 — 封面每库一条运行

**What to build:** 「扫描完成」开始说真话。封面生成成为它自己的运行（每库一条，**发起方**串联），
可单独暂停与取消；扫描运行在归档处理完就完成，不再假装封面也好了。

**Blocked by:** 12

**Status:** done

## 今天在骗人

只有缩略图重建会等封面队列排空。**普通的资料库扫描不等**：它在归档处理完就进**终态**，
此后封面仍在后台生成，而那些迟到的报文被终态守卫丢弃。用户看到 100% 完成，
书库里还有一片无封面的书。

## 报文走自带的通道（ADR 0005，取代 ADR 0002）

封面作业**入队时就带上它属于哪一次运行**，报文直接写进那条封面运行；**扫描观察者**只管扫描本身。

这与仓里把扫描进度的接缝从装配期挪到调用点是同一个思路：**让报文自带去处**，
而不是让接收侧靠一张带锁的侧表按身份反查。那张侧表上一次重构刚删掉，不要请回来。

**ADR 0002 因此被取代**：它当时判定观察者不设撤销机制，理由正是「封面帧还要经它推进」，
而那个前提到此为止。0002 已标注被取代，原文保留。

## 连带改造

- 今天那个**全局** `coverWG` 改成**按批计数**：一条封面运行要能回答「我这一批排进去的封面
  还剩几张」。worker 池仍然是共享的，两个库的封面运行会交错推进，这是预期行为。
- **缩略图重建的两阶段分母拆掉**：它今天把归档处理与封面生成拼成一个分母来避免过早 100%，
  封面独立成运行之后，它的第二阶段是另一条运行，分母回归单阶段。
