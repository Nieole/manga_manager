# 10 — 任务中心两层结构

**What to build:** 任务中心从一条平铺列表改成两层：上半**现在**——在跑的运行常驻置顶，
带槽位占用与全部暂停；下半**任务清单**——一个任务一行，写着上次结果与开关，展开看它的历次运行。
用户第一次能回答「这次是不是比上次慢」。

**Blocked by:** 09

**Status:** ready-for-agent

## 为什么必须现在改

票 07 之后同一个任务会有多条运行，而守护扫描（票 12）每天还要产出上百条。平铺列表里
**用户手动发起的那一条会被淹掉**。这一层结构是后面每一张功能票的落脚点：排队（票 11）、
停发（票 14）、详情入口（票 16）都往它上面挂。

## 形状（来自本次盘问）

```
现在  槽位 2/2   [全部暂停]
  扫描 1 号库  62%   ⏸ ✕
  重建缩略图  18%   ⏸ ✕

任务清单           上次      连败
 ▸ 扫描 1 号库     ✓ 2h前     0
 ▸ 扫描 3 号库     ✕ 失败     6
 ▸ 重建缩略图     ✓ 昨天     0
   展开 → 历次运行，每条可进详情
```

**发起方**、排队中、停发标红这几样的展示位在本票里留出来，但它们的数据要到票 11、12、14 才有值——
本票不得为了填满界面而伪造。

## 边界

- 筛选器保留，但语义要说清楚：筛的是运行还是任务。搜索与目标 id 那两个输入框「打完再查」的
  既有约定不变（绑到请求参数上的是已提交的那份，不是正在打的字）。
- 展开某个任务时按需拉它的历次运行，不要在列表接口里一次性带回所有运行。
- 既有的「中断任务不显示速率」那条前端底线（票 01 之后中断已有速率）要跟着更新，
  但「不把算不出的数伪造成 0」这条原则不变。

## 验收

- [ ] 两层结构落地：实况区常驻置顶，任务清单按任务折叠、可展开看历次运行
- [ ] 展开按需拉取，列表接口不返回全部运行
- [ ] 发起方 / 排队中 / 停发的展示位已留出且在无数据时不显示，不伪造
- [ ] 手动发起的运行在自动运行大量存在时仍然一眼可见
- [ ] 筛选语义在界面上明确；两个输入框的「打完再查」约定未被破坏
- [ ] 组件用例覆盖：折叠与展开、空历史、只有实况没有清单、只有清单没有实况
