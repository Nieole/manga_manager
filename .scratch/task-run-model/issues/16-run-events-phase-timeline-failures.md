# 16 — 运行事件、阶段时间线与失败明细

**What to build:** 运行详情页能回答两个今天答不出的问题：「慢在哪一段」和「哪些文件失败了、
为什么」。新增**运行事件**的写入与读取，详情页展示阶段时间线与失败明细，并把「查看日志」
从 grep 全局日志改成看这次运行自己的事件流（旁边留一个按运行过滤原始日志的入口）。

**Blocked by:** 10

**Status:** ready-for-agent

## 事件是封闭枚举的四类，必须显式发出

| kind | 记什么 |
| --- | --- |
| phase | **阶段**切换；相邻两条相减即是那一段的耗时 |
| item | 条目失败：文件与原因 |
| control | 暂停 / 恢复 / 取消 / 被**合并** |
| warn | 运行级告警：降级、批量跳过、护栏触发 |

**不做「日志自动转事件」的魔法。** 全仓 132 处 `slog.Warn/Error` 里绝大多数是技术噪音
（「序列化任务状态失败」这类），自动转会把它们当用户信息推给用户。事件经**运行句柄**显式发出。

## 上限

条目失败每次运行最多留 500 条，超出只累加计数并落一条「还有 N 条未列出」。一次大库扫描可能有
几千个条目失败，全写进去既撑爆表也撑爆界面。

## 边界

- 事件**不推送**（票 19 的推送只有快照与实况汇总帧），详情页打开时按需拉。
- 阶段耗时由相邻事件相减算出，**不另存一列**：多存一份就要维护它与事件的一致。
- 「查看日志」的旧实现（grep `task_key=` 子串）保留为「原始日志」那个入口，
  只是过滤条件换成运行标识。

- [ ] 条目失败 500 条上限生效，超出落一条计数事件
- [ ] 详情页展示阶段时间线（每段耗时）与失败明细（文件 + 原因）
- [ ] 「查看日志」改为事件流，旁边保留按运行过滤的原始日志入口
