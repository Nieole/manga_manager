# 19 — 推送形状：快照序号与实况汇总帧

**What to build:** 丢帧之后界面自己纠正——快照带单调序号，前端发现缺口就整份重拉，轮询从 15s
降到 60s 兜底。另加一种轻量的**实况汇总帧**（槽位占用、活动数、排队数、全局暂停），
实况区不必靠列表自己算。

**Blocked by:** 11

**Status:** ready-for-agent

## 今天丢帧没有任何补偿

投递走的是非阻塞通道，**buffer 满就丢弃并告警**；前端唯一的兜底是 15s 轮询。丢掉的那一帧
如果恰好是终态，界面会停在一个过期的进度上最多 15 秒。

序号让前端**知道自己漏了**：看到 811 之后直接来了 814，就整份重拉一次列表。这比把轮询调密便宜得多，
所以轮询可以从 15s 放松到 60s。

## 边界

- 快照仍是**全量**，不改成增量帧。增量的合并逻辑要前后端各维护一套，而合并错一个字段不会报错，
  只会让界面安静地停在错值上。
- **事件与采样不推**（票 16 / 17 已定），详情页按需拉。
- 既有的节流水位规则原样保留：逐条目进度按窗口节流，状态跃迁、启动与终态无条件投递，
  终态时清掉水位（否则同名任务重跑的首帧会被上一轮的残留水位吞掉）。
- 序号已经是运行行上的单调值（票 06 沿用它做排序主键），**不要再发第二个序号**。
