# 03 — 暂停统一成一个概念

**What to build:** 「全部暂停」改成把每一条**活动态**任务逐个按下**暂停闸门**，状态如实变成
**已暂停**。今天按下它之后任务还写着「运行中 62%」却一动不动——因为那条按钮走的是
`storageio` 的后台暂停，它只让**磁盘作业**在取**存储令牌**前阻塞，从不改任务状态。

**Blocked by:** 无 —— 可立即开始

**Status:** done

## 两套暂停今天的样子

| | 每个任务的暂停 | 全局暂停 |
| --- | --- | --- |
| 机制 | **暂停闸门**，任务体停在下一个可中断点 | `storageio` 的后台暂停 |
| 任务状态 | 如实变成**已暂停** | **仍写运行中** |
| 界面 | 每条任务上的暂停键 | 顶部一个布尔标识 |
| 词汇表 | 有条目 | 一个字都没有 |

本票把用户面前的那个概念收成一个：**全部暂停 = 逐个按下**。

## 边界与代价

- **不可暂停的任务不受影响**（ComicInfo 回写这类每本书都是一次原子替换的），界面上要明说，
  而不是让用户以为暂停失灵了。这是这次统一的已知代价：`storageio` 那条路本来对它们也有效。
- `storageio` 的后台暂停**保留为内部机制**，继续服务于「阅读时降载」。它不再作为用户按钮暴露，
  对应的两个端点降级或移除，诊断接口里的 `paused` 字段随之改由「有没有活动任务被暂停」回答。
- 取消时一并放行闸门这条既有顺序**不变**（暂停中的任务只取消不放行会永远收不到取消信号）。
- 逐个按下要按**每个任务**成对做，不要先收集全部再统一按——理由与停机时逐个取消并放行相同。
