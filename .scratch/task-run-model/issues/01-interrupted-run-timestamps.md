# 01 — 中断运行的时间戳与速率

**What to build:** 服务重启时把**活动态**任务批量标**中断**的那一笔，不再把 `updated_at` 一起盖成
重启时刻；`finished_at` 改取该行原有的 `updated_at`。随之拆掉进度派生里那道「中断一律不发速率」
的闸门。用户看到的中断记录从此带着真实的耗时与速率，而不是一条残废的记录。

**Blocked by:** 无 —— 可立即开始

**Status:** done

## 为什么这条今天是坏的

进度是异步落盘的：落盘 goroutine 每 500ms 刷一次最新快照，因此 `updated_at` **本身就是心跳**，
它记的是这个任务最后一次有动静的时刻。而标中断的那笔 UPDATE 用 `CURRENT_TIMESTAMP` 把它盖掉了，
于是分母里整段停机时长都算成了在干活——停一夜再启动，一个跑了 10 分钟的任务会被算成跑了 10 小时。

代码里已经因此明确放弃了这个数，注释写的是「库里也换不出第二个分母」。**换得出**：
那个分母就是被同一笔 UPDATE 盖掉的 `updated_at`。

## 边界

- **从未上报过进度的运行**（`started_at` 与 `updated_at` 相等）仍然算不出速率，那是真的没有数据，
  应当继续不发。这与「中断一律不发」是两回事，别把闸门原样挪个位置。
- 时间列的文本格式今天由两个写入方写成两种形状（一个带时区后缀、一个不带），排序主键因此取的是
  引擎单调发放的序号。**本票不动排序**，只保证被读回来的那个时刻是对的；若写入格式需要统一，
  在这一票里顺手统一，但排序键仍是序号。
- 中断仍然**不是失败**，可重试的判据不变。

## 与票据的差距（票据写于旧模型下）

票据的两半在排期上被票 07 拆开了：**时间戳那一半票 07 已经做掉**，本票只剩拆闸门那一半，
外加把「从未上报过进度」这条边界钉下来。

- 票据说「不再改写 `updated_at`」，是因为旧模型里心跳只有那一列可住。新表有 `finished_at`
  这一列，票 07 把心跳搬了进去，`updated_at` 回到它的本义——这一行最后一次被写的时刻。
  两者在其余三种终态下相等，中断这一种不相等，因为那笔转写确实发生在重启时刻。
  界面上那行「最后更新」因此在中断运行上显示重启时刻，挂在 D46。
- 票据说「若写入格式需要统一，在这一票里顺手统一」：不必了，票 07 把三个时刻改成
  INTEGER 毫秒，写入方只剩 `taskstore` 一个。排序键仍是序号，本票未动。
