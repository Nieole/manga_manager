# 04 — 身份四要素显式声明

**What to build:** 任务声明显式带上类型、**作用域**、作用域 id 与**变体**，不再由引擎从**任务键**
的字符串里反解。`inferTaskScope` 删除，书哈希重建那处按键 switch 的重试分发随之删除。

**Blocked by:** 无 —— 可立即开始

**Status:** ready-for-agent

## 今天在猜什么

`inferTaskScope` 的做法是：类型名里 `Contains("library")` 就判库级、`Contains("series")` 就判系列级；
再把任务键按 `_` 切开，末段能 `ParseInt` 就当作作用域 id。启动点手里明明就有 `lib.ID`，
却要先拼进字符串再由引擎猜回来。

**它已经在猜错**：外部库扫描的任务键末段是 session id，不是库 id。

## 变体解决的是另一半

同一个类型下今天有多条键，重启函数注册表按类型分发，因此要在下游再按键 switch 分一次：

| 类型 | 变体 | 跑法差别 |
| --- | --- | --- |
| 书哈希重建 | 前台重建 | 大批次、无停顿 |
| 书哈希重建 | 低优先级回填 | 压低批次、批间停顿、匹配模式钉死 |
| 刮削 | 全库 | —— |
| 刮削 | 单库 | 带库作用域 |

按类型重启会把回填重启成前台档——正是回填刻意避开的抢盘跑法。**变体**让注册表按
（类型，变体）分发，下游那次 switch 因此消失。

## 边界

- **本票不改任务键怎么拼**。键仍由启动点生成、仍是主键，只是作用域不再从它反解。
  键的降级要等新模型（票 07）。
- 17 个启动点各自填全四要素。漏填要有编译错误，不能靠零值兜底——那等于把猜换了个地方。
