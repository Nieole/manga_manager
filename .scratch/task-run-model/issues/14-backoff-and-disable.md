# 14 — 退避与禁用

**What to build:** 挂在拔掉的移动硬盘上的那个库，连败几次后自动**退避**、到上限就停发并在界面上
标红，不再每小时白转一遍盘；用户也可以直接禁用某个任务的自动发起。手动发起一次或成功一次即复位。

**Blocked by:** 12

**Status:** ready-for-agent

## 规则

- 连败后按 ×2 拉长**自动发起**的间隔，封顶 24h；连败 ≥6 次停发并标红。
- 手动发起一次，或成功一次，把连败次数与退避清零。
- 人工禁用是另一条开关：禁用后定时与监听不再为它发起，**手动仍可**。
- 三个数（倍率、封顶、停发阈值）可在设置里改。

## 边界

- **退避只约束自动发起，不影响已经在跑的运行。** 一条正在跑的运行不会因为退避被打断。
- 退避与禁用挂在**任务**上，不在运行上——它们是身份的长期属性（票 06 已经建好那几列）。
- 停发不是**终态**，也不是一种运行状态：它是任务的属性。界面上要能分清「这个任务停发了」
  与「这次运行失败了」。
- 界面要写明**为什么**停发（连败几次、最后一次的错误），否则用户只看到一个红点。

## 验收

- [ ] 连败后自动发起的间隔按倍率拉长，封顶生效
- [ ] 达到阈值后停发，界面标红并写明连败次数与最后一次错误
- [ ] 手动发起或成功一次即复位，有用例守着两条路径
- [ ] 人工禁用后定时与监听不再发起，手动仍可
- [ ] 退避不打断已经在跑的运行
- [ ] 三个阈值可配
- [ ] 规则用例压在领域包的构造点上（可控时钟），不靠真实等待
- [ ] `GOCACHE="$(pwd)/.gocache" GOTMPDIR="$(pwd)/.tmp" go test ./...` 全绿
- [ ] `cd web && npm run test && npm run lint && npm run build` 全绿
