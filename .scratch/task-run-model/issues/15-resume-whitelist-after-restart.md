# 15 — 中断续跑白名单

**What to build:** 服务重启后，扫描这类可重入的工作自己接着跑（**发起方**记「恢复」）；
改磁盘内容或花钱的那些停在**中断**，等人裁决。无人值守的 NAS 重启后不再需要有人登录去点重试。

**Blocked by:** 11

**Status:** ready-for-agent

## 白名单

**可续跑**（自动重排队）：资料库扫描、系列扫描、封面生成、重建缩略图、清理缩略图、
书哈希重建与低优先级回填、文件身份重建、KOReader 进度对账与匹配刷新。

**不可续跑**（只标中断，等人裁决）：清理资料库、外部库扫描与传输、ComicInfo 回写、刮削、AI 分组。
理由是它们要么改磁盘内容、要么花钱。

票 18 之后多出来的**运行历史清理**两边都不进，理由见挂账 D72：它的守护节拍启动就先
清一次，重启后那条中断的清理已经被接上，进白名单只会让每次重启多发一次并当场被**合并**掉。

## **可续跑**比**可重试**严格，两者不得合成一个标志

可重试只要求「能再发起一次」，可续跑还要求「在无人看着时再发起一次也不会造成意外」。
外部库传输与 ComicInfo 回写**可重试但不可续跑**——把它们并成一个布尔值，
断电后开机就会自己动文件。

## 边界

- 重排队走的是票 11 的队列，不是绕过它直接开跑：重启后一次性恢复的多条运行同样受槽位上限约束。
- 恢复出来的是**新一次运行**，原来那条留在中断态。不要把中断那条改回运行中。
- 全局开关默认开，关掉之后全部只标中断。
- 排队中的运行在重启时同样进中断，其中可续跑的照样恢复。

## 验收

- [ ] 白名单内的类型在重启后自动重排队，发起方为恢复
- [ ] 白名单外的类型只标中断，不自动发起
- [ ] 可续跑与可重试是两个独立判据，有用例证明存在「可重试但不可续跑」的类型
- [ ] 恢复产生新一次运行，原中断记录仍在
- [ ] 恢复的运行受槽位上限约束，不绕过队列
- [ ] 全局开关可关，关掉后全部只标中断
- [ ] `GOCACHE="$(pwd)/.gocache" GOTMPDIR="$(pwd)/.tmp" go test ./...` 全绿
- [ ] `cd web && npm run test && npm run lint && npm run build` 全绿
