# Spec: 如实上报——数报在该在的地方，合并不说「已发起」

Status: ready-for-agent

## Problem Statement

**用户点「强制重扫」，界面回一句「已发起」，然后什么都没有按他要的方式发生。** 那个库已经有一条
扫描**排队中**时（守护 tick 或监听扫描在长扫期间排下的很常见），这次发起会**合并**进那一条：
被丢掉的是本次的声明**与任务体**，跑的仍是先排上那份普通扫描。引擎其实知道——它交回的
`Launched` 上带着「本次被合并了」这一格，doc 也写明「本次交出的任务体不会执行」——是发起点把它
丢掉了，端点因此无条件回「已发起」。用户唯一能察觉的痕迹是那条排队运行的合并计数加了一。

**「这个库这个月一共扫了多少归档」答不出来。** 单库扫描收尾时报的十几个数——发现、跳过、处理、
打开的归档数，哈希过的文件数，排进队的封面数，失败数，改名重连数，过期统计数，格式过滤数，
以及三个时长——全部 `strconv` 成字符串塞进**重启入参**。指标之所以要有自己一张表，就是为了可查询
可聚合（ADR 0004 写着「这个库最近十次扫描平均多久」是一句 SQL）；走字符串的这十几个数一句也聚不出来。

**「重启函数读回原始入参」这句话不为真。** 那张入参表里今天混着十几个不是入参的东西。而同一个
文件里，缩略图重建的兄弟调用点写法是对的：计数走**指标**，描述性值走参数。**单库扫描那一处没跟上。**

**缩略图重建详情里那个存储档位是假的。** 它发起时按全局默认策略（空路径）解析一次写进声明，
而它**逐库**扫；每完成一个库，逐库报文又按键覆盖一次。所以那一格最终显示的是**最后一个跑完的库**
的档位——既不是全局默认，也不是任何有意义的答案。跨库的运行本来就没有单一的存储画像可报，
而这一点在撤掉它的并发徽章时就已经论证过了，徽章撤了、标签留着。

## Solution

**发起点不再丢掉引擎交回的东西。** 一次发起被合并、且本次带着强制时，端点如实说：已并入正在排着
的那次扫描，那次不是强制的。**语义一个字不改**——合并仍是合并，只是不再报「已发起」。

**十三个数搬进指标**，与同文件里缩略图重建的写法对齐；那四个描述性值不再第三次上报（发起声明与
上限表里已经各有一份）。

**缩略图重建不再报存储画像**，只留执行模式。

## User Stories

1. As a 用户, I want 点强制重扫却被合并时界面明确告诉我, so that 我不会以为强制重扫正在进行。
2. As a 用户, I want 那句提示说清楚「并进的那次不是强制的」, so that 我知道该等它跑完再点一次，而不是以为已经强制过了。
3. As a 用户, I want 强制重扫在没有排队扫描时照常生效, so that 这次改动不影响绝大多数情况——它今天就是对的。
4. As a 用户, I want 合并的语义不变, so that 守护扫描与监听扫描仍然不会堆出一串一模一样的运行。
5. As a 用户, I want 扫描的计数出现在运行详情的指标里, so that 它们和别的任务的指标读起来一样。
6. As a 用户, I want 问「这个库最近十次扫描平均处理了多少归档」能得到答案, so that 我看得出扫描量的趋势而不只是最后一次。
7. As a 用户, I want 升级前落下的扫描运行的数仍然显示, so that 我的历史不因为这次搬家变成空白。
8. As a 用户, I want 运行详情里的「存储 IO」那一条搬家之后仍然显示那五个数, so that 我不会因为一次内部整理少看到东西。
9. As a 用户, I want 扫描运行不再重复上报同一件事三遍, so that 参数面板里不再堆着与声明和上限表重复的项。
10. As a 用户, I want 缩略图重建的详情里不显示一个假的存储档位, so that 我不会照着一个错的档位去调设置。
11. As a 用户, I want 缩略图重建仍然显示它的 IO 数（等待、暂停、耗时）, so that 撤掉假标签不连累真数字。
12. As a 用户, I want 缩略图重建仍然标着它的执行模式, so that 我仍看得出它是低影响模式在跑。
13. As a 配了按库存储策略的用户, I want 界面不拿全局默认策略冒充我这个库的策略, so that 我调过的设置不被一个假显示盖过去。
14. As a 开发者, I want **重启入参**那张表里只有真的重启入参, so that 「重启函数读回原始入参」这句 doc 为真。
15. As a 开发者, I want 两个扫描观察者的上报写法一致, so that 下一个照抄的人抄到的是对的那一份。
16. As a 开发者, I want 上报通道的选择有一条说得出的判据, so that 新增一个数时我知道它该走指标还是走参数。
17. As a 下一个动这块的人, I want 「合并的『效果相同』是前提不是保证」写在词汇表里, so that 我不会再默认两次发起可以随便并。
18. As a 排障的人, I want 那一批被丢弃的入库仍然落成运行级告警, so that 这次上报整理不动已经对的东西。

## Implementation Decisions

### 合并时端点如实回话，语义不动

资料库扫描的启动点今天丢弃引擎交回的 `Launched`；改成接住它。手动发起且本次带**强制**、
而这次发起被**合并**时，端点回一句说明：已并入正在排着的那次扫描，那次不是强制的。
需要两条 i18n 词条（中英各一）。

**明确不做的两件**：不把强制立成**变体**（理由见下），不让本次发起顶替排队那条的声明与任务体。
顶替要在 `RunSpec` 上引入「这次发起有多强」这个新概念，还会让那条运行的**发起方**说谎——
它是守护扫描排下的，顶替之后跑的却是人点的强制重扫。

**为什么强制不是变体：** 判据不是「跑法不同」，而是**两个变体是两个身份，而两个身份允许同时跑**。
立成变体等于声明「同一个库上同时扫两遍是可以接受的」，而那不是任何人想要的。强制与普通是同一件
事的两种彻底程度，**强制是一次运行的属性，不是一个身份**。已写进 `CONTEXT.md` 的**变体**词条。

**窗口比看上去窄**：该库正在扫、队列里**还没有**排队运行时，强制重扫会新建一条排队运行并写下
本次的声明，强制完整保住。丢强制只发生在「队列里已经排着一条扫描」这一种情况。

### 单库扫描的十三个数搬进指标

十个计数（发现 / 跳过 / 处理 / 打开的归档数、哈希文件数、排队封面数、失败归档数、改名重连数、
过期系列统计数、格式过滤数）与三个时长（IO 等待、暂停、耗时）改走**累加指标**通道，与同文件里
缩略图重建的写法对齐。

四个描述性值（存储画像、卷键、归档打开并发、封面并发）**从报文里撤掉**：发起声明与**上限**表里
已经各有一份，而单库扫描的报文路径与发起时解析的是同一条路径，值必然相同。

**判据（写进符号 doc，供下一个新增数的人用）：可聚合的计数与时长走指标；描述「这次是在什么条件
下跑的」走参数或上限表；同一件事只报一次。**

### 存储 IO 那一条要跟着改

运行详情里「存储 IO」那一条今天直接读参数、**没有回落**。那五个数（打开归档数、哈希文件数、
IO 等待、暂停、耗时）一旦搬进指标，那一条就少五格。它要改成走既有的「先读指标、读不到再读参数」
那个取数函数。

指标面板本身**不需要改**：它用的取数函数本来就带参数回落，所以新老运行都照常显示，这次搬家在
指标面板上一格都不变。

### 缩略图重建撤掉存储画像标签

发起声明里的存储画像、卷键、封面并发三项撤掉，只留执行模式；逐库报文里那四个描述性值一并撤掉。
后果是这条运行的「存储 IO」那一条不再显示——**跨库的运行没有单一的存储画像可报**。它的 IO 数
（等待、暂停、耗时）不受影响，那些本来就走指标。

这不是新判断，是把撤掉它并发徽章时的理由做完：那次正是因为「那个数取自全局默认策略而它逐库扫」
才撤的徽章，标签是留下的尾巴。

### 词汇表

`CONTEXT.md` 的**变体**与**合并**两条词条已在设计阶段改过（变体的判据收紧成「两个身份允许同时
跑」并写下强制这个反例；合并写明「效果相同」是前提不是保证）。本批不需要再动词汇表。

## Testing Decisions

好的测试只断言**外部行为**。任务子域的观测面已经定死：任务引擎只有一个 seam（构造点
`newTaskEngine`），观测面是**投递出去的载荷**。本批**不新增 seam**。

**在任务引擎 seam 上守（`internal/api`，断言投递出去的运行快照）：**
- 一次单库扫描收尾后，那十三个数出现在**指标**里，不在参数里。
- 那四个描述性值不再出现在扫描运行的参数里（发起声明里那一份仍在，那是对的）。
- 缩略图重建的运行上不带存储画像、卷键与两个并发数；执行模式仍在；它的 IO 指标仍在。
- 前例：既有的维护任务装置与后台引擎装置，两者都交回 `func() []RunStatus`。

**在真路由上守合并时的回话：**
需要摆出「活动一条 + 排队一条 + 再来一次强制」的局面。**首选在扫描端点这一层断言 HTTP 响应**，
前例是既有的自动扫描装置。共用装置若撑不住「让一条运行停在**活动态**」，**这张票就给它加上这个
能力**（一个可控的、由用例放行的任务体），而不是退到更低一格。退到断言启动函数交回的 `Launched`
是**有记录的最后手段**，不是默认选择——因为用户看见的是那句 HTTP 回话，不是那个结构体。

**前端（vitest）：** 「存储 IO」那一条在五个数搬进指标之后仍然显示；缩略图重建的运行上那一条
整条不显示。前例：既有的任务中心组件用例。

**明确不写的：** 不为「合并的语义」新写用例——语义没变，队列与合并的机制用例在领域包里已经有人守。

## Out of Scope

- 不改**合并**的语义：不顶替、不拒绝、不按声明分叉排队。
- 不把**强制**立成**变体**。
- 不给**运行句柄**加读回自己入参的面（顶替方案才需要，本批不做）。
- 不动任何寻址——那是 `address-by-object` 的事；本批不碰**任务键**、不碰重试端点。
- 不动前端生成契约：指标与参数本来就在同一份载荷里，搬家只改哪个键出现在哪张 map。
- 不修刮削全库那条写死的中文**作用域**显示名。
- 不动封面运行那两个已经搬走的数（生成封面数、缩略图写入耗时），它们归封面运行是对的。

## Further Notes

- 本批与 `address-by-object` **无依赖**，两边可以并行，落地顺序不限。本批不动契约，`address-by-object`
  动且只重生一次。
- 升级前落下的扫描运行的那十三个数仍留在参数里。指标面板的取数函数带参数回落，所以它们照常显示；
  「存储 IO」那一条改成同一个取数函数之后，新老运行也都照常显示。**这次搬家没有可见的断层。**
- 合并那句回话只覆盖**手动 + 强制**这一种组合。守护扫描与监听扫描被合并时不需要回话——它们没有
  人在等答案，而监听器已经按既有的约定出口重新排期。
