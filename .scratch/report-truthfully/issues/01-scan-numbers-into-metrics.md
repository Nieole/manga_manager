# 01 — 单库扫描的十三个数搬进指标

**What to build:** 用户能问出「这个库最近十次扫描平均处理了多少归档」——今天答不出，因为单库
扫描收尾报的十几个数被 `strconv` 成字符串塞进了**重启入参**，一句也聚不出来。**指标**之所以有
自己一张表，就是为了可查询可聚合。

同一个文件里，缩略图重建的兄弟调用点写法是对的（计数走指标、描述性值走参数）；单库扫描那一处
没跟上。这张票让两处对齐，并把那四个第三次上报的描述性值撤掉——发起声明与**上限**表里已经各有
一份，而扫描的报文路径与发起时解析的是同一条路径，值必然相同。

用户这一侧**不该有可见变化**：指标面板的取数函数本来就带参数回落，所以新老运行都照常显示。
唯一会坏的是「存储 IO」那一条——它直接读参数、没有回落，必须跟着改。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 十个计数（发现 / 跳过 / 处理 / 打开的归档数、哈希文件数、排队封面数、失败归档数、改名重连数、过期系列统计数、格式过滤数）改走**累加指标**通道
- [ ] 三个时长（IO 等待、暂停、耗时）一并改走指标
- [ ] 四个描述性值（存储画像、卷键、归档打开并发、封面并发）从扫描报文里撤掉；发起声明与上限表里那两份**保留**
- [ ] 在任务引擎 seam 上断言：一次单库扫描收尾后，那十三个数出现在投递出去的载荷的**指标**里，且不在参数里
- [ ] 在同一处断言：那四个描述性值不再出现在扫描运行的参数里
- [ ] 「存储 IO」那一条改走既有的「先读指标、读不到再读参数」取数函数；前端用例守它在搬家之后仍显示那五个数
- [ ] 在上报侧的符号 doc 上写下判据：**可聚合的计数与时长走指标；描述「这次是在什么条件下跑的」走参数或上限表；同一件事只报一次**
- [ ] 不改任何契约结构体、不重生 `generated.ts`（指标与参数本来就在同一份载荷里）
- [ ] `CHANGELOG.md` 记一条
- [ ] 后端与前端门禁全绿
